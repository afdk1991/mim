## 版本号体系整改（第八轮，commit 741589d）

用户决定**弃用整套 v0.0.x**，改用 `v0.0.0.0`。

### 已执行

- 删除全部 `v0.0.x` git tag（本地 + 远端均归零）：v0.0.0 / v0.0.5（本轮早些时候）
  及 v0.0.1–v0.0.4。其中 v0.0.1/v0.0.2 本来只存在于本地（仓库重建遗留，远端早无）。
- `package.json` version：0.0.5 → `0.0.0.0`。
- 打 tag `v0.0.0.0`（指向 741589d）。

### 🔴 关键认知：npm 对四段式版本号的两副面孔

实测（隔离目录 /tmp/semvertest 验证，结论可复现）：

| 命令 | version=0.0.0.0 | 结论 |
|---|---|---|
| `npm install` | ✅ 通过（exit 0） | **容忍**无效 semver，不报错 |
| `npm publish` | ❌ `npm error Invalid version: "0.0.0.0"` | **拒绝**，四段非合法 semver |

`semver.valid('0.0.0.0')` 返回 `null`；合法且最接近四段观感的是 `0.0.0-0`（prerelease）。

→ 因此 CI 表现完全可预测且影响可控：
- `v0.0.0.0` tag run：**质量门禁 & 构建 success**，仅 `publish-package` failure
  （`npm error Invalid version`）。其余 job 因 tag 不触发而 skipped。
- `main` run：**全部 success**（Pages / EdgeOne / 冒烟全绿），`publish-package` skipped
  （该 job 的 if 是 tag 才跑）。
- 即：**主部署不受无效版本号影响**，代价只是该版本号永远发不出 npm 包。

### 遗留

- Packages 上 `0.0.0` / `0.0.5` **仍未删除**：需带 `delete:packages` + `read:packages`
  的 PAT，当前 gh token scope 仅 `gist, read:org, repo, write:packages`（能发不能删）。
  这两版在 72h 窗口内可删；`0.0.1`–`0.0.4` 与 `1.0.0` 已超窗口，**永久删不掉**。
- 教训：npm 已发布版本不可重发（409），且 unpublish 后同版本 24h 内不可重发。
  故版本号一旦发出去，基本只能靠「升版本号」向前修正，无法回头擦除。

## 管理后台权限死锁修复（#/admin 无访问权限）

**报告**：https://afdk1991.github.io/mim/#/admin 显示「没有管理后台访问权限」。

**根因（设计级死锁）**：注册触发器 `handle_new_user_role()` 只分配默认角色 `user`；
而 `public.user_roles` 的写策略 `user_roles_admin_write` 要求调用者已是 admin（`is_admin()`）。
→ 没有任何人能成为第一个 admin，/#/admin 对包括作者在内的所有人恒为无权限。
CI 的 `ADMIN_EMAIL` 通道也易失效：用户名注册映射为合成邮箱 `<username>@mim.app`，
按真实邮箱匹配常命中不到。

**修复**：
1. 新迁移 `supabase/migrations/0010_admin_bootstrap.sql`
   - `has_any_admin()`（anon/authenticated 可调）供前端判断
   - `bootstrap_admin()`：仅当系统尚无 admin 时把调用者提为 admin，**门自动关闭**
   - `grant_admin_by_name(text)`：按用户名或邮箱授予，**revoke from public**
     （仅 service_role / SQL Editor 可用，防普通用户自提权）
   - 顺带修正 `0008_mall.sql` 的 `is_admin(uuid)` 误用 `user_roles.role` 列
     （实际为 `role_id` 外键）→ 运行时报 column does not exist，商城订单核销恒失败
2. 前端 `src/App.tsx` AdminGate 三态化：未登录引导登录；已登录无 admin 时展示
   当前账号/角色 + 授权路径；系统无 admin 时显示「👑 成为首个管理员」按钮。
   新模块 `src/lib/admin-bootstrap.ts` 封装 RPC（CloudBase 备后端自动降级为静态说明）。
3. 通道脚本 `scripts/grant-admin.mjs`（`npm run admin:grant`，Management API，
   支持 `--list` / `--who`）；`supabase/grant-admin.sql`（SQL Editor 粘贴版，零凭证）。
4. 文档：INSTALL.md §3「解锁管理后台」四条通道表；DEPLOY.md 同章节 + bug 说明。

**验证**：tsc 0 错；build 通过（819KB）；`npm run verify:routes` 46/46 全绿；
playwright 实测 #/admin 未登录态渲染「管理后台仅对已登录的 admin 账号开放 + 🔐 去登录」。

**待办**：0010 需应用到线上库（push main 后 CI `migrate-db` job 自动执行，
依赖 SUPABASE_ACCESS_TOKEN / SUPABASE_PROJECT_REF secrets）；
迁移未生效前前端会降级为「执行 grant-admin.sql」静态说明。

## 自托管 BaaS 平台架构方案（设计文档）

输出 `docs/selfhosted-baas-blueprint.md`：对标 Supabase 的可完全自托管 BaaS，覆盖
Database(PostgREST+pg_graphql+RLS) / Auth / Realtime / Storage / Edge Functions / Vector 六模块。

**核实到的关键事实（2026-10）**：
- Supabase 自托管 compose 现以 **Envoy 为默认网关**（Kong 变可选别名），组件含
  gotrue v2.19x、postgrest v14、realtime v2.13x、storage-api v1.7x、edge-runtime v1.7x、
  postgres-meta、supavisor 2.9.x、imgproxy、logflare+vector
- 自托管 Edge Functions 官方仍标 **Beta**（会有 breaking change）
- pgvector 0.8.6：vector 索引上限 2000 维 / halfvec 4000 / bit 64000；
  0.8+ 才有 iterative_scan（解决"过滤后召回不足"）；并行构建需 ≥0.8.2（CVE-2026-3172）
- 连接池 transaction 模式下：裸 SET（非 LOCAL）会跨请求残留导致越权、LISTEN 失效、
  会话级 advisory lock 失效；PostgREST 因用事务内 set_config(...,true) 而安全

**方案要点**：Postgres 为唯一真相源，安全边界统一落在库内 RLS；
优先级 P0=Database+Auth（Auth↔RLS 是全部模块的安全地基）→ P1=Storage/Realtime/Vector
→ P2=OAuth+GraphQL+Edge Functions（Edge 先用普通微服务替代）→ P3=多区域/混合检索。
