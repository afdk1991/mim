## 版本号统一（v0.0.0.0 → v0.0.0-0）

用户指出「没有实现版本号统一」——此前 git/站点是 `v0.0.0.0`，但 npm Packages 永远
不会有该版本，导致双层分裂。

**根因（硬边界，非权限/配置问题）**：`0.0.0.0` 是四段式，**不是合法 semver**。
- `npm install` 容忍（exit 0，不报错）→ 故构建与主部署不受影响
- `npm publish` 拒绝：`npm error Invalid version: "0.0.0.0"`
→ 只要用四段式，站点与包必然永久分裂，无法统一。

**解法**：改用 **`0.0.0-0`**（prerelease 形式）——保留四段观感，且 `semver.valid` 通过。

**关键机制**：`scripts/prepare-package.mjs` 用 **tag 名去 `v` 前缀**作为发布版本号
（`v0.0.0-0` → `0.0.0-0`），不注入则 package.json 固定版本第二次发版会撞 409。
故统一动作必须同时改 package.json + 建同名 tag。

**执行**：package.json `0.0.0.0`→`0.0.0-0`（commit `d7ea777`）→ push main
→ 删旧 tag `v0.0.0.0`（本地+远端）→ 建新 tag `v0.0.0-0` 推送触发发布。

**四处统一验证（全绿）**：
| 层 | 值 |
|---|---|
| package.json | `0.0.0-0` |
| git tag（本地/远端） | `v0.0.0-0`（唯一，各 1 个） |
| GitHub Pages 部署 | sha `d7ea777`（Pages/EdgeOne/线上冒烟 均 success） |
| GitHub Packages | `0.0.0-0`（id 1455641303）且 **dist-tags.latest 指向它** |

**验证要点**：`0.0.0-0` 是 prerelease，原担心 npm 不会将其设为 `latest`
（则 `npm install` 仍装旧版）。用真实 `gh auth token` 查 registry 实测
`dist-tags: {"latest":"0.0.0-0"}` —— 疑虑被证伪，GitHub Packages 会将其设为 latest。

## 全项目功能落地检查（跨前端/后端/数据库三层）

**方法（关键）**：不靠静态推测，用**真实探测**定论 —— 把 `scripts/probe-schema.mjs`
从「手工维护 14 项抽样」改成「自动从 src/ 提取 24 表 + 13 函数 + 反查所属迁移」，
再逐项打线上 PostgREST。

**两个探测陷阱（都踩了并修正，后续复用）**：
1. **带参 RPC 的空 payload 假阴性**：PostgREST 按 payload 做重载解析，对
   `wallet_debit(p_fen,p_note)` 发 `{}` 会返回 404 PGRST202，看起来像"函数不存在"。
   修正：从本地 SQL 解析签名构造合法 payload 再探测。修正后 wallet_credit/debit/
   growth_record/send_message/username_taken 全部由 ❌ 翻 ✅。
2. **OpenAPI 端点不可用于探测**：`GET /rest/v1/` 返回 401
   `Only secret API keys can be used for this endpoint`（publishable key 不够）。

**校验器自身也可能是假的**：`pgsql-parser` 的 `parse()` 返回 Promise，
同步 `try/catch` 抓不到 → 12 个 SQL 全部"通过"实为假绿。
修正：先跑反例（错误语法必须被 reject）自证校验有效，再校验正例。
**通用纪律：任何"全绿"的校验都要先用一个已知错误反证它真的会报错。**

**实测结论（线上库）**：0000-0007 已应用；**0008/0009/0010 从未应用**
（mall_orders / confirm_order / price_quotes / price_latest / rec_feedback_* /
has_any_admin / bootstrap_admin 全缺）。CI migrate-db job 缺 secrets 时静默跳过且不报错。

**代码层断裂（本次已补）**：

**三条根因（此前版本永远统一不了的真正原因）**：
1. `ci-cd.yml` 的 tag 过滤只写 `'v*'`，而规范 tag 是大写 `V0.0.0.0` —— GitHub Actions
   的 tag 匹配**区分大小写**，故 desktop Release 会跑、npm 发布**永不触发**。
2. `prepare-package.mjs` 直接取 tag 字面值当版本 → `V0.0.0.0` 得四段 `0.0.0.0` →
   `npm publish` 报 `Invalid version`（实测）。
3. `build-release.yml` 四个 job 用 tag **覆盖写入** `src/version.ts`，方向反了；
   tag 与源码不符时静默产出「A 号制品 B 号代码」。

**修复**：
- `prepare-package.mjs` 改为从 `APP_VERSION` 派生三段（第1.第2.第4段）+ tag 一致性强校验
- `ci-cd.yml` tags → `['v*','V*']`，publish 条件同时匹配大小写
- `build-release.yml` 四个 job 的「注入 APP_VERSION」→「校验 tag == V<APP_VERSION>」，
  desktop 的 tauri 版本改从 APP_VERSION 派生
- `version-check.mjs` 增加本地 tag 必查 + `--remote` 比对 origin tag
