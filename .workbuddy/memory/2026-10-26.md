### 交叉核对发现真实交付阻塞（已修）

`supabase/apply-all-manual.sql` 生成于 10-25 00:35，**早于** 0004/0005 的幂等修正
（10-25 23:09/23:10）。其内嵌 0005 段仍是旧版：用 `add constraint if not exists`——
**PostgreSQL 的 ADD CONSTRAINT 不支持 IF NOT EXISTS**，买家按 INSTALL.md 推荐
「一键补齐」路径粘贴执行会在约束处直接语法报错。

修复：`npm run db:gen-manual` 重新生成（与 CI 同源）。逐段 diff 校验七段
（0000_schema/0001..0005/9999_seed）与源文件全部一致；bundle 末尾多出的
`schema_migrations` 登记语句是生成器设计内行为（gen-apply-all.mjs:74）。
附带修正 0004 文件头误导注释（声称 add constraint if not exists，实际 DO 块幂等）。

### 方法论沉淀

- **生成产物必须与源文件做时间戳比对**：mtime 早于任一源文件 = 必过期，
  重新生成即可，不要手改 bundle；
- **逐段 diff 时先确认分段边界**：本次 0005 段误判 51 行差异实为提取范围
  越界带入了 seed 段，先 `grep -n` 段头行号再切片；
- **bundle 体积压成 1 行**：统计字符串用 `grep -o | wc -l` 不用 `grep -c`。
