### 架构（四层）
1. **迁移 0003_account_bridge.sql**：`account_bridge` 表（username PK、cloudbase_uid、
   password_hash、salt、migrated、failed_attempts、locked_until）+ RPC
   `username_taken` / `claim_username`（均 security definer、anon 可调）；
   RLS 禁客户端 select（防 hash 泄漏），anon 仅可 insert（与开放注册同暴露面）。
2. **Edge Function /auth/bridge-login**（supabase/functions/mim-api/index.ts）：
   PBKDF2-SHA512(100k,64B) 验旧哈希（Web Crypto，与 CloudBase 版逐位一致，有单测证据）
   → Admin API 自动落户 → bridge.migrated=true。**安全核心：只可新建，账号已存在一律 409，
   绝不改对方密码**（防知道 CloudBase 旧密码者接管同名 Supabase 账号）；5 次失败锁 15 分钟。
3. **CloudBase mim-api 注册链路**（cloudfunctions/mim-api/index.js，已重新部署）：
   register 前调 username_taken（fail-open：Supabase 不可用不拒绝注册，本地 unique 兜底），
   成功后 fire-and-forget claim_username。线上实测：0003 未应用时注册照常成功（fail-open 路径验证）。
4. **前端适配层**（src/lib/supabase.ts）：signUp 前全局查重 + 成功后双写 CloudBase register；
   signInWithPassword 原生失败 → bridgeLogin（200+upgraded→原密码重试；423→锁提示；
   其余/网络异常→静默跳过走原生报错）。
