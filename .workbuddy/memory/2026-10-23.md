## ⑥ CI 假失败修复：deploy workflow 关闭 cancel-in-progress

**现象**：连续 push 时 EdgeOne 部署 job 报 `##[error]The operation was canceled.`（红 X），
但日志末尾其实已输出 `Deploy Success` + Deploy URL —— **部署真的成功了，只是被 cancel**。

**根因**：`ci-cd.yml` 的 `concurrency.cancel-in-progress: true`。
连推多个 commit ⇒ 新 run 掐断进行中的旧 run，部署跑到一半/刚完成就被杀，
结果判为失败，且线上状态与 CI 结论不一致，排查时被误导。

**修复**：`cancel-in-progress: false` ⇒ 并发 run 排队依次跑完。
代价是多花 runner 分钟（个人仓库 2000 分钟/月，够用），换取部署完整性与结论可信。

**验收**：`39976698732` 全绿 —— 质量门禁 35s / EdgeOne 1m13s / GitHub Pages 37s，假失败消失。

**教训**：`cancel-in-progress: true` 只适合纯校验类 workflow（typecheck/test）；
**凡是 workflow 里含真实部署/发布步骤，一律必须设为 false**。
