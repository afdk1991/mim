Mim 全平台产品底座 — 产品需求文档

版本：V0.0.0-preview　|　通道：preview　|　日期：2026-11-04　|　状态：草案

本文档定位：定义 Mim 全平台产品底座的 P0 核心用户旅程与功能需求。底座支撑多产品形态（工具/SaaS/内容/电商/社交）、多端（Web/小程序/App/PC）、双市场（国内+出海）、全能力（支付/IM/音视频/AI）。旗舰产品形态于 2026-11-04 重定义为 SaaS 工具型（订阅制）— 功能模块商城 + 漫剧 AI 剧工作室（FR-03 重写，替代原「跨端任务与轻协作工具」方案）。核心工作区由两域构成：功能模块商城负责模块上架、定价与解锁；漫剧 AI 剧覆盖 AI 全自动成片、AI 辅助创作工作台、作品管理与分发、工作台+导出成片四种交付形态。首端为 Web + 微信小程序（国内），出海以 App + Web 切入。

1. 背景与目标

观察到的问题：一套产品需要同时覆盖国内与海外、PC 与移动、小程序与原生 App，且要求支付、IM、音视频、AI 等重资产能力。若按传统方式为每个端独立开发业务逻辑，会导致：

  • 同一功能在多端重复实现，改一处需同步 N 处；
  • 国内/海外数据与账号体系后期打通代价极高；
  • 支付、IM、音视频等能力在各端重复对接，无法统一治理。

产品决策：采用「Headless 中台 + 多端薄壳」架构，将业务逻辑、能力网关、账号与数据下沉为共享层，各端仅负责 UI 与平台 API 适配。

可观测的目标：用户在任意一端完成注册与订阅后，可在其他所有端以同一身份登录并使用已订阅的功能；支付、IM、音视频、AI 能力对业务方以统一接口暴露，国内/海外差异由驱动层屏蔽。

2. 产品契约

要素定义
主要用户终端用户（国内 / 海外）、运营管理员
核心任务注册账号 → 进入功能模块商城选购模块/订阅 → 完成支付 → 在漫剧 AI 剧工作台创作 → 导出成片 → 跨端继续使用

3. 范围

P0 必须交付

  • 账号与身份：注册、登录、跨端账号打通、国内（手机号+微信/支付宝）与海外（邮箱+Google/Apple）双登录体系
  • 订阅与支付：计划展示、订阅、支付（国内通道 + Stripe/PayPal + Apple IAP/Google Play）、订单、退款、凭证校验
  • 核心 SaaS 工作区 — 功能模块商城：模块目录与详情、模块定价（按 region / 币种独立定价）、模块解锁（Entitlement）、订单挂载模块、解锁状态校验；支持「订阅制解锁」与「一次性购买解锁」两种模式，退款需回收解锁
  • 核心 SaaS 工作区 — 漫剧 AI 剧：覆盖四种交付形态 ① AI 全自动生成成片（题材/剧本大纲 → AI 分镜与角色设定 → 静帧/关键帧 → 合成漫剧短视频，需接入文生图/图生视频模型与任务队列）② AI 辅助创作工作台（剧本、分镜、角色一致性、对白、配音由 AI 建议、人工确认，交付物为创作工程）③ 漫剧作品管理与分发（成片管理、版本、发布与浏览）④ 创作工作台 + 导出成片（②与③的组合）。四种形态均在本 P0 定义范围内，按 §5 FR-03.2 的形态表与 [07 §12](file:///f:/合并项目/Mim/docs/wiki/07-functional-modules.md) 拆分清单分里程碑落地
  • 多端体验一致性：Web、微信小程序、App（iOS/Android）、PC（Win/macOS）至少一端可用，其余端适配
  • 国际化基础：i18n 多语言、多币种、多时区
  • 合规与隐私：隐私政策、用户协议、数据收集清单、账号注销、数据删除请求

P1 后续迭代

  • IM 即时通讯（会话、消息、离线推送、内容审核）
  • 音视频（信令、SFU、录制、转码）

4.2 核心对象与状态

Subscription（订阅）

状态进入条件可执行操作
active支付成功且在有效期内使用付费功能、取消续费、申请退款
past_due续费失败，宽限期内更新支付方式、查看欠费
canceled用户取消或退款完成不可用付费功能（至当期结束）
expired订阅到期未续费重新订阅

Order（订单）

状态说明
pending已创建，等待支付
paid支付成功
failed支付失败
refunded已退款（全额或部分）
closed超时未支付关闭

Refund（退款）

状态说明
pending用户已申请，等待运营审核；IAP 退款以商店通知为准，本地同步为同一状态流
approved审核通过，等待通道执行退款
rejected审核拒绝，订单与订阅状态不变，需记录驳回原因
executed通道退款成功；订单转 refunded，订阅按 §5 FR-02 规则失效或折算，模块解锁同步回收

Module（功能模块）

状态进入条件可执行操作
draft运营创建，尚未上架编辑信息与定价、预览、提交上架
active审核通过并开放售卖用户可浏览、订阅解锁或一次性购买解锁；运营可下架
archived运营下架不可新购；已产生的 Entitlement 在其有效期内继续可用

Entitlement（模块解锁）

状态进入条件可执行操作
active订阅覆盖该模块，或一次性购买订单已支付使用该模块；订阅型解锁随订阅状态联动
expired订阅到期未续费（仅订阅型解锁）重新订阅后恢复；永久解锁不进入此状态
revoked退款执行完成或运营风控回收不可使用该模块，需重新购买/订阅

ComicProject（漫剧工程）

状态进入条件可执行操作
draft新建工程，已填题材/大纲编辑大纲、角色设定、剧本、分镜；发起生成
storyboarded分镜与角色设定已确认生成静帧/关键帧；回退至 draft 修改
generating存在排队或运行中的 GenerationJob查看进度、取消任务；不可并发发起全量重生成
rendered成片合成成功，ComicFilm 已生成预览、重生成局部、发布、导出
published作品已发布至作品库查看、下线、产生新版本
archived用户归档或长期未活跃恢复；不可直接发布

ComicFilm（成片）

状态进入条件可执行操作
draft合成完成，未提交审核预览、重新合成、删除
reviewing已提交内容审核查看审核状态；不可编辑
published审核通过并发布浏览、分享、下线
archived用户下线或运营下架恢复或删除；不再对外可见

GenerationJob（生成任务）

状态进入条件可执行操作
queued已提交，等待配额与并发位取消；查看队列位次
running已分配模型资源（文生图/图生视频/合成）查看进度；取消（已产生费用按供应商规则结算）
succeeded模型返回产物并通过校验下载产物、挂载至工程节点
failed模型报错、超时或产物校验不通过按 retry_count 重试（上限 3 次）；超限转人工介入
canceled用户取消或系统熔断重新发起
状态机通用约束：所有状态变更必须经领域层校验并写入事件表（只追加，禁止 UPDATE 历史）；金额相关对象（Order / Refund）禁止软删除，只能追加冲正；模块解锁的发放与回收必须与订单/退款在同一事务内完成，避免出现「已退款仍解锁」或「已支付未解锁」。

5. 功能需求

FR-01 账号与身份

目的

用户在任意端完成注册/登录后，其账号与订阅状态在所有端实时同步。国内与海外采用不同的登录方式，但底层账号体系统一。

注册与登录方式

市场注册/登录方式说明
国内手机号 + 验证码、微信登录、支付宝登录手机号为主，第三方为辅
海外邮箱 + 密码/验证码、Google Sign-In、Apple Sign-InApp 端提供第三方登录时必须同时提供 Apple Sign-In（App Store 要求）

跨端账号打通规则

  • 同一手机号或邮箱在国内与海外视为不同账号（数据物理隔离，region 维度区分）
  • 同一市场内，手机号、微信、支付宝等不同登录方式可绑定至同一账号
  • 绑定需二次验证（已登录方式确认 + 新方式验证码）
  • 账号合并：若用户用两种方式注册了两个账号，可申请合并，合并后订阅与订单归并至保留账号 TBD：合并策略细节

异常与边界

  • 验证码发送频率限制：同一标识 60 秒内仅一次，1 小时内不超过 5 次
  • 验证码 5 分钟有效，错误 5 次后失效需重新获取
  • 登录失败 5 次后账号锁定 15 分钟（仅该端，不影响其他端在线会话）
  • 已登录用户在新设备登录时，若开启设备保护，需邮件/短信确认

FR-02 订阅与支付

目的

用户选择订阅计划并完成支付后，获得对应功能的使用权。支付通道按市场与平台路由，底层由驱动层屏蔽差异，业务方只感知统一的订阅状态。

订阅计划（Plan）

字段说明
plan_id计划唯一标识
name计划名称（多语言）
billing_cycle月 / 季 / 年
price分币种定价（CNY、USD 等）
region适用市场（国内 / 海外 / 全球）
statusactive / archived

支付通道路由

场景可用通道规则
国内 Web/小程序微信支付、支付宝、银联按用户选择
国内 App 数字商品—iOS 必须走 Apple IAP；Android 国内商店规则视渠道而定 Assumption
海外 WebStripe、PayPal按用户选择
海外 App 数字商品Apple IAP、Google Play Billing商店强制，否则拒审
资金合规硬约束：支付清算必须由持牌机构完成。产品自研的是「支付编排、账务、订阅计费、对账、风控」层，底层通道对接持牌方。iOS/Android 数字商品必须走商店 IAP，抽成 15%~30%。

订阅生命周期

用户选择计划 → 创建 Order(pending) → 拉起支付 → ├─ 支付成功 → Order(paid) → Subscription(active) → 发放权限 ├─ 支付失败 → Order(failed) → 提示重试 └─ 超时未支付 → Order(closed) 续费： 到期前 N 天自动扣款 → ├─ 成功 → Subscription 续期 └─ 失败 → Subscription(past_due)，宽限期内重试 → 仍失败 → expired

退款规则

  • IAP 订单：按商店政策走商店退款流程，产品侧接收退款回调并更新订阅状态
  • 直连通道订单：支持用户申请退款，运营审核后执行 TBD：退款窗口与条件
  • 退款后订阅立即失效（或按比例折算至当期结束），不可恢复

异常与边界

  • 支付回调重复到达：以 order_id + 通道流水号幂等处理
  • 支付成功但订阅未生效：对账任务每日扫描 paid 但无 active subscription 的订单，自动补发
  • 跨端订阅状态：订阅状态变更后 5 秒内同步至所有在线端，离线端下次拉取时更新

FR-03 核心 SaaS 工作区（功能模块商城 + 漫剧 AI 剧）

2026-11-04 重定义：原 FR-03「项目 → 任务 → 子任务 + 协作 + 仪表盘 + 同步 + CSV 导出」已整体移除。新 FR-03 由两域构成：FR-03.1 功能模块商城（模块上架、定价、解锁与订单挂载）与 FR-03.2 漫剧 AI 剧（四种交付形态）。两域共享 §4.2 的 Module / Entitlement / ComicProject / ComicFilm / GenerationJob 状态机。

FR-03.1 功能模块商城

目的：用户可在商城中浏览模块、按 region 与币种查看定价，并通过「订阅解锁」或「一次性购买解锁」获得模块使用权；服务端以 Entitlement 作为唯一鉴权依据，端上不得自行判断是否已购买。

字段说明
module_id模块唯一标识（稳定不变，改版不换 ID）
code机器可读编码，用于代码内鉴权（如 comic-studio、ai-film-auto）
name / summary多语言名称与简介（zh-CN / en-US）
unlock_modesubscription（随订阅生效）或 one_time（一次性永久解锁）
price按 region + currency 独立定价，金额为最小货币单位整数
entitlements_required前置模块依赖（如「全自动成片」依赖「创作工作台」），未满足时商城展示为「需先解锁 X」
statusdraft / active / archived（状态机见 §4.2）
region可售区域；cn 与 global 独立定价、独立库存策略

定价与解锁规则

  • 订阅解锁：订阅处于 active 且该订阅包含本模块时，系统自动发放 Entitlement(active)；订阅转 past_due 保留至当期结束，转 expired 时对应解锁转 expired。
  • 一次性购买解锁：订单 paid 后发放永久 Entitlement(active)，不随订阅状态变化，仅在退款执行后转 revoked。
  • 组合购买：同一订单可挂载多个模块（订单行 = 模块 + 计价项），任一模块退款只回收对应解锁，不影响其他模块。
  • 改价不改史：价格变更只影响新订单；历史订单与已发放解锁不受影响。

主流程

浏览商城 → 模块详情（查定价 / 查前置依赖） → 选择解锁方式（订阅 / 一次性） → 创建 Order（挂载 module 行）→ 拉起支付 → 支付成功 → 同事务发放 Entitlement → 工作区入口点亮 → 支付失败 / 超时 → Order(failed / closed)，不发解锁 退款：Refund(pending) → 审核 → executed → Order(refunded) → Entitlement(revoked) → 商城入口熄灭

异常与边界

  • 价格展示与下单金额必须由服务端计算，客户端传入金额一律忽略。
  • 重复支付同一模块：以 order_id + 通道流水号幂等，不重复发放解锁。
  • 模块下架（archived）后不可新购，但已发放的解锁在有效期内继续可用。
  • 前置依赖缺失时禁止下单，接口返回明确错误码（如 ENTITLEMENT_REQUIRED）。
  • 退款回收解锁必须与退款执行同事务，避免出现「已退款仍解锁」。

FR-03.2 漫剧 AI 剧（四种交付形态）

目的：以同一套创作工程（ComicProject）承载四种交付形态，用户可按需在「AI 建议 + 人工确认」与「AI 全自动」之间切换，最终交付可以是创作工程，也可以是成片（ComicFilm）。

形态交付物关键能力
① AI 全自动生成成片漫剧短视频（成片）题材/大纲 → AI 分镜与角色设定 → 静帧/关键帧 → 合成短片；需文生图/图生视频模型 + 任务队列，全程可无人值守
② AI 辅助创作工作台创作工程（不出成片）剧本、分镜、角色一致性、对白、配音由 AI 建议，人工逐项确认后保存工程；支持导出素材
③ 漫剧作品管理与分发成片管理与发布成片管理、版本、发布与浏览；不含 AI 生成能力（承接外部导入的成片）
④ 创作工作台 + 导出成片创作工程 → 成片②与③组合：先在工作台完成工程，再由 AI 生成分镜图并合成短片导出

创作流水线

题材 / 剧本大纲 → 结构化剧本（AI 建议 + 人工确认）→ 角色设定（多视角参考图锁定一致性） → 分镜表（镜号 / 画面描述 / 台词 / 时长 / 运镜） → 关键帧生成（文生图，按角色参考图与风格锚点） → 图生视频 / 镜头运动（可选） → 配音与对白（TTS + 字幕对齐） → 合成（音轨 + 字幕 + 转场）→ ComicFilm → 提交审核 → 发布 / 导出

角色一致性规则

  • 每个角色维护一组「参考图 + 外观描述 + 种子」，生成时作为固定输入，禁止跨镜头随机漂移。
  • 角色设定变更需用户显式确认，并记录为工程版本（version 递增），便于回滚。
  • 一致性校验失败（人脸/服饰差异超阈值）时，任务标记 failed 并提示重生成，而非静默接受。

生成任务与队列

  • 所有模型调用统一封装为 GenerationJob，按工程 + 镜头粒度可重试，状态机见 §4.2。
  • 队列按用户配额与付费等级分配并发位；同工程禁止并发全量重生成，避免成本失控。
  • 任务失败自动重试上限 3 次（指数退避），超限转人工介入并通知用户。
  • 任务产物落对象存储，数据库只存 object key 与校验信息（尺寸、时长、哈希）。

成本与配额

  • 按模型调用计量（图片张数 / 视频秒数 / TTS 字数），免费用户与付费等级配额不同，配额由订阅计划决定。
  • 每次任务创建前先做配额与成本预检，不足直接拒绝并提示升级或购买额度包。
  • 实际消耗与预估偏差超阈值时写入成本告警，供运营侧调整模型路由（供应商与单价见 OQ-08）。

成片版本与发布

  • 同一工程可产出多个 ComicFilm 版本，版本号单调递增，旧版本只读保留。
  • 发布前必须通过内容审核（机审 + 人审），审核不通过不得对外可见。
  • 发布后可下线（archived），下线不影响已导出到本地的文件。
  • P0 内只做作品管理与浏览，不含全站推荐与多渠道分发（见 §3 P1 内容管理）。

异常与边界

  • 模型供应商超时/限流：任务转 failed 并按退避重试，不阻塞其他工程队列。
  • 用户取消运行中任务：已产生的模型费用按供应商规则结算，不退还配额。
  • 版权与合规：输入素材与生成产物需留存来源记录，侵权投诉可定位到工程与任务（详见 OQ-07）。
  • 敏感题材：涉及真人肖像、未成年人、暴力等题材需强制人审，机审不通过不得进入生成队列。

FR-04 多端体验一致性

目的

用户在不同端使用产品时，核心功能、数据、状态保持一致。各端的 UI 差异仅由平台适配层处理，业务逻辑统一。

一致性契约

维度统一规则
账号与订阅同一市场内跨端实时同步
业务数据用户产生的数据在所有端可见可编辑
文案与术语同一概念在所有端使用同一文案（来自 i18n 资源）
错误提示同一错误码在所有端映射为同一用户可读提示
设计系统Design Token 统一颜色、间距、字号，各端组件库基于 Token 实现
平台兼容下限iOS 15.0+ / Android 9.0+ / 微信、支付宝、抖音、百度、QQ 小程序 / Windows 10–11 / macOS 12+ / Ubuntu 20.04+（P0/P1 分列见 §3「平台兼容性要求」矩阵）

平台适配层职责

  • 登录：封装各端原生登录 SDK（微信、支付宝、Google、Apple）
  • 支付：封装各端支付 SDK（微信支付、支付宝、Stripe、IAP）
  • 推送：封装各端推送通道（APNs、FCM、厂商通道）
  • 存储：封装本地存储 API（localStorage、AsyncStorage、SQLite）
  • 分享：封装各端原生分享能力

FR-05 国际化与本地化

多语言

  • 默认语言：中文（简体）、英文；后续按需扩展 TBD：首批语种清单
  • 语言检测优先级：用户设置 → 浏览器/系统语言 → 默认语言
  • 所有用户可见文案从 i18n 资源加载，禁止硬编码
  • 支持 RTL 布局（阿拉伯语等）P1

多币种与价格

  • 每个计划按币种独立定价，不使用实时汇率换算
  • 币种由 region 决定，国内默认 CNY，海外默认 USD
  • 价格展示包含货币符号与两位小数（日元等零小数币种除外）

多时区

  • 服务端时间统一存储为 UTC
  • 展示时按用户时区转换，时区默认取系统时区，可在设置中修改

FR-06 合规与隐私

隐私政策与用户协议

  • 首次注册时必须展示隐私政策与用户协议，用户勾选同意后方可继续
  • 隐私政策包含：数据收集清单、使用目的、存储期限、第三方 SDK 清单（来源：docs/wiki/09-third-party-sdk-inventory.md）、用户权利（访问、更正、删除、注销）
  • 政策更新时，用户下次登录需重新确认

数据收集最小化

  • 仅收集实现功能所必需的数据
  • 敏感数据（手机号、邮箱）加密存储，展示时脱敏
  • 国内数据存储于境内服务器，海外数据存储于对应区域，数据不出境
  • 第三方 SDK / API 密钥一律不入库：仓库仅提交空值占位模板 .env.example，真实密钥只保存在本地环境变量或 KMS；密钥登记唯一真源为 docs/wiki/09-third-party-sdk-inventory.md，一致性由 scripts/env-check.mjs 校验

账号注销与数据删除

  • 用户可申请账号注销，注销前提示：订阅将失效、数据将删除且不可恢复
  • 注销申请有 7 天冷静期，期间可撤销
  • 冷静期结束后，删除用户个人数据，保留匿名化的订单与财务记录（合规要求）
  • 海外用户的数据删除请求按 GDPR/CCPA 要求在 30 天内处理
