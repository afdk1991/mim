Mim 全平台产品底座 — 产品需求文档

版本：V0.0.0-preview　|　通道：preview　|　日期：2026-11-04　|　状态：草案

本文档定位：定义 Mim 全平台产品底座的 P0 核心用户旅程与功能需求。底座支撑多产品形态（工具/SaaS/内容/电商/社交）、多端（Web/小程序/App/PC）、双市场（国内+出海）、全能力（支付/IM/音视频/AI）。旗舰产品形态于 2026-11-04 重定义为 SaaS 工具型（按模块一次性解锁）— 功能模块商城 + 漫剧 AI 剧工作室（FR-03 全节重写，早期旗舰形态及其功能条目已按用户指令于 2026-11-10 从文档中删除）。核心工作区由两域构成：功能模块商城负责模块上架、定价与解锁；漫剧 AI 剧覆盖 AI 全自动成片、AI 辅助创作工作台、作品管理与分发、工作台+导出成片四种交付形态。首端为 Web + 微信小程序（国内），出海以 App + Web 切入。

1. 背景与目标

观察到的问题：一套产品需要同时覆盖国内与海外、PC 与移动、小程序与原生 App，且要求支付、IM、音视频、AI 等重资产能力。若按传统方式为每个端独立开发业务逻辑，会导致：

  • 同一功能在多端重复实现，改一处需同步 N 处；
  • 国内/海外数据与账号体系后期打通代价极高；
  • 支付、IM、音视频等能力在各端重复对接，无法统一治理。

产品决策：采用「Headless 中台 + 多端薄壳」架构，将业务逻辑、能力网关、账号与数据下沉为共享层，各端仅负责 UI 与平台 API 适配。

可观测的目标：用户在任意一端完成注册登录后，可在其他所有端以同一身份登录并使用已解锁的功能；IM、音视频、AI 能力对业务方以统一接口暴露，国内/海外差异由驱动层屏蔽。

2. 产品契约

要素定义
主要用户终端用户（国内 / 海外）、运营管理员
核心任务注册账号 → 进入功能模块商城解锁模块（一次性购买） → 在漫剧 AI 剧工作台创作 → 导出成片 → 跨端继续使用

信任基础数据合规（PIPL/GDPR）、隐私保护（最小收集 + 可删除）、内容合规审核

3. 范围

P0 必须交付

  • 账号与身份：注册、登录、跨端账号打通、国内（手机号+微信/支付宝）与海外（邮箱+Google/Apple）双登录体系
  • 核心 SaaS 工作区 — 功能模块商城：模块目录与详情、模块定价（按 region / 币种独立定价）、模块解锁（Entitlement）、解锁状态校验；解锁方式为一次性购买解锁（`unlock_mode=one_time`，唯一方式）。
  • 核心 SaaS 工作区 — 漫剧 AI 剧：覆盖四种交付形态 ① AI 全自动生成成片（题材/剧本大纲 → AI 分镜与角色设定 → 静帧/关键帧 → 合成漫剧短视频，需接入文生图/图生视频模型与任务队列）② AI 辅助创作工作台（剧本、分镜、角色一致性、对白、配音由 AI 建议、人工确认，交付物为创作工程）③ 漫剧作品管理与分发（成片管理、版本、发布与浏览；2026-11-12 上线「放映厅」：`/comic-studio` 默认进入视频播放页，匿名可看内置演示片库，登录后可播放本人成片，支持集数切换与断点续播）④ 创作工作台 + 导出成片（②与③的组合）。四种形态均在本 P0 定义范围内，按 §5 FR-03.2 的形态表与 [07 §12](./docs/wiki/07-functional-modules.md) 拆分清单分里程碑落地
  • 多端体验一致性：Web、微信小程序、App（iOS/Android）、PC（Win/macOS）至少一端可用，其余端适配
  • 国际化基础：i18n 多语言、多币种、多时区
  • 合规与隐私：隐私政策、用户协议、数据收集清单、账号注销、数据删除请求

P1 后续迭代

4.2 核心对象与状态

Module（功能模块）

状态进入条件可执行操作
draft运营创建，尚未上架编辑信息与定价、预览、提交上架
active审核通过并开放售卖用户可浏览、一次性购买解锁；运营可下架
archived运营下架不可新购；已产生的 Entitlement 在其有效期内继续可用

Entitlement（模块解锁）

状态进入条件可执行操作
active一次性购买解锁已发放，或运营手工发放使用该模块
expired时效到期的临时解锁重新解锁后恢复；永久解锁不进入此状态
revoked运营风控回收不可使用该模块，需重新解锁

ComicProject（漫剧工程）

状态进入条件可执行操作
draft新建工程，已填题材/大纲编辑大纲、角色设定、剧本、分镜；发起生成
storyboarded分镜与角色设定已确认生成静帧/关键帧；回退至 draft 修改
generating存在排队或运行中的 GenerationJob查看进度、取消任务；不可并发发起全量重生成
rendered成片合成成功，ComicFilm 已生成预览、重生成局部、发布、导出
published作品已发布至作品库查看、下架归档、产生新版本
archived用户归档或长期未活跃恢复；不可直接发布

ComicFilm（成片）

状态进入条件可执行操作
draft合成完成，未提交审核预览、重新合成、删除
reviewing已提交内容审核查看审核状态；不可编辑
published审核通过并发布浏览、分享、下架归档
archived用户下架归档或运营强制下架恢复或删除；不再对外可见

GenerationJob（生成任务）

状态进入条件可执行操作
queued已提交，等待配额与并发位取消；查看队列位次
running已分配模型资源（文生图/图生视频/合成）查看进度；取消（已产生费用按供应商规则结算）
succeeded模型返回产物并通过校验下载产物、挂载至工程节点
failed模型报错、超时或产物校验不通过按 retry_count 重试（上限 3 次）；超限转人工介入
canceled用户取消或系统熔断重新发起
状态机通用约束：所有状态变更必须经领域层校验并写入事件表（只追加，禁止 UPDATE 历史）；模块解锁的发放必须与触发其的业务动作在同一事务内完成，避免出现「已付款未解锁」。

5. 功能需求

FR-01 账号与身份

目的

用户在任意端完成注册/登录后，其账号状态（基础资料、地区、登录方式绑定）在所有端实时同步。国内与海外采用不同的登录方式，但底层账号体系统一。

注册与登录方式

市场注册/登录方式说明
国内手机号 + 验证码、微信登录、支付宝登录手机号为主，第三方为辅
海外邮箱 + 密码/验证码、Google Sign-In、Apple Sign-InApp 端提供第三方登录时必须同时提供 Apple Sign-In（App Store 要求）

已实现的最小可用登录入口（2026-11-12）

在短信 / 邮件第三方通道尚未注入私有凭证的阶段，为避免「普通访客没有任何可自助的登录入口」导致聊天等模块实际不可用，先落地三条不依赖外部通道的入口，并由前端按部署实际能力自动呈现：

  • 自助注册 + 账号口令登录：POST /api/v1/auth/register（region + 账号标识 + 口令，可选昵称）创建自建账号，口令以 bcrypt 摘要写入 credentials（kind=password），注册成功即下发访问 / 刷新令牌；随后可用 POST /api/v1/auth/password 以同一账号口令登录。口令要求至少 8 位且同时包含字母与数字，重复注册返回 409 AUTH_IDENTITY_EXISTS。
  • 管理员口令登录：同一 /auth/password 端点，口令来自部署环境变量 MIM_AUTH_ADMIN_PASSWORD，用于冷启动与运维登录；与账号口令互不覆盖，两者都未配置时返回 503 AUTH_PASSWORD_NOT_CONFIGURED。
  • 通道自检：GET /api/v1/auth/channels 只返回 {sms,email,password,register} 布尔值，登录页据此在验证码通道未配置时直接提示「请改用密码登录或注册」，避免用户反复触发 503。
  • 聊天匿名只读体验：/chat 匿名访问不再显示「此功能需登录后使用」空白卡片，而是进入只读演示页（同一套聊天布局、示例会话与消息、禁用输入区、登录/注册引导），登录后才创建会话、收发消息、传文件与群管理。
  • 信息架构收口：账号设置不再是面向未登录访客的独立页面——原「设置」页的昵称 / 语言 / 时区 / 区域信息 / 注销操作全部并入登录后的个人中心（「资料」与「账号与设置」两个分区），导航里的个人中心入口仅在登录后出现；旧 /settings 链接自动落到 /account。
  • Mim ID 自动分配：每个新用户在建号事务内自动获得对外编号 MIM-10000001 起的 8 位补零号码（唯一索引 uq_users_member_no，上限 99_999_999），与内部 uuidv7 主键解耦。自助注册、验证码首登、密码首登、第三方首登四条链路全部收敛到同一建号入口 identity.ts createUser，因此「注册即发号」没有例外；注册成功页先展示号码再进入工作台，个人中心资料区与账号安全区均显示该号码。历史无号用户在服务启动时按 created_at ASC 批量补齐（可重放幂等），登录时再兜底一次。
  • 第三方登录统一入口：/signin 一次性展示 9 家提供方（GitHub / Gitee / GitLab / Google / Apple / Microsoft / 微信 / QQ / 抖音），按 region 过滤、未配置凭证的直接置灰并标注「未配置」。流程为 POST /auth/oauth/:provider/authorize 取授权地址 → 平台回跳 GET|POST /auth/oauth/:provider/callback → 302 带 300 秒一次性票据回前端 → POST /auth/oauth/exchange 换取双令牌。正式令牌不出现在地址栏；state 只存 sha256、10 分钟过期、回调即删。登录后可主动绑定 / 解绑第三方账号，但受「同一第三方身份不可绑两个 Mim 账号」与「至少保留一种登录方式」约束。

短信与邮件通道（阿里云短信 / AWS SES）代码路径已就绪，注入 MIM_SMS_ALIYUN_* 或 MIM_EMAIL_SES_* 环境变量后 /auth/channels 自动置真、验证码入口自动可用，无需改代码。自助注册的开放程度、频控与邮箱验证属产品与安全待决策项（当前注册端点无独立限流，仅受口令强度与登录失败锁定约束）。

跨端账号打通规则

  • 同一手机号或邮箱在国内与海外视为不同账号（数据物理隔离，region 维度区分）
  • 同一市场内，手机号、微信、支付宝等不同登录方式可绑定至同一账号
  • 绑定需二次验证（已登录方式确认 + 新方式验证码）
  • 账号合并：若用户用两种方式注册了两个账号，可申请合并，合并后身份绑定与历史业务数据归并至保留账号 TBD：合并策略细节

异常与边界

  • 验证码发送频率限制：同一标识 60 秒内仅一次，1 小时内不超过 5 次
  • 验证码 5 分钟有效，错误 5 次后失效需重新获取
  • 登录失败 5 次后账号锁定 15 分钟（仅该端，不影响其他端在线会话）
  • 已登录用户在新设备登录时，若开启设备保护，需邮件/短信确认

FR-03 核心 SaaS 工作区（功能模块商城 + 漫剧 AI 剧）

2026-11-04 重定义：原 FR-03「项目 → 任务 → 子任务 + 协作 + 仪表盘 + 同步 + CSV 导出」已整体移除。新 FR-03 由两域构成：FR-03.1 功能模块商城（模块上架、定价、解锁与订单挂载）与 FR-03.2 漫剧 AI 剧（四种交付形态）。两域共享 §4.2 的 Module / Entitlement / ComicProject / ComicFilm / GenerationJob 状态机。

FR-03.1 功能模块商城

目的：用户可在商城中浏览模块、按 region 与币种查看定价，并通过一次性购买解锁（unlock_mode=one_time，唯一方式）获得模块使用权；服务端以 Entitlement 作为唯一鉴权依据，端上不得自行判断是否已购买。当前未实现在线支付，解锁由运营侧经独立管理后台发放与回收（apps/admin 权益管理页，生产入口 /admin/，2026-11-08 已上线：权益列表过滤、发放、回收与审计事件时间线；同后台另含商城管理页，支持模块创建 / 编辑 / 状态流转 / 软删除与定价行 CRUD）。

字段说明
module_id模块唯一标识（稳定不变，改版不换 ID）
code机器可读编码，用于代码内鉴权（如 comic-studio、ai-film-auto）
name / summary多语言名称与简介（zh-CN / en-US）
unlock_modeone_time（一次性永久解锁，唯一方式）
price按 region + currency 独立定价，金额为最小货币单位整数
entitlements_required前置模块依赖（如「全自动成片」依赖「创作工作台」），未满足时商城展示为「需先解锁 X」
statusdraft / active / archived（状态机见 §4.2）
region可售区域；cn 与 global 独立定价、独立库存策略

定价与解锁规则

  • 一次性购买解锁：解锁发放后为永久 Entitlement(active)，不随任何外部状态变化；仅由运营风控回收转 revoked。
  • 改价不改史：价格变更只影响新解锁记录；已发放解锁不受影响。

主流程

浏览商城 → 模块详情（查定价 / 查前置依赖） → 确认一次性购买解锁 → 发放 Entitlement(active) → 工作区入口点亮 → 前置依赖缺失 → 禁止解锁（ENTITLEMENT_REQUIRED）

当前无在线支付，解锁发放由运营侧动作触发。

模块真实能力（2026-11-11 全覆盖）

  • 205 条导航条目全部具备可调用能力：62 条工具型专项能力 + 17 条「模块起盘蓝图」分组能力（一条能力绑定该一级分组下全部 143 条软件方向模块），商城页不再出现「规划中」徽标。
  • 调用端点 POST /modules/:code/invoke：入参 { text, options }，出参 { output, output_kind, meta, elapsed_ms }；门禁 = 登录 + 模块 active + 已登记能力 + 有效权益。
  • 蓝图能力按路由下发的 module_code 取该条目专属交付目标、技术栈与起步代码，再由分组模板补目录树、交付物与验收清单，产出可直接开工的模块起盘文档。

异常与边界

  • 价格展示金额必须由服务端计算，客户端传入金额一律忽略。
  • 模块下架（archived）后不可新购解锁，但已发放的解锁继续可用。
  • 前置依赖缺失时禁止解锁，接口返回明确错误码（如 ENTITLEMENT_REQUIRED）。
  • 解锁回收必须与触发其的风控动作同事务，避免出现「已回收仍可用」。

FR-03.2 漫剧 AI 剧（四种交付形态）

目的：以同一套创作工程（ComicProject）承载四种交付形态，用户可按需在「AI 建议 + 人工确认」与「AI 全自动」之间切换，最终交付可以是创作工程，也可以是成片（ComicFilm）。

形态交付物关键能力
① AI 全自动生成成片漫剧短视频（成片）题材/大纲 → AI 分镜与角色设定 → 静帧/关键帧 → 合成短片；需文生图/图生视频模型 + 任务队列，全程可无人值守
② AI 辅助创作工作台创作工程（不出成片）剧本、分镜、角色一致性、对白、配音由 AI 建议，人工逐项确认后保存工程；支持导出素材
③ 漫剧作品管理与分发成片管理与发布成片管理、版本、发布与浏览；不含 AI 生成能力（承接外部导入的成片）
④ 创作工作台 + 导出成片创作工程 → 成片②与③组合：先在工作台完成工程，再由 AI 生成分镜图并合成短片导出

创作流水线

题材 / 剧本大纲 → 结构化剧本（AI 建议 + 人工确认）→ 角色设定（多视角参考图锁定一致性） → 分镜表（镜号 / 画面描述 / 台词 / 时长 / 运镜） → 关键帧生成（文生图，按角色参考图与风格锚点） → 图生视频 / 镜头运动（可选） → 配音与对白（TTS + 字幕对齐） → 合成（音轨 + 字幕 + 转场）→ ComicFilm → 提交审核 → 发布 / 导出

角色一致性规则

  • 每个角色维护一组「参考图 + 外观描述 + 种子」，生成时作为固定输入，禁止跨镜头随机漂移。
  • 角色设定变更需用户显式确认，并记录为工程版本（version 递增），便于回滚。
  • 一致性校验失败（人脸/服饰差异超阈值）时，任务标记 failed 并提示重生成，而非静默接受。

生成任务与队列

  • 所有模型调用统一封装为 GenerationJob，按工程 + 镜头粒度可重试，状态机见 §4.2。
  • 队列按全局成本上限分配并发位；同工程禁止并发全量重生成，避免成本失控。
  • 任务失败自动重试上限 3 次（指数退避），超限转人工介入并通知用户。
  • 任务产物落对象存储，数据库只存 object key 与校验信息（尺寸、时长、哈希）。

成本与配额

  • 按模型调用计量（图片张数 / 视频秒数 / TTS 字数）；以成本上限预检控制用量——单任务上限 MIM_AI_JOB_COST_LIMIT_MINOR（默认 100000 分）、当日累计上限 MIM_AI_DAILY_COST_LIMIT_MINOR（默认 500000 分）。
  • 每次任务创建前先做成本预检，超限直接拒绝并返回明确错误码。
  • 实际消耗与预估偏差超阈值时写入成本告警，供运营侧调整模型路由（供应商与单价见 OQ-08）。

成片版本与发布

  • 同一工程可产出多个 ComicFilm 版本，版本号单调递增，旧版本只读保留。
  • 发布前必须通过内容审核（机审 + 人审），审核不通过不得对外可见。
  • 发布后可下架归档（archived），归档不影响已导出到本地的文件。
  • 实现状态（2026-11-08，与代码交叉核对）：形态④「导出成片」已落地——POST /api/v1/comic/films/:id/export 基于最新成片版本签发 1 小时有效的一次性预签名下载地址；MP4 / 1080p 直接下载原片，MOV / 720p 等组合需服务端配置 MIM_FFMPEG_PATH 转码，未配置时前端提供本地化降级说明与「直接下载原片」一键入口。契约测试 9 例与浏览器真渲染 E2E 14 项断言全通过，实现明细见 08 §1.2 成片导出实现。
  • P0 内只做作品管理与浏览，不含全站推荐与多渠道分发（见 §3 P1 内容管理）。

异常与边界

  • 模型供应商超时/限流：任务转 failed 并按退避重试，不阻塞其他工程队列。
  • 用户取消运行中任务：已产生的模型费用按供应商规则结算，不退还配额。
  • 版权与合规：输入素材与生成产物需留存来源记录，侵权投诉可定位到工程与任务（详见 OQ-07）。
  • 敏感题材：涉及真人肖像、未成年人、暴力等题材需强制人审，机审不通过不得进入生成队列。

FR-03.3 对象模型与状态机

商城与漫剧的对象状态机统一在 §4.2「核心对象与状态」定义：Module（draft/active/archived）、Entitlement（active/expired/revoked）、ComicProject（draft/storyboarded/generating/rendered/published/archived）、ComicFilm（draft/reviewing/published/archived）、GenerationJob（queued/running/succeeded/failed/canceled）。

FR-04 多端体验一致性

目的

用户在不同端使用产品时，核心功能、数据、状态保持一致。各端的 UI 差异仅由平台适配层处理，业务逻辑统一。

一致性契约

维度统一规则
账号同一市场内跨端实时同步
业务数据用户产生的数据在所有端可见可编辑
文案与术语同一概念在所有端使用同一文案（来自 i18n 资源）
错误提示同一错误码在所有端映射为同一用户可读提示
设计系统Design Token 统一颜色、间距、字号，各端组件库基于 Token 实现
平台兼容下限iOS 15.0+ / Android 9.0+ / 微信、支付宝、抖音、百度、QQ 小程序 / Windows 10–11 / macOS 12+ / Ubuntu 20.04+（P0/P1 分列见 §3「平台兼容性要求」矩阵）

平台适配层职责

  • 登录：封装各端原生登录 SDK（微信、支付宝、Google、Apple）
  • 推送：封装各端推送通道（APNs、FCM、厂商通道）
  • 存储：封装本地存储 API（localStorage、AsyncStorage、SQLite）
  • 分享：封装各端原生分享能力

FR-05 国际化与本地化

多语言

  • 默认语言：中文（简体）、英文；后续按需扩展 TBD：首批语种清单
  • 语言检测优先级：用户设置 → 浏览器/系统语言 → 默认语言
  • 所有用户可见文案从 i18n 资源加载，禁止硬编码
  • 支持 RTL 布局（阿拉伯语等）P1

多币种与价格

  • 每个模块按币种独立定价，不使用实时汇率换算
  • 币种由 region 决定，国内默认 CNY，海外默认 USD
  • 价格展示包含货币符号与两位小数（日元等零小数币种除外）

多时区

  • 服务端时间统一存储为 UTC
  • 展示时按用户时区转换，时区默认取系统时区，可在设置中修改

FR-06 合规与隐私

隐私政策与用户协议

  • 首次注册时必须展示隐私政策与用户协议，用户勾选同意后方可继续
  • 隐私政策包含：数据收集清单、使用目的、存储期限、第三方 SDK 清单（来源：docs/wiki/09-third-party-sdk-inventory.md）、用户权利（访问、更正、删除、注销）
  • 政策更新时，用户下次登录需重新确认

数据收集最小化

  • 仅收集实现功能所必需的数据
  • 敏感数据（手机号、邮箱）加密存储，展示时脱敏
  • 国内数据存储于境内服务器，海外数据存储于对应区域，数据不出境
  • 第三方 SDK / API 密钥一律不入库：仓库仅提交空值占位模板 .env.example，真实密钥只保存在本地环境变量或 KMS；密钥登记唯一真源为 docs/wiki/09-third-party-sdk-inventory.md，一致性由 scripts/env-check.mjs 校验

账号注销与数据删除

  • 用户可申请账号注销，注销前提示：已解锁模块将失效、数据将删除且不可恢复
  • 注销申请有 7 天冷静期，期间可撤销
  • 冷静期结束后，删除用户个人数据，仅保留匿名化的必要合规记录
  • 海外用户的数据删除请求按 GDPR/CCPA 要求在 30 天内处理

FR-07 即时通讯与视频通话

功能概述

  • 支持单聊（direct）与群聊（group），会话列表按最后消息时间倒序
  • 消息类型：文本、图片、文件、系统消息；图片/文件走 media 预签名上传，WS 仅传 object_key 引用
  • 消息通过 WebSocket 实时推送，离线消息在下次连接时可通过 HTTP 拉取
  • 支持已读回执（message.read），成员可查看自己的未读数
  • 支持「输入中」状态广播（typing 帧）
  • 用户上线或离线时向其会话成员推送 presence 帧
  • 引用回复（2026-11-11）：消息可携带 reply_to_id，服务端在发送时校验被引用消息仍存在且未撤回，并固化 reply_excerpt 摘要快照；气泡内渲染引用块，发送后引用态自动清除
  • 文件气泡下载（2026-11-11）：文件消息展示文件名与体积，并提供 presign 下载直链按钮，失败时回退为纯文本文件名
  • 群管理（2026-11-11）：群主可设/撤管理员、转让群主，群主与管理员可移除成员、搜索并邀请入群；成员变更通过 conversation.members 帧广播，成员数与角色实时刷新
  • 会话内搜索与定位（2026-11-11）：搜索结果最多 20 条，点击后以 ?around= 拉取目标消息上下文窗口并高亮 2.6 秒
  • 未读分割线与表情（2026-11-11）：按 unread_count 换算锚点渲染「以下是新消息」分割线；输入区提供 20 个 Unicode 表情的快捷选择器

视频通话

  • 信令复用 WebSocket 连接：call.invite → call.offer → call.answer → call.ice → call.hangup
  • 媒体走 WebRTC（RTCPeerConnection），STUN 服务器 stun:stun.l.google.com:19302
  • 前端浮动窗口展示本地与远端视频流，支持挂断
  • 当前未配置 TURN 服务器，对称 NAT 环境下可能无法直连（待后续按需引入免费 TURN）

协议与鉴权

  • WebSocket 端点：wss://mim.mixm.top/api/v1/im/ws?token=<access_token>
  • 鉴权：query.token 经 JWT 校验；失败时完成 101 握手后发送 error 帧并以 close code 1008 关闭
  • 心跳：客户端 25s 发 ping，服务端回 pong，10s 超时断开
  • 断线自动重连：指数退避 0.5s → 10s
