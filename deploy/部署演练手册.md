# Mim 部署演练手册（本机基准 → 生产 systemd 等效）

> 目的：把「本机 Windows 开发机 + 本地 PostgreSQL + node 直跑 server」这条已跑通的
> 基准链路，逐项对应到生产（Linux + systemd + nginx）的等效动作，作为每次发版前
> 的演练清单。全程无 Docker。

---

## 一、本机基准（Windows 开发机，已跑通）

前置：本机 PostgreSQL 在 127.0.0.1:5432 已起，库 `mim` 已迁移。

```powershell
# 在仓库根目录 F:\合并项目\Mim 下
$env:DATABASE_URL='postgres://postgres:postgres@127.0.0.1:5432/mim'
$env:JWT_SECRET='mim-local-test-secret-1541559655'
$env:PORT='8787'
node server/src/main.js
```

另开一个终端验证：

```powershell
Invoke-RestMethod http://127.0.0.1:8787/api/health          # ok/db=true
Invoke-RestMethod 'http://127.0.0.1:8787/api/health?full=1'  # migrations 明细
```

跑通判据：

- `/api/health` 返回 `ok=true`、`db=true`、`rpcs` 计数与 `RPCS` 注册表一致；
- `/api/health?full=1` 的 `migrations.pending` 为空（磁盘迁移都已应用）；
- stdout 访问日志是 JSON 行（含 `request_id/status/ms/ip`）。

这是生产演练的**对照基准**——生产上任何一步的期望输出都应与它一致。

## 二、生产等效（Linux + systemd + nginx）逐项对应

| 本机动作（Windows 基准） | 生产等效 | 文件 |
| --- | --- | --- |
| `$env:DATABASE_URL=...` | 写进 `/opt/mim/server/.env` 的 `DATABASE_URL` | `deploy/install.sh` 自动生成 |
| `node server/src/main.js` | `systemctl restart mim-server`（开机自启 + 崩溃重启） | `deploy/mim-server.service` |
| 手动开终端跑 | `WorkingDirectory=/opt/mim/server`、`EnvironmentFile=.env`、`ExecStart=/usr/bin/node src/main.js` | `mim-server.service` |
| 直接访问 :8787 | nginx 80 反代 `/api/` → 127.0.0.1:8787，静态直出 dist | `deploy/nginx-mim.conf` |
| 手动看终端日志 | `journalctl -u mim-server -f`（日志走 journald） | `mim-server.service` |
| （无） | nginx 访问日志按天轮转 14 天 | `deploy/logrotate-mim.conf` |

## 三、一次性演练步骤（干净服务器上）

```bash
# 0) 装 node>=20 / postgresql / nginx / rsync（或用 SKIP_PKGS=1）
# 1) 一键部署（root）
sudo MIM_DIR=/opt/mim DOMAIN=example.com ./deploy/install.sh

# 2) 演练自检（等价于本机一、的三条）
systemctl status mim-server                 # active (running)
curl -fsS http://127.0.0.1:8787/api/health  # 本机直连
curl -fsS http://127.0.0.1/api/health       # 走 nginx 80
curl -fsS 'http://127.0.0.1:8787/api/health?full=1'   # migrations 对齐
/opt/mim/scripts/monitor.sh                 # 五项探活全 OK
```

### 3.1 systemd 单元要点核对

- `WorkingDirectory` 必须是 `/opt/mim/server`（storage.js 相对路径 `./data/uploads` 依赖它）；
- `EnvironmentFile=/opt/mim/server/.env`（密钥唯一来源，脚本只读 process.env）；
- `ReadWritePaths=/opt/mim/server/data`（`ProtectSystem=full` 下唯一可写目录，上传落这里）；
- `Restart=always`（崩溃自动拉起）。

### 3.2 nginx 要点核对

- `root /opt/mim/dist`（前端构建产物）；
- `location /api/ { proxy_pass http://127.0.0.1:8787; }`（**末尾不带斜杠**，否则 /api 前缀丢）；
- `try_files $uri /index.html`（SPA 回退）；
- `client_max_body_size` 与 `UPLOAD_MAX_BYTES` 一致（默认 3MB）。

### 3.3 logrotate 要点核对

- `install.sh` 已按发行版替换属主（Debian `www-data:adm`，RHEL `nginx:nginx`）；
- 干跑：`sudo logrotate -d /etc/logrotate.d/mim` 无报错。

## 四、无容器闸门核对

本项目全程不用 Docker，CI 里有专门闸门（`deploy.yml` / `build.yml` 的
「禁止容器化产物」步骤）：仓库里一旦出现 `Dockerfile` / `docker-compose.yml` /
`.dockerignore` 就让流水线红。部署演练前确认这三个文件在仓库里**不存在**：

```bash
git ls-files | grep -Ei '(^|/)(Dockerfile|docker-compose\.ya?ml|\.dockerignore)$' || echo '无容器产物，OK'
```
