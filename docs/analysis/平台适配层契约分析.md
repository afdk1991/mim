# 平台适配层契约分析

> 分析对象：`src/platform/`（types/index/web/capacitor/miniprogram/mock/contract-check）、`tests/platform-contract.test.ts`、`src/core/storage.ts`、`src/core/theme.ts`、`src/core/http.ts`。
> 证据基准：上述文件的 `文件:行号` 引用。未运行时验证的事项在文末单列。

---

## 分析结论摘要

1. **分层清晰、方向正确**：`IPlatformAdapter = { kind, storage, env, ui }`（`platform/types.ts:52-57`）是全工程唯一允许触碰宿主环境（window/document/wx/Capacitor）的位置，core/domain/pages 一律经 `getPlatform()` 取能力，且 platform 层不 import core/React（`types.ts:4-10`）。
2. **四端复用做得很省**：Capacitor 不另写存储/环境，直接复用 `webStorage/webEnv/webUi`，只覆写 `openExternal`（`platform/capacitor.ts:29-43,45-52`）；真正的差异只收敛在「开外链」一处。
3. **契约校验是「类型/布尔型」而非「语义等价」**：`contract-check.ts` 的 13 条用例只校验返回值类型与 `true/false`，不校验行为内容（如复制的文本是否等于原文、分享是否真的发生），也无法区分「真的可用」与「恒返回 true 的桩」。
4. **真实 Capacitor 原生分支未被契约测试覆盖**：测试用的是 `createCapacitorAdapterForTest()`（纯 Web 语义，`capacitor.ts:55-57`），真实 `createCapacitorAdapter()` 里 `await import('@capacitor/browser')` 这条原生分支（`capacitor.ts:33-42`）从不进契约。
5. **网络层没有平台化是最大缺口**：`core/http.ts:63` 直接用全局 `fetch`，不在 `IPlatformAdapter` 内。Web/Capacitor 没问题，但小程序端 `fetch` 不可用（须 `wx.request`），当前抽象对小程序网络层失效。
6. **小程序的「降级语义」被契约静默放行**：`applyTheme` 空实现、`openExternal` 恒 false、`share` 复制到剪贴板却返回 false（`miniprogram.ts:104-131`），这些是刻意的平台差异，但契约只校验「不抛异常 + 返回布尔」，不要求上层感知并给用户降级文案。
7. **没有覆盖并发/容量/异常路径**：存储配额超限、键冲突、离线切换、主题跨会话持久化、`purgeUid`/`migrateOnce` 迁移等均无契约用例。

## 一、分层设计

### 1.1 接口定义（types.ts）

`platform/types.ts` 定义四组最小能力：

```
IPlatformAdapter {
  kind: PlatformKind                       // 'web'|'mock'|'capacitor'|'miniprogram'  (:14)
  storage: KeyValueStore                    // get/set/remove/keys(prefix)  (:19-25)
  env: PlatformEnv                         // prefersDark/isOnline/language/userAgent  (:34-42)
  ui: PlatformUi                           // applyTheme/copyText/share/openExternal  (:45-50)
}
```

宿主全局读取统一收敛在 `hostGlobals()`（`types.ts:78-95`）：从 `globalThis` 安全取 `wx / Capacitor / window / document`，Node/构建期无 window 时返回 null。这是全工程唯一读这些全局对象的地方。

### 1.2 探测与注入（index.ts）

探测顺序（`index.ts:29-34`）：
1. 存在 `wx.getStorageSync` → `miniprogram`
2. `globalThis.Capacitor.isNativePlatform()===true` → `capacitor`
3. 其余 → `web`

`getPlatform()` 带缓存，首次调用才探测（`index.ts:54-57`）；`setPlatform(adapter|null)` 支持测试/原生壳显式注入，传 null 恢复自动探测（`index.ts:60-62`）。

### 1.3 各适配器实现差异

| 能力 | web（`web.ts`） | capacitor（`capacitor.ts`） | miniprogram（`miniprogram.ts`） | mock（`mock.ts`） |
|---|---|---|---|---|
| storage | localStorage，失败退进程内 Map（`web.ts:14-75`） | **复用 webStorage**（`:48`） | `wx.getStorageSync/setStorageSync`，缺键 `''` 归一为 null（`:21-24,31-71`） | 纯内存 Map（`:34-50`） |
| env.prefersDark | `matchMedia('(prefers-color-scheme: dark)')`（`web.ts:78-86`） | 复用 webEnv（`:49`） | `wx.getSystemInfoSync().theme==='dark'`（`:83-87`） | 构造参数注入（`:53`） |
| env.isOnline | `navigator.onLine`（`web.ts:87-91`） | 复用 | `networkType!=='none'`（`:88-91`） | 注入（`:54`） |
| env.language | `navigator.language`（`web.ts:92-96`） | 复用 | `systemInfo.language`（`:92-95`） | 注入（`:55`） |
| ui.applyTheme | 写 `documentElement.dataset.theme`（`web.ts:138-142`） | 复用 webUi.applyTheme（`:30`） | **空实现**（无 document，`:104-106`） | 记录调用（`:60-63`） |
| ui.copyText | `navigator.clipboard` → `execCommand` DOM 兜底（`web.ts:104-135`） | 复用 | `wx.setClipboardData`（`:107-120`） | 注入布尔（`:64-67`） |
| ui.share | `navigator.share`，无则复制 url（`web.ts:144-158`） | 复用 webUi.share（`:32`） | 把文本复制到剪贴板并**返回 false**（提示走右上角菜单，`:121-127`） | 注入布尔（`:68-71`） |
| ui.openExternal | `window.open(...,noopener)`（`web.ts:159-168`） | `await import('@capacitor/browser').Browser.open`，失败退回 web（`:33-42`） | **恒 false**（`:128-131`） | 注入布尔（`:72-75`） |

设计取舍清晰：Capacitor 与 Web 共享一套 WebView 语义，差异仅「开外链走原生 Browser 插件」；小程序把「做不到的能力」如实降级为空/false，不伪造成功。

## 二、contract-check 如何校验适配器与契约

`platform/contract-check.ts` 的 `runAdapterContract(adapter)`（`:21-92`）跑 13 条统一用例：

| # | 用例（`contract-check.ts`） | 校验内容 |
|---|---|---|
| 1 | kind 在白名单（`:34`） | `KIND_WHITELIST` 含 web/mock/capacitor/miniprogram |
| 2-6 | storage set→get、二次覆盖、keys(prefix)、remove 后 null、未写键 null（`:36-57`） | 存储读写自洽与前缀过滤 |
| 7-10 | prefersDark/isOnline 返回 boolean、language 非空串、userAgent 串（`:59-69`） | env 返回类型 |
| 11 | applyTheme dark/light 不抛异常（`:71-75`） | 主题落地不炸 |
| 12-14 | copyText/share/openExternal 返回 boolean（`:77-89`） | ui 能力返回类型 |

判定标准（`:7-8`）：**同一份用例对任意 kind 都必须全绿**；任一红了即说明该端能力语义与 Web 不一致。`contractFailure(cases)`（`:95-99`）全绿返回 null，否则拼出失败明细供 CI 打印。

**关键局限**：用例只断言「返回类型正确」，不断言「行为内容正确」：
- `copyText('mim')` 只检查返回 boolean（`:77`），不检查剪贴板里真的是 `'mim'`；
- `share(...)` 只检查返回 boolean（`:79-83`），不区分 Web 真分享与小程序「复制后返回 false」；
- 一个恒 `return true` 的桩也能全绿通过。

## 三、core 层的抽象与平台差异处理

### 3.1 storage.ts（本地存储统一键 + 元素级校验）

- 键名规范：`mim.<scope>.<field>` 全局、`mim.<scope>.<uid>.<field>` 按身份隔离（`core/storage.ts:22-28`）。
- 所有读写经 `getPlatform().storage`（`:32-54`），本文件是全工程唯一允许出现存储键名规范的地方。
- `readJson/writeJson` 带 parse 逐元素校验，脏数据回退 fallback（`:67-85`）；`arrayOf` 任一元素非法则整体回退（`:88-99`）。
- `migrateOnce` 旧键一次性迁移（`:115-125`）；`purgeUid` 按身份子串清理（`:128-138`）。
- 平台差异处理：写失败/隐私模式静默降级，不抛异常（`:40-46`）。

### 3.2 theme.ts（主题）

- `getTheme()`：先读持久化 `mim.theme`，无则取 `env.prefersDark()`（`core/theme.ts:19-23`）。
- `setTheme()`：落库 + `ui.applyTheme()`（`:29-32`）；`initTheme()` 启动即套用防闪白（`:41-43`）。
- 平台差异：Web/Capacitor 由适配层写 `<html data-theme>`；小程序无 document，适配层空实现、主题由 app.json 全局配置决定（`miniprogram.ts:104-106`）。core 不感知这个差异。

### 3.3 http.ts（传输层）

- 全工程唯一后端出入口（`core/http.ts:1-9`），统一 `Result<T>`、401 交会话层、10s 超时、写不重试读重试 1 次（`:15,110-120`）。
- **但它直接调用全局 `fetch`**（`:63`），并不经过 `IPlatformAdapter`。
- 含义：网络这一宿主能力被排除在平台抽象之外。Web/Capacitor WebView 有 `fetch`，小程序没有（须 `wx.request`）——当前 http 层在小程序端不可用，是抽象的明显缺口。

## 六、缺口与风险

| 编号 | 证据（文件:行号） | 缺口/风险 | 影响 | 建议 |
|---|---|---|---|---|
| P1（高） | `core/http.ts:63` 直接 `fetch`；`types.ts:52-57` IPlatformAdapter 无网络项 | **网络层未平台化**，小程序端无 fetch | 同一套业务代码在小程序端无法发请求，抽象不闭环 | 在 IPlatformAdapter 增加 `http.request` 能力，小程序实现走 `wx.request`，web/capacitor 用 fetch |
| P2（中） | `contract-check.ts:77-89` 只断言返回 boolean | **契约校验类型而非语义**，恒 true 的桩也能全绿 | 适配器退化（如复制失效）测试照样绿 | 增加内容断言：copyText 后校验传入文本；share/openExternal 记录目标，区分「真做了」与「降级 false」 |
| P3（中） | `tests/platform-contract.test.ts:57-59` 用 `createCapacitorAdapterForTest()`；`capacitor.ts:33-42` 原生分支 | **真实 capacitor 原生分支从未进契约** | Browser 插件失败/未 sync 时的回退路径无回归保护 | 对真实 `createCapacitorAdapter()` 增加可注入 Browser 模块的测试，覆盖原生成功与 catch 回退 |
| P4（中） | `miniprogram.ts:104-131` applyTheme 空、openExternal 恒 false、share 复制后返回 false | **小程序降级语义被契约静默放行**，上层未必给用户文案 | 用户点分享/开外链无反应，不知道该走右上角菜单 | 契约增加「降级约定」：share/openExternal 返回 false 时上层必须展示引导文案；或在适配层返回结构化降级原因 |
| P5（低-中） | `contract-check.ts:19` 硬编码 `KIND_WHITELIST`；`types.ts:14` PlatformKind 联合类型 | **两处白名单重复**，新增端要改两个地方（文件注释已自承 `:13`） | 新增鸿蒙/Tauri 时易漏改一处 | 由 `PlatformKind` 派生白名单，或契约直接反射 kind |
| P6（低） | `web.ts:37-46` set 同时写 memory 与 localStorage；get 先读 localStorage | 内存与持久层可能短暂分叉（写成功后读到 localStorage，刷新后持久） | 行为符合预期，但隐私模式下 memory 态随页面生命周期丢失，无跨会话兜底 | 文档化 memory 兜底仅为「本次会话自洽」；如需跨会话降级需另设计 |
| P7（低） | `storage.ts:128-138` purgeUid 用 `k.includes('.${uid}.')` 子串匹配 | 字段名若恰好含 `.local.` 之类会误删 | 注销/切号时可能清掉不该清的键 | 改为按段精确切分键名后比对 uid 段 |
| P8（低） | `index.ts:55` `detectPlatformKind()` 连续调用两次 | 探测结果理论上可在两次调用间变化，造成 kind 不一致 | 实际概率极低 | 探测结果缓存一次再分支 |
