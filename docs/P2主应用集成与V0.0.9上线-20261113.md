# P2 主应用集成与 V0.0.9 上线说明（2026-11-13）

## 一、本轮解决的问题

P2 后端能力此前只在测试自建 mini app 中挂载，主应用 `src/app.ts` 没有注册对应路由，线上会直接 404。本轮把以下路由真正接入生产应用：

| 能力 | 路由 | 挂载位置 | 鉴权 |
|---|---|---|---|
| 邀请码管理 | `/api/v1/admin/invites` 等 | 主应用 `/api/v1` | 管理端 `rbac:write` / `user:read` |
| 实名认证 | `/api/v1/auth/realname/*`、`/api/v1/admin/realname/*` | 主应用 `/api/v1` | 本人端点 `requireAuth`，审核端点 `user:read` / `rbac:write` |
| 跨站 SSO | `/api/v1/auth/sso/ticket|exchange|logout` | 主应用 `/api/v1` | 签发/登出需登录，兑换凭一次性票据 |
| 公告 / 更新日志 / 推广 | `/api/v1/announcements`、`/changelog`、`/promotions`、`/admin/content/*` | 主应用 `/api/v1` | 公开读；管理端 `content:write` |
| 自研工具目录 | `/api/v1/tools`、`/api/v1/tools/:slug`、`/api/v1/tools/manage` | 主应用 `/api/v1` | 公开读；管理端 `appearance:write` |

新增回归测试 `test/p2-routes-mounted.test.ts`，直接对主应用断言：未登录实名返回 401、邀请码管理返回 401、非法 SSO 票据返回 `AUTH_SSO_TICKET_INVALID`、公告/更新日志/工具返回 200。该测试防止“测试 mini app 通过、线上 404”再次发生。

## 二、前端可用性补齐

购物车结算此前固定只传 `channel`，P2 的积分抵扣虽然后端已实现，但前台无法开启。本轮：

- `apps/web/src/api.ts` 的 `cart.checkout` 增加 `use_points` / `points_to_use` 可选参数，并补齐结算结果中的 `points_spent` / `points_deduct_cents` / `payable_cents` 类型。
- `apps/web/src/views/Cart.tsx` 增加「使用积分抵扣」勾选框，结算时传 `use_points`，结果行回显消耗积分与折抵金额。
- 空购物车带积分参数结算返回 200/空结果，不产生异常扣减。

## 三、构建与版本
