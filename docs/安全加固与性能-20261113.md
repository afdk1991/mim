## 2. 导出工厂与挂载建议

> 本包不改 `app.ts`；以下工厂由主控在应用装配层选择性挂载，测试均自建 mini app。

### 2.1 缓存头中间件（必须先于业务路由挂载）

- 工厂：`createCacheHeaderMiddleware(options?: CacheHeaderOptions)`
- 选项：`maxAgeSeconds`（缺省 60）、`scope`（`public`/`private`，缺省 `public`）、`methods`（缺省 `GET`/`HEAD`）。
- 行为：只读方法响应序列化后取 sha256 前 32 位生成弱 ETag；命中 `If-None-Match` 回 304（不发响应体）；写方法不打缓存头。
- **挂载顺序**：与其他全局中间件同层，**先于** `router.use(...)` 业务路由；建议挂在公开只读路由组之上：

```ts
import { createCacheHeaderMiddleware } from './middleware.js';

app.use(createCacheHeaderMiddleware({ maxAgeSeconds: 60, scope: 'public' }));
// 之后再挂载 navigation / 公开 catalog 等只读路由
```

### 2.2 验证码中间件工厂（按场景挂到对应写路由）

- 工厂：`createCaptchaMiddleware(scene: 'register' | 'login' | 'report' | 'post')`
- 行为：off 模式或场景未强制时直接放行；第三方缺凭证/上游不可用抛 503，答案错误/过期抛 400，交全局错误信封收口。

| 场景 | 建议挂载点 |
| --- | --- |
| `register` | `POST /auth/register` 处理前 |
| `login` | `POST /auth/login` 处理前 |
| `report` | `POST /reports`（路由内已直调 `verifyCaptcha(..., 'report', ...)`，无需重复挂中间件） |
| `post` | 论坛发帖 / 回复路由处理前（community.ts 在禁改清单内，待主控接线） |

### 9.2 Redis 重连阻塞修复点

- **根因**：`RedisCache.connect()` 的 `connecting` 承诺在 socket `error` / `close` 事件里只排空了 `pending` 队列，没有 `reject` 连接承诺；断连后再次 `await this.connect()` 永久挂起（此前断连降级用例 20s 超时）。
- **修法**：
  1. 闭包内 `let settled = false`，`failConnect(err)` 先 `failPending(err)`，未收敛则 `reject(err)` 并置 `settled=true`；
  2. `socket.on('error', failConnect)`；`socket.on('close', …)` 先置 `this.socket=null`，再 `failConnect(new Error('redis connection closed'))`；
  3. 握手成功回调先判 `settled` 再 `resolve()`，避免 close 与成功回调双写；
  4. `connecting.finally(…)` 派生承诺补空 `.catch()`，避免拒绝以未处理告警形式冒泡（rawCommand 的 `await` 已收口主承诺）。
- **断连降级行为**：Redis 中途不可用时 `RedisFallbackCache` 自动回落内存后端，业务读写不中断；启动/降级日志如实打印 `[cache] backend=…` 与原因。
