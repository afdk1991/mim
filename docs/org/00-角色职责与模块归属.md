# 角色职责 → 代码模块归属

> **前提声明（重要）**：本项目当前由一人推进，上表 10 岗 11 角色是**职责帽子**而非编制。
> 本文的作用是把每顶帽子钉到**真实存在的目录/文件**上，让「谁对这块负责」有唯一答案，
> 避免多人加入后出现责任真空。凡在下表中出现 Owner 的角色，即为该模块的最终责任人（RACI 中的 A）。

## 10. 命名与风格统一约束（所有角色必须遵守）

| 约束 | 规则 |
|---|---|
| 目录 | 小写中划线（多词），域划分用单数名词：`domain/content`、`pages/system` |
| 组件文件 | PascalCase 且与导出同名：`AdminDevicesPage.tsx` → `AdminDevicesPage` |
| 桶导出 | 每个 `pages/<域>/index.ts` 统一导出，路由表只从桶导入 |
| 依赖方向 | `pages → app → domain → data → core`，反向依赖即缺陷（`core` 不得 import `data`） |
| RPC 参数 | 一律 `p_` 前缀（`p_order_id`），snake_case |
| 前端风格 | 无第三方 UI/状态库；样式用既有 class；错误统一 `Result<T>` 返回不抛异常 |
| 金额 | 统一整数「分」，字段名 `*Fen` / 库列 `*_fen` |
| 平台能力 | 端差异一律经 `src/platform`，禁止裸 `window` / `document` |
| 迁移 | 编号不跳号；每张新/改表写在各自 SQL 内，注释写清负责人与设计取舍 |
