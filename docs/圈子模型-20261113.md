# 圈子模型落地说明（2026-11-13）

本轮在论坛既有「板块（board）」体系之外，独立落地一套以**人 / 兴趣 / 组织**为中心的**成员制社群（circle）**模型：数据表 + 后端路由 + 前端视图 + 契约测试，端到端可跑。圈子与板块是两个概念，不共用表、不互相冒充。

## 二、模型边界：圈子 circle ≠ 板块 board

| 维度 | 板块 board（既有论坛分区） | 圈子 circle（本包新增） |
| --- | --- | --- |
| 中心 | 内容分区，隶属站点 | 人 / 兴趣 / 组织，成员制社群 |
| 核心关系 | 板块 → Tab → 帖子；关注 / 付费门槛 | 成员关系：圈主、管理员、普通成员；加入审核 |
| 准入 | 板块可见性 / 付费 / 关注门槛 | `open` 直入、`approve` 待审、`invite` 邀请码；成员上限 |
| 内容形态 | 板块帖流（`community_threads`） | 圈内专属动态流 + 圈内公告；可跨板块聚合（`circle_posts.thread_id` 可空回填既有板块帖），也可只有纯圈内动态 |
| 存储 | `community_boards / community_board_memberships / community_board_follows / community_board_tab_configs` | `circles / circle_members / circle_posts / circle_notices` 四张独立表 |

结论一句话：**板块是站点下的内容分区，圈子是以人为核心的成员社群；圈子不写板块表，板块表也不冒充圈子。**

## 三、表结构（`schema.d/40-circles.sql`）

由 `db.ts` 的 `applyDomainSchema()` 按文件名升序在 `schema.sql` 之后自动加载；新表全部 `IF NOT EXISTS`，无 `DROP` / `DELETE` / 无覆盖既有数据的 `UPDATE`。

### 1. `circles`（圈子主表）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 内部主键（`circle-<uuid>`），不对外暴露 |
| `slug` | TEXT NOT NULL UNIQUE | 对外标识，小写字母 / 数字 / 连字符，全局唯一 |
| `name` | TEXT NOT NULL | 圈子名称（2~40 字） |
| `intro` | TEXT NOT NULL DEFAULT '' | 简介 |
| `cover_url` | TEXT | 封面图地址，可空 |
| `owner_id` | TEXT NOT NULL → `users(id)` | 圈主（成员角色 `owner`） |
| `visibility` | TEXT NOT NULL DEFAULT `public` | `public` 公开可浏览 / `private` 仅成员可见 |
| `join_mode` | TEXT NOT NULL DEFAULT `open` | `open` 直接加入 / `approve` 待审核 / `invite` 凭邀请码 |
| `member_limit` | INTEGER NOT NULL DEFAULT 0 | 成员上限；`0` 表示不限 |
| `category` | TEXT | 分类标签（兴趣 / 组织 / 地域等） |
| `status` | TEXT NOT NULL DEFAULT `active` | `active` 正常 / `archived` 归档 |
| `invite_code` | TEXT | `invite` 模式邀请码；仅 owner / admin 可见，加入时校验 |
| `created_at` | TEXT NOT NULL | 创建时间（UTC ISO-8601） |

索引：`idx_circles_owner(owner_id)`、`idx_circles_list(visibility, category, status)`；`slug` 由列级 `UNIQUE` 保证唯一。

### 2. `circle_members`（成员关系表）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `circle_id` | TEXT NOT NULL → `circles(id)` ON DELETE CASCADE | 所属圈子 |
| `user_id` | TEXT NOT NULL → `users(id)` ON DELETE CASCADE | 用户 |
| `role` | TEXT NOT NULL DEFAULT `member` | `owner` 圈主 / `admin` 管理员 / `member` 普通成员 |
| `status` | TEXT NOT NULL DEFAULT `active` | `pending` 待审核 / `active` 已加入 / `left` 已退出或被拒 |
| `joined_at` | TEXT NOT NULL | 最近一次加入 / 审核通过时间 |

唯一键：`PRIMARY KEY (circle_id, user_id)`——同一用户在一个圈子内只有一条关系行，重复加入 / 退出 / 审核都在该行流转状态，避免重复行导致成员计数翻倍。
索引：`idx_circle_members_circle(circle_id, status)`、`idx_circle_members_user(user_id, status)`。

### 3. `circle_posts`（圈内动态）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 主键（`circle-post-<uuid>`） |
| `circle_id` | TEXT NOT NULL → `circles(id)` ON DELETE CASCADE | 所属圈子 |
| `thread_id` | TEXT | 关联板块帖（可空；纯圈内动态为 `NULL`，跨板块聚合时回填） |
| `author_id` | TEXT NOT NULL → `users(id)` | 作者 |
| `body` | TEXT NOT NULL | 动态正文 |
| `created_at` | TEXT NOT NULL | 发布时间 |

索引：`idx_circle_posts_circle(circle_id, created_at DESC)`。

### 4. `circle_notices`（圈内公告）

| 列 | 类型 | 说明 |
| --- | --- | --- |
| `id` | TEXT PK | 主键（`circle-notice-<uuid>`） |
| `circle_id` | TEXT NOT NULL → `circles(id)` ON DELETE CASCADE | 所属圈子 |
| `author_id` | TEXT NOT NULL → `users(id)` | 发布者（owner / admin） |
| `body` | TEXT NOT NULL | 公告正文 |
| `created_at` | TEXT NOT NULL | 发布时间 |

索引：`idx_circle_notices_circle(circle_id, created_at DESC)`。

## 四、端点契约

路由前缀 `/api/v1`，工厂签名 `createCirclesRouter(deps: ApiDeps): Router`。公开读链路挂**可选鉴权**（令牌有效则识别「我是否成员」，匿名不阻断）；受保护链路挂 `requireAuth`，所有写操作叠 `idempotency`。错误信封沿用全局 `errorHandler`：`{ error: { code, message, details } }`。

| 方法 | 路径 | 权限 / 门禁 | 主要错误码（details.reason） |
| --- | --- | --- | --- |
| GET | `/circles` | 公开；可选鉴权；支持 `category / visibility / keyword / page / limit` | 400 入参非法 |
| GET | `/circles/:slug` | 公开；`private` 圈子仅 active 成员可读 | 404 `NOT_FOUND`；403 `FORBIDDEN`（私密非成员） |
| POST | `/circles` | 登录；受等级 / 每人数量上限约束；创建者自动成为 owner | 401 `AUTH_UNAUTHORIZED`；403 `CIRCLE_CREATE_LEVEL`；400 `CIRCLE_CREATE_LIMIT`；400 入参校验；409 `CONFLICT`（slug 重复） |
| POST | `/circles/:slug/join` | 登录；`open` 直入 / `approve` 落 pending / `invite` 校验邀请码 | 401；404；409 `CIRCLE_MEMBER_LIMIT`（满员）；400 `CIRCLE_INVITE_INVALID`；400 `CIRCLE_ARCHIVED` |
| POST | `/circles/:slug/leave` | 登录且 active 成员；owner 不可退出 | 401；404 `NOT_FOUND`（未加入）；403 `CIRCLE_OWNER_CANNOT_LEAVE` |
| GET | `/circles/:slug/members` | active 成员；owner / admin 额外收到 `pending` 待审名单 | 401；403 `FORBIDDEN`；404 |
| POST | `/circles/:slug/approve` | owner / admin；通过待审成员转 `active` | 401；403 `FORBIDDEN`；404（无待审成员） |
| POST | `/circles/:slug/reject` | owner / admin；待审成员置 `left` | 401；403 `FORBIDDEN`；404 |
| POST | `/circles/:slug/posts` | active 成员；`thread_id` 可空 | 401；403；404 |
| GET | `/circles/:slug/posts` | active 成员；动态流倒序 | 401；403；404 |
| POST | `/circles/:slug/notices` | owner / admin | 401；403；404 |
| GET | `/circles/:slug/notices` | active 成员；公告流倒序 | 401；403；404 |

### 关键行为约定
- **成员计数**：`pending / left` 不计入 `member_count`，也不进入正式成员名单；满员判定只统计 `active`。
- **重复加入**：已 `active` 幂等返回当前角色；已 `pending` 重复申请不重复入队；`left` 后重新加入按当前 `join_mode` 重新落位。
- **权限分层**：`owner / admin` 可审核、发公告；`member` 可发动态；动态流 / 公告流 / 名单要求 active 成员。
- **跨板块聚合**：`circle_posts.thread_id` 可回填既有板块帖 ID；圈子本身不反向写板块表。
- **归档**：`archived` 圈子只读展示，不可再加入 / 发声。

## 五、环境变量

| 变量 | 默认 | 说明 |
| --- | --- | --- |
| `MIM_CIRCLE_CREATE_MIN_LEVEL` | `0` | 创建圈子所需最低等级（等级口径与 growth 一致：积分每 300 一级、每 3 笔订单加一级，封顶 10）；`0` 不设门槛 |
| `MIM_CIRCLE_CREATE_MAX_PER_USER` | `1` | 每个用户可创建的 active 圈子数量上限 |
