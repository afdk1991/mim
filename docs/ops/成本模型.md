## 1. 成本结构总览

Mim 的成本形态由两个决策直接决定：

1. ADR-003：后端零框架、唯一依赖 `pg`、宿主机 systemd 直部署 → 无容器编排、无 PaaS 托管费。
2. ADR-004：本地磁盘替代对象存储 → 无对象存储与出网流量费。

| 成本项 | 是否发生 | 说明 |
| --- | --- | --- |
| 服务器（宿主机） | **发生** | systemd + nginx + PostgreSQL 全部是宿主机原生进程 |
| 带宽（出网） | **发生** | 静态资源 + API 响应 + 上传下载 |
| PostgreSQL 存储 | **发生** | 数据卷 + WAL + 备份（本地磁盘） |
| 对象存储 | **不发生** | 上传文件落本地磁盘 `server/data/uploads`（`server/src/storage.js` 明确不用 `bytea`） |
| 证书 | **不发生** | Let's Encrypt 免费；当前 nginx 配置只监听 80（`deploy/nginx-mim.conf`），TLS 终止尚未配置 |
| 域名 | **发生** | 生产用一个域名 |
| 容器/编排 | **不发生** | 全程无 Docker，且 CI 有禁容器闸门（`build.yml:41-77`） |
| 云函数 / Serverless | **不发生** | 旧流水线已废弃（`build.yml:3-5`） |
| 云音视频 / 转码 | **不发生** | ADR-006 明确 Phase 1 不自建、不采购 |
| 外部 API | 部分发生 | 前端直连的第三方接口（如天气、汇率等公开 API），多为免费档 |
| 监控 / APM SaaS | **不发生** | 无集中式 metrics 与 APM（见可观测性规范 OBS-1/OBS-2） |
| 外部拨测 | 免费档 | UptimeRobot 免费档（`deploy/README.md:505`） |
| GitHub（Actions / Pages / Releases） | 免费 | 公开仓标准 runner 免费；Releases 不计入 Packages 配额；Pages 免费 |
| 镜像仓（Gitee / gitcode / AtomGit / CNB） | 免费额度内 | 只读副本；注意 Gitee 500MB 仓容量墙 |

## 2. 单用户单月成本测算公式

### 2.1 模型假设（必须先声明）

| 符号 | 含义 | 假设值（示例） | 假设依据 |
| --- | --- | --- | --- |
| `U` | 月活用户数（MAU） | 10,000 | 示例规模，用于摊薄固定成本 |
| `S` | 服务器月成本（元/月） | 300 | 单台 2C4G 级别宿机含 IP 的常规价位区间 |
| `B` | 月出网总流量（GB） | 500 | 按人均 50MB/月估算 |
| `Pb` | 带宽单价（元/GB） | 0.5 | 国内常规按量带宽价位区间 |
| `D` | 数据库年增长（GB/年） | 20 | 业务数据 + WAL + 索引 |
| `Pd` | 存储单价（元/GB/月） | 0.3 | 云盘/附加盘价位区间 |
| `Ds` | 数据库基准容量（GB） | 50 | 系统与基础数据 |
| `F` | 域名月摊（元/月） | 5 | 年费 60 元摊薄 |
| `M` | 杂项月成本（元/月） | 50 | 备份异地存储、外部拨测超额、临时扩容等 |

**以上全部为估算假设，未与任何实际账单核对。**

### 2.2 公式

```text
固定成本（月）  = S + F + M
存储成本（月）  = (Ds + D × 已运行月数 / 12) × Pd
带宽成本（月）  = B × Pb
总成本（月）    = 固定成本 + 存储成本 + 带宽成本

单用户单月成本  = 总成本（月） / U
```

按人均表达（便于做敏感性分析）：

```text
人均成本（月） = (S + F + M) / U
              + ((Ds + D × 月数/12) × Pd) / U
              + (人均月流量 GB × Pb)
```

### 2.3 示例测算（U = 10,000，运行第 12 个月）

| 项 | 计算 | 结果（元/月） | 人均（元/用户/月） |
| --- | --- | --- | --- |
| 服务器 | S | 300.00 | 0.0300 |
| 域名 | F | 5.00 | 0.0005 |
| 杂项 | M | 50.00 | 0.0050 |
| 存储 | (50 + 20) × 0.3 | 21.00 | 0.0021 |
| 带宽 | 500 × 0.5 | 250.00 | 0.0250 |
| **合计** | | **626.00** | **0.0626** |

**结论（按上述假设）：单用户单月成本约 0.063 元（约 6 分钱）。**

### 2.4 敏感性分析（人均成本随 MAU 变化）

| MAU | 固定成本人均 | 存储人均 | 带宽人均 | 合计人均（元/月） |
| --- | --- | --- | --- | --- |
| 1,000 | 0.355 | 0.021 | 0.025 | 0.401 |
| 5,000 | 0.071 | 0.004 | 0.025 | 0.100 |
| 10,000 | 0.036 | 0.002 | 0.025 | 0.063 |
| 50,000 | 0.007 | 0.000 | 0.025 | 0.033 |
| 100,000 | 0.004 | 0.000 | 0.025 | 0.029 |

读法：固定成本随规模迅速摊薄，**带宽是唯一不随规模摊薄的人均成本项**（人均流量恒定时）。因此降本的主战场是带宽与人均流量。

### 2.5 成本结构占比（U = 10,000）

| 项 | 占比 |
| --- | --- |
| 服务器固定成本 | 47.9% |
| 带宽 | 39.9% |
| 存储 | 3.4% |
| 域名 + 杂项 | 8.8% |
| 对象存储 | 0% |
| 音视频/转码 | 0% |
| 监控 SaaS | 0% |

## 3. 各项成本的实况说明

### 3.1 服务器

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 形态 | 单台宿主机，systemd + nginx + PostgreSQL 原生进程 | `deploy/mim-server.service`、`deploy/nginx-mim.conf` |
| 实例数 | 1 | 单实例，无集群、无负载均衡（见 R-004） |
| 冗余 | 无 | 主机故障即全站不可用 |
| 扩缩容 | 手工 | 无自动扩缩（无容器、无编排） |
| 成本特征 | 固定 | 与用户量无关，直到需要第二台 |

### 3.2 带宽

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 主要来源 | 前端静态资源（JS/CSS/图片）、API 响应、上传下载 | — |
| 优化现状 | nginx 开启 gzip（`gzip_comp_level 6`），首屏体积约降到 1/3 | `deploy/nginx-mim.conf` |
| 缓存现状 | `/assets/` 长缓存 1 年 + immutable；`index.html` `no-cache` | `deploy/nginx-mim.conf` |
| 缺失 | 无 CDN | 静态资源全部由源站出，跨地域延迟与带宽成本由源站承担 |
| 上传 | 单文件上限 3MB（前端 / nginx / 后端三方对齐） | `storage.js`、`nginx-mim.conf` |
| 成本特征 | 随流量线性增长 | 唯一不摊薄的人均成本 |

### 3.3 PostgreSQL 存储

| 项 | 现状 | 说明 |
| --- | --- | --- |
| 位置 | 本机 127.0.0.1:5432 | `server/src/db.js:20` |
| 主要占用 | 业务表 + 索引 + WAL | 迁移文件里已用部分索引减少体积（如 `idx_devices_owner` 带 `where owner_id is not null`） |
| 刻意规避 | 上传文件不进 PG（`bytea` 会让表体积与 WAL 成倍膨胀） | `storage.js:1-7` |
| 备份 | 逻辑导出 `pg_dump` + gzip，本地保留 14 天 | `scripts/backup.sh`、`.env` 未含异地 |
| 缺失 | 无归档/分区策略；无 PITR（时间点恢复） | 只有全量逻辑备份 |
| 成本特征 | 随数据量缓慢增长 | 在总成本中占比小 |

### 3.4 对象存储

**当前为零。** 上传文件落 `<cwd>/data/uploads`（可由 `UPLOAD_DIR` 覆盖），由 nginx 直出。

| 项 | 说明 |
| --- | --- |
| 成本 | 0（占用宿主机磁盘，已含在服务器与存储成本中） |
| 风险 | 单机磁盘不满足多实例共享；将来多实例必须先换 S3/OSS |
| 迁移代价 | 低：`storage.js` 注明「换成 S3/OSS 时只需替换本文件的 put/get 两个函数」 |
| 触发条件 | 多实例部署 / 单机磁盘不足 / 需要 CDN 回源 |

### 3.5 证书与域名

| 项 | 现状 |
| --- | --- |
| 证书 | 当前 nginx 只 `listen 80`，**TLS 尚未配置**；生产必须补 Let's Encrypt（免费） |
| 域名 | 一个生产域名；`nginx-mim.conf` 的 `server_name _` 需在部署时替换 |
| 成本 | 域名年费摊薄，证书免费 |

### 3.6 明确不存在的成本（诚实声明）

| 项 | 状态 | 依据 |
| --- | --- | --- |
| 云音视频 | **无** | ADR-006：Phase 1 不自建、不采购 RTC PaaS |
| 转码 | **无** | 同上；无 FFmpeg 集群、无媒体处理流水线 |
| 容器编排 | **无** | 全程无 Docker，`build.yml` 有禁容器闸门 |
| PaaS 后端托管 | **无** | 自托管 systemd |
| 对象存储 | **无** | 本地磁盘 |
| 监控 SaaS | **无** | 无 metrics / APM / 告警系统 |
| Serverless | **无** | 旧流水线已废弃 |

## 4. 降本路径

### 4.1 当前可立即执行（零成本）

| 编号 | 措施 | 预期收益 | 依据 |
| --- | --- | --- | --- |
| C-1 | 收紧上传体积：3MB 上限已三方对齐，但对图片可进一步做前端压缩后再传 | 降低带宽与磁盘 | 现状未做前端压缩 |
| C-2 | 开启 nginx gzip（已开）并补充 `brotli`（需模块） | 进一步降带宽 | 当前仅 gzip |
| C-3 | 长缓存策略已生效（`/assets/` 1 年 + immutable），继续保证带 content-hash 的产物走长缓存 | 减少重复下载 | `nginx-mim.conf` |
| C-4 | 定期 `journalctl --vacuum-size` 与清旧备份 | 降磁盘 | `deploy/README.md:494` |
| C-5 | 上传目录清理 | 降磁盘 | `scripts/cleanup-images.sh` |
| C-6 | 索引优化（部分索引 / 表达式索引） | 降存储与 IO | `0008_iot_device.sql`、`0010_wallet_idempotency.sql` 已在用 |

### 4.2 中期（需投入，有明确收益）

| 编号 | 措施 | 收益 | 代价 / 前提 |
| --- | --- | --- | --- |
| C-7 | 引入 CDN 承载静态资源 | 带宽成本转移 + 跨地域延迟下降 | 新增成本项；需评估 CDN 单价与源站带宽单价的差额 |
| C-8 | 图片格式升级（WebP/AVIF）与响应式尺寸 | 带宽显著下降 | 需处理上传侧转换（会引入 CPU 消耗，见 ADR-006 §3.1 不做转码的边界） |
| C-9 | 静态资源与 API 分离域名 + 独立缓存策略 | 缓存命中率提升 | 配置复杂度上升 |
| C-10 | 数据库归档（冷数据移出主库） | 存储与备份时间下降 | 需先有归档策略与查询路径改造 |

### 4.3 明确不做（避免伪降本）

| 措施 | 不做的理由 |
| --- | --- |
| 迁到容器编排降本 | 本路线刻意不用容器，容器不降本只提复杂度 |
| 迁到 Serverless 按量计费 | 常驻流量下按量计费反而更贵，且已废弃该路线 |
| 换更便宜的单核机 | 单实例是既成事实，进一步降配会放大 R-004 的单点风险 |
| 砍监控省钱 | 当前监控支出为 0，问题不是贵而是没有（见可观测性规范） |

## 5. 成本相关的风险与触发条件

| 风险 | 触发信号 | 影响 | 关联 |
| --- | --- | --- | --- |
| 带宽突增（热内容 / 爬虫 / 盗链） | 出网流量环比翻倍 | 成本线性上升 | 当前无流量监控（OBS-1） |
| 单机磁盘被上传打满 | 磁盘可用 < 15% | 服务不可用 | 可观测性 AL-6 |
| 数据库无归档导致备份时间不可控 | 备份耗时显著增长 | 恢复 RTO 上升 | R-009 |
| 多实例改造被迫提前 | 单机 CPU/连接数瓶颈 | 对象存储与共享存储成本从 0 跳升 | R-004 |
