# 内容结构 + 专业工具面：两级分类 / 标签 / 作者卡 / 归档 / 站内检索（2026-11-25）

> 本批次只改代码并跑本地门禁，未提交、未部署、未建数据库备份。线上入口：前端 `https://zy.laal.top`，API `https://api.laal.top/api/v1`。

## 1. 已落地口径

- **两级分类**：一级 = 板块 `community_boards`；二级 = 帖子类型 `community_threads.kind`（text / video / gallery / series / qa / poll）。
- **标签**：作者发帖时自建，每帖 1–3 个，2–12 字，按归一化 slug 去重；列表 / 详情回带 `tags` 数组；`GET /community/tags` 按关联帖数倒序分页。
- **作者公开卡**：昵称、Mim ID（member_no）、等级、徽章数与徽章名、发帖数、累计获赞、加入时间；不公开收藏与关注。`GET /community/authors/:id` 匿名可读，不存在 / 已注销返回 404。
- **归档**：近 12 个月按自然月分组，每月计数 + 最近 3 条标题；不做无限回溯。
- **检索**：`GET /community/search?q=` 聚合板块、帖子（标题 / 摘要 / 正文片段，沿用既有 `buildSnippet` 高亮）、标签三组，返回各组命中总数。

## 2. 数据结构（`schema.d/86-community-tags.sql`，幂等增量）

- `community_tags(id, slug UNIQUE, name, status DEFAULT 'active' CHECK in ('active','hidden'), created_by, created_at)`
- `community_thread_tags(thread_id, tag_id, PRIMARY KEY(thread_id, tag_id))` + 标签维度、帖子维度两个索引。
- 迁移加载器在 `src/db.ts` 启动期自动枚举 `schema.d/*.sql` 升序执行，**无需在加载清单手动登记**；后续新增结构同样落 `schema.d/88-*.sql` 即可。

## 3. 本轮未做项与后续方案

### 3.1 标签后台治理（驳回 / 隐藏 / 合并）—— 后续批次

- 现状：新建标签一律 `active`；`status` 已预留 `hidden` 态，字典表与关系表结构可直接承接治理动作。
- 待补后台能力：
  1. 标签列表后台页（按关联帖数 / 创建时间排序，可见创建者）；
  2. 驳回 / 隐藏：`UPDATE community_tags SET status='hidden'`，隐藏后不出现在热门标签与检索分组，已挂载关系保留可回滚；
  3. 合并：把源标签关系行 `community_thread_tags.tag_id` 重写到目标标签（同事务、复合主键 `INSERT OR IGNORE` 防重复），源标签置 `hidden` 或软删；
  4. 治理动作写审计日志，沿用既有 RBAC 权限点口径。

### 3.2 Schema 后续变更方案

- **只做增量**：新表 / 新列 / 新索引一律写新的 `schema.d/<编号>-<主题>.sql`，`CREATE TABLE IF NOT EXISTS` / `CREATE INDEX IF NOT EXISTS`；不改写既有历史分片，不 DROP 既有列。
- **列扩容 / 冲突修复**：沿用 `db.ts` 里 `ensureIdentityUsernameProvider` 一类启动期幂等迁移函数的模式，检测旧结构后原地补齐，重复启动不重复生效。
- **标签合并若改主键口径**（例如 slug 规则变更）：关系表外键 `tag_id` 不变，只改字典行；需要历史回填时在启动期迁移里按新规则重算 slug 并写审计。
- **全文检索升级**：当前标题 / 摘要 / 正文仍走 `LIKE + 自研 BM25`；标签 / 板块分组是 `LIKE` 匹配。帖子量上来后再评估外置全文索引（见 `verify-indexes` 慢查询候选口径），本轮不引入新第三方依赖。
