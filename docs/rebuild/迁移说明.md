## 一、删除了什么，现在由什么替代

| 已删除目录 | 原本是干什么的 | 现在的替代 |
| --- | --- | --- |
| `supabase/` | 主后端：托管 Postgres + `schema.sql` 与 12 个 `migrations/*.sql`、RLS 策略、Deno Edge Function（`functions/mim-api/`）、人工补齐 SQL（`apply-all-manual.sql` 等） | **库结构** → `server/db/migrations/0001~0005*.sql` + `server/scripts/migrate.js`（幂等执行器）<br>**接口** → `server/src/rest.js`（通用 CRUD）+ `server/src/rpc.js`（服务端过程）<br>**鉴权** → `server/src/auth.js`<br>**对象存储** → `server/src/storage.js`（本地磁盘）<br>**RLS** → 应用层归属校验（`server/src/rest.js` 的 `owner` 注入与读策略 `public`/`owner`/`admin`） |
| `cloudfunctions/` | 备后端的云函数入口（`mim-api/index.js`） | 合并进 `server/src/main.js` 的路由分发 |
| `cloudbase/` | 备后端的迁移 SQL（5 个 `migrations/*.sql`，含 `mim_rls_rpc`、`mim_app_users`、`wallet_growth_mall`） | 迁移统一到 `server/db/migrations/`；RPC 统一到 `server/src/rpc.js` |
| `baas/` | 自托管 BaaS 编排实验：PostgREST + GoTrue + Envoy + Deno 函数 + Prometheus + 10 个 `db/migrations/*.sql` + Makefile | 完全被 `server/` 取代：一个 Node 进程 + 一个 Postgres，不再需要网关、网关配置、监控栈与多容器编排 |
| `worker/` | 空目录（无内容） | 无 |

同时作废的还有：

- 旧 CI 里的「数据库迁移 / 云函数部署 / 边缘函数」作业 —— 见 `.github/workflows/build.yml` 顶部注释。重建后的流水线只有 `verify`（typecheck + build）与 `deploy-pages` 两个作业。
- 一批依赖托管后端凭证的一次性脚本，已从文档与命令表中移除（不引用、不使用）。
- 前端侧的托管后端 SDK 与相关环境变量（`VITE_SUPABASE_*` 一类）全部删除，只剩 `VITE_MIM_API_BASE`。

## 三、行为差异（最容易踩的几点）

| 维度 | 旧架构 | 重建后 |
| --- | --- | --- |
| **鉴权** | 托管后端自带鉴权 + 第三方 JWT 库 | `server/src/auth.js` 自实现 **HMAC-SHA256** 自签令牌（`crypto`），不再引入 JWT 库 |
| **密码** | 托管 Auth 服务托管哈希 | `crypto.scrypt` 加盐哈希，哈希落在 `users.password_hash` |
| **登出** | 丢弃本地令牌，服务端令牌仍有效至过期 | 令牌带 `jti`，登出写入 `token_revocations`，**每次鉴权都查吊销表** |
| **金额单位** | `amount` 为**元**（`int`） | 一律 **`amount_fen`（分，`bigint`）**；前端字段带 `Fen` 后缀，展示走 `yuanText()`。历史库曾因两套单位并存导致退票金额错位 100 倍，新库**不保留任何「元」列、也不建兼容列** |
| **访问控制** | 数据库 RLS 策略 | 应用层归属校验：写操作强制注入 `owner`（客户端传的 `owner` 一律忽略）；读策略 `public` / `owner` / `admin`；`posts.visibility='self'` 对所有人（含管理员）隐藏 |
| **并发裁定** | plpgsql 函数 + 前端判断 | 集中在 `server/src/rpc.js`（Node 侧事务），**不在数据库层写 plpgsql** |
| **错误表达** | 多种（throw / null / undefined / toast 后继续） | 统一 `Result<T>` + `ErrCode`；后端统一 `{data}` / `{error:{code,message}}` |
| **缺列处理** | 整行写入被拒即失败 | 报 `code='schema'`，前端 `writeWithFallback` 自动剔除缺失列重试（上限 12 轮） |
| **未配置后端** | 依赖托管地址，缺省即不可用 | **前端完全可用**：数据落 localStorage，云端写回三态协议的 `skip`（不算错误） |
| **依赖数量** | 多个托管 SDK + 编排组件 | 后端依赖只有 **`pg`** |

## 四、数据怎么搬过来

新库是**空库起步**（不预置任何演示商品、示例文章或假数据）。要把旧库数据搬过来：

1. 从旧库导出 CSV / `COPY`。
2. **金额换算**：`amount_fen = round(amount * 100)`（旧 `amount` 是元）。
3. **合并订单三表**：`orders` + `order_items` + `payment_records` → `mall_orders`，行项目与支付信息序列化进 `ext`（JSONB）。
4. **钱包流水改名**：`wallet_txns` → `wallet_txs`。
5. **点赞表**：把 `post_likes` / `comment_likes` / `article_likes` / `snippet_likes` 的计数汇总回写到对应行的计数字段。
6. 导入后执行 `npm run server:migrate`（幂等，确保 `schema_migrations` 完整）。

> 没有旧数据要搬？直接 `npm run server:up && npm run server:migrate` 起步即可。

## 五、回滚

### 5.1 Git 锚点

```bash
git tag                                  # 应能看到 pre-rebuild-20261028-0126
git show pre-rebuild-20261028-0126 --stat
```

回到重建前的完整状态：

```bash
git checkout -b rollback-rebuild pre-rebuild-20261028-0126
```

或只读地看某个旧文件：

```bash
git show pre-rebuild-20261028-0126:package.json
```

不要整体 reset？可以先建分支保留工作区，确认无误再切换，避免丢失重建后的改动。

### 5.3 回滚的代价

- **代码**：可完整回滚（锚点在重建前的最后一次提交）。
- **数据库**：旧库是托管实例，不受本次重建影响；新库是本地 / 自建 Postgres，删掉 `pgdata` 卷即回到空库。
- **前端本地数据**：键名从历史混写（`mim-<域>-<uid>:<field>`）统一为点分结构（`mim.<scope>.<uid>.<field>`）。`src/core/storage.ts` 的 `migrateOnce` 会在首次读取时自动搬运旧键，**老用户数据不丢**；但**回滚到旧代码后**，新键不会被反向迁移回去。
