## 一、TanStack Query 单模块试点

### 1.1 现状与痛点

当前数据层是手写的 thin client（`src/data/client.ts`）+ 各页面自己管 loading / error /
空态，已经稳定，但随业务增长出现两类重复：

1. **同一资源多页面重复拉取**：`products` 列表在 `MallHomePage` / `MallGoodsPage` /
   `MallCartPage` 都各拉一次，没有缓存与去重。
2. **写入后手动失效**：商城订单、钱包流水、审核列表都是「写完手动 setState / emit」，
   跨页面同步靠 `EVT.mall` / `EVT.wallet` 事件总线，写一处要记得发事件、订阅方要记得重拉。

### 1.2 试点边界（单模块，不全局替换）

**第一个试点模块：商城商品目录（`products` REST）**。理由：

- 读多写少，最能体现缓存价值；
- 只有一个写入口（`AdminProductsPage`），失效逻辑简单；
- 不涉及钱包 / 订单等资金类强一致链路，风险低。

试点范围严格限定为：

- `MallHomePage` / `MallGoodsPage` / `MallCartPage` 的商品目录读取改走 `useQuery`；
- `AdminProductsPage` 的增删改走 `useMutation` + `queryClient.invalidateQueries(['products'])`；
- **不**替换 `db.rpc`（库存扣减 / 核销 / 退票等写过程仍走原 thin client，避免把资金类
  操作塞进 Query 的乐观更新语义）；
- **不**替换本地优先状态（`useMall()` / `useWallet()` / `useApp()` 的 Context 状态）。

### 1.3 落地点（照做即可）

```bash
npm i @tanstack/react-query
```

- 在 `src/app/providers.tsx` 的最外层包一个 `QueryClientProvider`，`staleTime: 30_000`，
  `retry: 1`（与 http.ts 的读重试对齐）。
- 新建 `src/data/queries/products.ts`：`useProductsQuery()` / `useProductQuery(id)` /
  `useProductMutation()`，内部仍调用 `db.list` / `db.insert` / `db.update` / `db.remove`，
  不绕过 http 层的鉴权与 Result 化。
- 迁移完成后跑一次对比：商品目录在三个页面间切换，Network 面板应只在首次和 invalidate
  后打请求。
- 试点稳定一个发版周期后，再评估钱包流水 / 通知中心是否接入。**禁止一步切全工程**。

### 1.4 不引入的理由（避免过度工程）

- Redux / Zustand：当前 Context + useReducer 已覆盖跨页面状态，没有状态穿透问题。
- SWR：与 TanStack Query 二选一即可，后者在 REST + RPC 混合场景的 query key 约定更明确。
- GraphQL：后端是自建 Node RPC，没有 schema 强需求。

## 二、Headless / 工具类可选引入清单

下列依赖都是「**等真的需要时再装**」，当前手写实现已够用，**不要因为它们流行就提前加**。

| 包 | 用途 | 当前是否已有等价实现 | 引入触发条件 |
| --- | --- | --- | --- |
| `clsx` | 条件 className 拼接 | `src/core/utils.ts` 的 `cx()` 已实现，且已被全工程使用 | 不引入，保持零依赖 |
| `tailwind-merge` | 冲突 className 智能合并 | 无 | 出现「组件库 + 自定义样式冲突」时再评估 |
| `radix-ui` (headless) | 无障碍 Modal / Tabs / Dropdown | `ui/basic.tsx` 手写 Modal / Tabs，已通过键盘焦点测试 | 出现「手写 Modal 焦点陷阱修不完」时再引入 |
| `@floating-ui/dom` | Tooltip / Popover 定位 | 无（当前没有 Tooltip） | 真要做图表 hover 提示时 |
| `react-hook-form` | 表单状态 / 校验 | 各页面手写受控 input + useState | 管理后台表单超过 3 个且校验规则趋同时 |
| `zod` | 运行时 schema 校验 | `core/result.ts` + 各 parse* 函数 | 后端返回结构漂移导致白屏出现 ≥2 次 |
| `date-fns` | 日期格式化 | `core/utils.ts` 的 `formatDate` / `TimeAgo` | 跨时区 / 相对日期文案变复杂 |

### 硬约束

1. 任何新依赖都必须先在本文件登记「触发条件」，触发后才允许进 `package.json`。
2. 引入前评估 bundle 体积：`npm run build` 前后 `dist/assets/index-*.js` 差异 ≤ 3KB
   才允许进核心路径；超过则放按需 chunk。
3. **不引入** UI 组件库（AntD / MUI / shadcn）——项目红线是「零第三方 UI 库、零 CSS 框架」。
