# Mim 重建工程 · 启动与配置说明

## 一、工程结构

```
mim/
├─ src/
│  ├─ main.tsx            入口（主题先行 → 挂载 React）
│  ├─ App.tsx             根组件：Provider 栈 + Shell + 路由分发
│  ├─ core/               基础设施：utils / storage / events / http / config / version / theme / result
│  ├─ data/               后端客户端：client / session / sync
│  ├─ domain/             领域纯逻辑：content / social / identity / commerce（含 biz四业务）/ growth / tools
│  ├─ app/                应用层：router / routes(45条) / nav / shell / providers / state(content·mall·wallet)
│  ├─ ui/                 组件库 + 主题变量化样式
│  ├─ features/           跨页面复用容器
│  └─ pages/              页面（按域分桶：content / social / commerce / tools / system）
├─ server/                自托管后端（Node 20 + pg，零额外依赖）
├─ scripts/               验证与工具脚本
└─ docs/rebuild/          重建文档（本文件所在目录）
```

**依赖方向单向**：`pages → app → domain → data → core`。页面不得直接 fetch，领域层不得引入 React。

## 二、前端启动

```bash
npm install
npm run dev          # http://localhost:5173
```

其他命令：

| 命令 | 作用 |
|---|---|
| `npm run typecheck` | TS 严格检查（0 错误才可提交） |
| `npm run build` | 生产构建到 `dist/` |
| `npm run preview` | 预览构建产物 |
| `npm run verify:routes` | 路由可达性回归（需先起 dev server） |

### 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `VITE_MIM_API_BASE` | 空 → 同源 `/api` | 后端地址。开发期 vite 会把 `/api`、`/auth`、`/storage` 代理到 `MIM_API_BASE`（默认 `http://127.0.0.1:8787`） |

未配置后端时前端**完全可用**（本地模式）：数据落 localStorage，云端写回自动跳过（`skip` 不算错误）。

## 三、后端启动

```bash
cd server
npm install
# 1) 起数据库
docker compose up -d           # 或自行准备 Postgres：createdb mim
# 2) 执行迁移
npm run migrate
# 3) 启动
npm run dev                    # 默认 http://127.0.0.1:8787
```

环境变量（`server/.env` 或 shell）：

| 变量 | 默认 | 说明 |
|---|---|---|
| `PORT` | `8787` | 监听端口 |
| `DATABASE_URL` | `postgres://postgres:postgres@127.0.0.1:5432/mim` | 数据库连接串 |
| `JWT_SECRET` | 开发用默认值 | **生产必须改为随机长字符串** |
| `STORAGE_DIR` | `server/.storage` | 上传文件落盘目录 |

健康检查：

```bash
curl http://127.0.0.1:8787/api/health
npm run server:health          # 仓库根目录，脚本化探测
```

### 后端路由契约

```
GET    /api/rest/:table[?select=&eq=col.val&order=col.asc&limit=]
POST   /api/rest/:table
PATCH  /api/rest/:table/:id
DELETE /api/rest/:table/:id
POST   /api/rpc/:fn
POST   /api/auth/register|login|logout
GET    /api/auth/me
POST   /api/storage/upload
```

响应统一 `{ data }`，错误统一 `{ error: { code, message } }`。错误码与前端 `src/core/result.ts` 的 `ErrCode` 一一对应。

## 四、首个管理员

新库没有任何管理员时：

1. 注册一个账号并登录
2. 访问 `#/admin`，页面会给出「👑 成为首个管理员」按钮（服务端校验全库无管理员才放行）
3. 之后在「角色管理」中授予他人 admin

## 五、数据迁移（从旧 Supabase 库）

旧库表结构与新库有差异（尤其订单金额由「元」改为「分」）。迁移前先导出、`amount * 100 → amount_fen` 后导入。旧 `supabase/` 目录已作为历史存档保留，不再参与构建。

## 六、部署

- **GitHub Pages**：推送 `main` 即触发 `.github/workflows/build.yml`，自动构建并部署。仓库 Settings → Pages → Source 选 `GitHub Actions`。
- **自托管**：`npm run build` 后把 `dist/` 交给任意静态服务器；把 `/api` 反代到后端进程即可（前端默认同源 `/api`）。

## 七、开发红线（改动前必读）

1. **金额一律「分」整数**，字段带 `Fen` 后缀；展示用 `yuanText()`。
2. **不伪造数据**：无真实来源时显示空态，禁止预置演示商品、随机点赞、假已读回执。
3. **不写死颜色**：只用 CSS 变量或既有类名。
4. **不新增第三方依赖**。
5. 提交前 `npm run typecheck` 必须 0 错误。
