# Mim 重建工程 · 启动说明

> 面向**第一次拿到这个仓库**的人。按顺序做完，你将得到：本机跑起来的前端（5173）+ 自托管后端（8787）+ 一个可用的管理员账号。
> 每一步的命令都可以直接复制执行。

---

## 〇、环境要求

| 依赖 | 版本 | 检查命令 | 用途 |
| --- | --- | --- | --- |
| Node.js | `>=20` | `node -v` | 前端构建与后端运行 |
| npm | 随 Node 附带 | `npm -v` | 依赖安装 |
| Docker + Docker Compose | 任意近期版本 | `docker -v`、`docker compose version` | 起 PostgreSQL 16（**只想跑前端可跳过**） |
| Git | 任意近期版本 | `git -v` | 拉取代码 |

逐平台安装步骤见 [`INSTALL.md`](../../INSTALL.md)。

**只想看前端效果？** 做完第一节就够了 —— 不配置后端时前端完全可用（数据落 localStorage，云端写回自动跳过）。

## 一、前端

```bash
git clone <你的仓库地址>
cd mim
npm install
npm run dev
```

预期输出：

```
  VITE v8.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

打开 <http://localhost:5173/> 。首页默认落在 `#/feed`（动态广场）。

自检项：

```bash
npm run typecheck     # TS 严格检查，必须 0 错误
npm run build         # 生产构建，产物在 dist/
```

### 指定后端地址（可选）

```bash
cp .env.example .env.local
# 编辑 .env.local：VITE_MIM_API_BASE=http://127.0.0.1:8787
npm run dev           # 改环境变量后需重启 dev server
```

留空即可 —— 开发期 `vite.config.ts` 会把 `/api`、`/auth`、`/storage` 代理到 `http://127.0.0.1:8787`，无需手工处理跨域。

## 二、后端

### 1) 安装后端依赖

```bash
npm run server:install
```

等价于 `npm --prefix server install`，只装一个依赖：`pg`。

### 2) 起 Postgres 16

**一键版**：

```bash
npm run server:up
```

等价于 `docker compose -f server/docker-compose.yml up -d`，会拉起：

- `mim-db`（`postgres:16-alpine`，宿主端口 `5432`）
- `mim-api`（Node 20，宿主端口 `8787`）
- `migrate`（一次性任务，跑完迁移即退出）

> `mim-api` 只等 `db` healthy，不等 `migrate` 完成，所以顺序不保证。建议用下面的分步版，或在 `up` 之后补跑一次迁移（迁移是幂等的，重复执行无害）。

**分步版（推荐，顺序可控）**：

```bash
docker compose -f server/docker-compose.yml up -d db     # 只起库
docker compose -f server/docker-compose.yml run --rm migrate
docker compose -f server/docker-compose.yml up -d api    # 再起服务
```

确认数据库就绪（等 `healthy`）：

```bash
docker ps --format 'table {{.Names}}\t{{.Status}}'
# 期望看到 mim-db 状态为 Up (healthy)
```

### 3) 执行数据库迁移

迁移文件在 `server/db/migrations/`，按文件名升序执行且**幂等**（可重复执行）。

**方式 A（推荐，容器内执行）**：

```bash
docker compose -f server/docker-compose.yml run --rm migrate
```

**方式 B（宿主 Node 执行）** —— 需要先给 shell 注入连接串：

```bash
# Linux / macOS / Git Bash
export DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/mim
npm run server:migrate

# Windows PowerShell
$env:DATABASE_URL = "postgres://postgres:postgres@127.0.0.1:5432/mim"
npm run server:migrate
```

预期输出（首次）：

```
[migrate] 应用 0001_iam.sql … ok
[migrate] 应用 0002_content.sql … ok
[migrate] 应用 0003_commerce.sql … ok
[migrate] 应用 0004_business.sql … ok
[migrate] 应用 0005_growth.sql … ok
```

再次执行会显示 `跳过（已应用）`，不会重复写数据。

### 4) 健康检查

```bash
npm run server:health
```

预期输出：

```
Mim 后端健康探测 → http://127.0.0.1:8787
  ✓ 健康检查：200 {"ok":true,"db":true,"service":"mim-server","uptime_ms":…,"rpcs":16}
  ✓ REST 商品列表：200 []

全部通过：后端可用
```

等价的手工验证：

```bash
curl http://127.0.0.1:8787/api/health
```

### 5) 想看实时日志 / 断点调试

不用容器里的 api，直接在宿主跑进程：

```bash
cd server
export DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/mim   # PowerShell: $env:DATABASE_URL = "..."
npm run dev
```

或在仓库根目录：`npm run server:dev`。

### 6) 停止

```bash
npm run server:down      # 停止并移除容器；pgdata / uploads 数据卷保留
npm run server:down -- -v   # 额外删除数据卷（会清空数据库，慎用）
```

## 三、创建首个管理员

全新库里没有任何管理员，管理后台会提示「当前账号不是管理员」。三个官方出口**都是一次性的**（库里已有管理员后失效）：

### 方式 A：后台页面自助（推荐）

1. 打开 <http://localhost:5173/#/login> ，注册一个账号并登录。
2. 访问 <http://localhost:5173/#/admin> 。
3. 页面出现「👑 成为首个管理员」按钮 —— 点击即可。
   - 它走 `db.rpc('bootstrap_admin')`（`src/app/admin-gate.tsx`），会带上登录令牌；服务端校验「全库无管理员」才放行。
4. 成功后自动刷新，侧栏出现「管理后台」入口。

### 方式 B：命令行授予

```bash
cd server
export DATABASE_URL=postgres://postgres:postgres@127.0.0.1:5432/mim
node scripts/promote-admin.js <你的用户名>
```

已有管理员时脚本会拒绝执行。

### 方式 C：环境变量预置

在 `server/.env` 里设置：

```
BOOTSTRAP_ADMIN_USERNAME=你的用户名
```

该账号下次登录或调用 `/auth/me` 时自动获得 `admin` 角色。

> 已有管理员后，给其他人授权请走后台 `#/admin/roles`（需要 `role:manage` 权限），**不要**直改 `user_roles` 表 —— 那会绕过审计。

## 四、常见问题

### 端口被占用

| 端口 | 占用者 | 处理 |
| --- | --- | --- |
| `5173` | vite dev server | 换端口：`npm run dev -- --port 5174` |
| `8787` | 后端 API | `docker compose -f server/docker-compose.yml down` 后改 `server/.env` 的 `PORT`；宿主进程用 `PORT=8788 npm run server:dev` |
| `5432` | Postgres | 改 `server/docker-compose.yml` 的 `PGPORT`（如 `5433:5432`），并同步 `DATABASE_URL` |

查占用进程：

```bash
# Windows PowerShell
netstat -ano | findstr :5173
# Linux / macOS
lsof -i :5173
```

### Postgres 起不来

```bash
docker logs mim-db              # 看具体报错
docker compose -f server/docker-compose.yml down -v   # 清掉数据卷重来（会丢数据）
npm run server:up
```

常见原因：

- 宿主 5432 已被另一个 Postgres 占用 → 改 `PGPORT`。
- 数据卷残留旧版本不兼容 → `down -v` 后重新 `up` + `migrate`。
- Docker Desktop 没启动 / WSL 后端未就绪 → `docker info` 确认。

### `health` 里 `db:false`

`/api/health` 仍返回 HTTP 200，表示进程活着但连不上库。检查 `DATABASE_URL`：

- 宿主进程连宿主映射端口：`127.0.0.1:5432`
- 容器内 `api` 服务：hostname 是 **`db`**，不是 `127.0.0.1`（`docker-compose.yml` 已写死为 `db:5432`）

### 页面报「线上数据结构尚未就绪」/ 未知列

说明库结构比迁移旧。处理：

```bash
npm run server:migrate                                  # 补齐迁移
docker compose -f server/docker-compose.yml restart api # 重启服务刷新列名缓存
```

前端 `src/data/sync.ts` 的 `writeWithFallback` 会自动剔除缺失列重试，所以迁移补齐前功能也不会崩，只是那几列不落库。

### 迁移报 `relation "xxx" does not exist`

迁移没跑全。回到第二节第 3 步重跑（幂等），然后重启 api。

### 上传报 400（超过 3MB）

`UPLOAD_MAX_BYTES` 与前端 `LIMITS.uploadMaxBytes` 都是 3MB。要放大必须**两边同时改**。

### 管理后台按钮点了没反应 / 提示未登录

`bootstrap_admin` 需要登录令牌。确认已登录（`#/login`），且库里还没有管理员。已有管理员时用后台 `#/admin/roles` 授权。

### 登出后令牌还能用？

不会。令牌带 `jti`，登出写入 `token_revocations`，每次鉴权都会查一次吊销表。

## 五、开发红线（改动前必读）

1. **金额一律「分」整数**，字段带 `Fen` 后缀；展示用 `yuanText()`。
2. **不伪造数据**：无真实来源时显示空态，禁止预置演示商品、随机点赞、假已读回执。
3. **不写死颜色**：只用 `src/ui/styles/theme.css` 的主题变量。
4. **分层单向依赖**：`pages / ui → app → domain → data → core`，反向禁止。
5. **不新增第三方依赖**（后端只允许 `pg`）。
6. 提交前 `npm run typecheck` 必须 0 错误。

完整规则见 [`README.md`](../../README.md) 第三节与 [`页面实现规范.md`](页面实现规范.md)。
