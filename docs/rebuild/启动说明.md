# Mim 重建工程 · 启动说明

> 面向**第一次拿到这个仓库**的人。按顺序做完，你将得到：本机跑起来的前端（5173）+ 自托管后端（8787）+ 一个可用的管理员账号。
> 每一步的命令都可以直接复制执行。

## 一、前端

```bash
git clone <你的仓库地址>
cd mim
npm install
npm run dev
```

预期输出：

```
  VITE v8.x  ready in xxx ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose
```

打开 <http://localhost:5173/> 。首页默认落在 `#/feed`（动态广场）。

自检项：

```bash
npm run typecheck     # TS 严格检查，必须 0 错误
npm run build         # 生产构建，产物在 dist/
npm test              # vitest 单元测试（vitest run，一次性跑完退出）
npm run server:check  # 后端语法体检：对 server/src 各模块与 scripts 逐个 node --check
```

> 根 `package.json` 全部 scripts：`dev` / `build` / `preview` / `typecheck` / `test` / `server:install` / `server:dev` / `server:start` / `server:migrate` / `server:check` / `server:health` / `verify:routes` / `verify:backend` / `version:check` / `native:sync` / `native:android` / `native:ios`。

### 指定后端地址（可选）

```bash
cp .env.example .env.local
# 编辑 .env.local：VITE_MIM_API_BASE=http://127.0.0.1:8787
npm run dev           # 改环境变量后需重启 dev server
```

留空即可 —— 开发期 `vite.config.ts` 会把 `/api`、`/auth`、`/storage` 代理到 `http://127.0.0.1:8787`，无需手工处理跨域。

## 二、后端

### 1) 安装后端依赖

```bash
npm run server:install
```

等价于 `npm --prefix server install`，只装一个依赖：`pg`。

### 2) 安装 PostgreSQL 并创建一个空库

Debian / Ubuntu：

```bash
sudo apt-get update
sudo apt-get install -y postgresql
sudo systemctl enable --now postgresql          # enable = 开机自启，--now = 立即启动
systemctl status postgresql                     # 期望 active (running)
```

macOS：`brew install postgresql@16 && brew services start postgresql@16`
Windows（PowerShell）：`winget install PostgreSQL.PostgreSQL.16`
RHEL 系：`sudo dnf install -y postgresql-server && sudo postgresql-setup --initdb && sudo systemctl enable --now postgresql`

库本身建议用仓库里的幂等脚本创建（建账号 + 建库，已存在就跳过、不动数据）：

```bash
PGUSER=mim PGPASSWORD='换成你的密码' PGDATABASE=mim ./deploy/init-db.sh
```

它会打印出对应的连接串，形如：

```
DATABASE_URL=postgres://mim:<口令>@127.0.0.1:5432/mim
```

> 口令通过 `PGPASSWORD` 传，`psql` 内部用变量做转义，特殊字符不会打断脚本。
> 忘了口令没关系 —— **重新跑一次同一个脚本即可重置口令**，不会删库。

已经能连上库就没问题了：

```bash
sudo -u postgres psql -c 'select version();'
```

### 3) 写配置并执行数据库迁移

```bash
cp server/.env.example server/.env
vi server/.env                 # 至少填 DATABASE_URL 与 JWT_SECRET
```

必改两项：

| 变量 | 填什么 |
| --- | --- |
| `DATABASE_URL` | `init-db.sh` 打印出来的连接串，例如 `postgres://mim:换成你的密码@127.0.0.1:5432/mim` |
| `JWT_SECRET` | `openssl rand -hex 32` 的生成结果（生产**必须**替换默认值） |

然后跑迁移（文件在 `server/db/migrations/`，按文件名升序执行且**幂等**，可重复执行）：

```bash
npm run server:migrate
```

预期输出（首次）：

```
[migrate] 应用 0001_iam.sql … 完成
[migrate] 应用 0002_content.sql … 完成
[migrate] 应用 0003_commerce.sql … 完成
[migrate] 应用 0004_business.sql … 完成
[migrate] 应用 0005_growth.sql … 完成
[migrate] 应用 0006_sync.sql … 完成
[migrate] 当前已应用 6 个迁移：0001_iam.sql, 0002_content.sql, 0003_commerce.sql, 0004_business.sql, 0005_growth.sql, 0006_sync.sql
```

再次执行会显示 `跳过（已应用）`，不会重复写数据。迁移清单与各文件作用见 [`迁移说明.md`](迁移说明.md)。

想给 shell 临时注入连接串（不想改 `.env` 时）：

```bash
# Linux / macOS / Git Bash
export DATABASE_URL=postgres://mim:换成你的密码@127.0.0.1:5432/mim
npm run server:migrate

# Windows PowerShell
$env:DATABASE_URL = "postgres://mim:换成你的密码@127.0.0.1:5432/mim"
npm run server:migrate
```

### 4) 启动后端

后端是宿主机上一个普通的 Node 进程，前台跑便于看日志与断点调试：

```bash
npm run server:dev             # 等价于 cd server && node src/main.js，默认 127.0.0.1:8787
```

需要临时改端口或连接串时，直接在命令前加环境变量：

```bash
PORT=8788 npm run server:dev
```

预期输出末尾类似：

```
[mim] 自托管后端已启动：http://127.0.0.1:8787/api/health
[mim] REST 表 35 张，RPC 19 个，上传目录 data/uploads
```

（REST 表数与 RPC 数以你本机后端实际打印为准；`RPC 19 个` 对应 `server/src/rpc.js` 当前注册表。）

停服：在跑进程的终端按 `Ctrl+C`（后端注册了 SIGTERM/SIGINT 处理器，会先关连接池再退出）。

> 生产不要靠终端常驻：用 systemd 单元 `deploy/mim-server.service` 守护，
> `Restart=always` 负责崩溃自动重启，`systemctl enable` 负责开机自启。详见 [`deploy/README.md`](../../deploy/README.md)。

### 5) 健康检查

```bash
npm run server:health
```

预期输出：

```
Mim 后端健康探测 → http://127.0.0.1:8787
  ✓ 健康检查：200 {"ok":true,"db":true,"service":"mim-server","uptime_ms":…,"rpcs":19}
  ✓ REST 商品列表：200 []

全部通过：后端可用
```

（`rpcs` 是 `/api/health` 动态返回的当前注册表函数数，随 `server/src/rpc.js` 增删而变化，不是固定常量。）

等价的手工验证：

```bash
curl http://127.0.0.1:8787/api/health
```

### 6) 停止与重启

本机开发：在跑进程的终端 `Ctrl+C` 即可。

服务器上（systemd 守护）：

```bash
sudo systemctl status  mim-server
sudo systemctl stop    mim-server
sudo systemctl restart mim-server      # 改了 server/.env 或拉了新代码之后
sudo systemctl disable --now mim-server  # 停服并取消开机自启
sudo journalctl -u mim-server -f       # 实时日志
```

注意 **`start` 不等于 `enable`**：只 `start` 的服务，机器重启后不会自己起来。

## 三、创建首个管理员

全新库里没有任何管理员，管理后台会提示「当前账号不是管理员」。三个官方出口**都是一次性的**（库里已有管理员后失效）：

### 方式 A：后台页面自助（推荐）

1. 打开 <http://localhost:5173/#/login> ，注册一个账号并登录。
2. 访问 <http://localhost:5173/#/admin> 。
3. 页面出现「👑 成为首个管理员」按钮 —— 点击即可。
   - 它走 `db.rpc('bootstrap_admin')`（`src/app/admin-gate.tsx`），会带上登录令牌；服务端校验「全库无管理员」才放行。
4. 成功后自动刷新，侧栏出现「管理后台」入口。

### 方式 B：命令行授予

```bash
cd server
export DATABASE_URL=postgres://mim:换成你的密码@127.0.0.1:5432/mim
node scripts/promote-admin.js <你的用户名>
```

已有管理员时脚本会拒绝执行。

### 方式 C：环境变量预置

在 `server/.env` 里设置：

```
BOOTSTRAP_ADMIN_USERNAME=你的用户名
```

该账号下次登录或调用 `/auth/me` 时自动获得 `admin` 角色。

> 已有管理员后，给其他人授权请走后台 `#/admin/roles`（需要 `role:manage` 权限），**不要**直改 `user_roles` 表 —— 那会绕过审计。

## 四、常见问题

### 端口被占用

| 端口 | 占用者 | 处理 |
| --- | --- | --- |
| `5173` | vite dev server | 换端口：`npm run dev -- --port 5174` |
| `8787` | 后端 API | 临时绕开：`PORT=8788 npm run server:dev`；长期改 `server/.env` 的 `PORT`（**同时同步 nginx 的 `proxy_pass`**，否则 502） |
| `5432` | PostgreSQL | 机器上已有另一个 PostgreSQL 实例时，改本机实例的端口：编辑 `/etc/postgresql/<版本>/main/postgresql.conf` 的 `port = 5433`，`sudo systemctl restart postgresql`，并同步 `DATABASE_URL` |

查占用进程：

```bash
# Windows PowerShell
netstat -ano | findstr :5173
# Linux / macOS
lsof -i :5173
```

### PostgreSQL 服务没起来

```bash
systemctl status postgresql              # 先看状态，期望 active (running)
sudo systemctl start postgresql          # 只是这一次没起
sudo systemctl enable --now postgresql   # 顺便把开机自启也配上
sudo journalctl -u postgresql -n 50      # 起不来时看具体报错
```

常见原因：

- 服务压根没 enable/start → 上面两条命令解决。
- 本机 5432 已被另一个 PostgreSQL 占用 → 改端口，见上一节。
- 数据目录在上次非正常关机后有残留锁 → 看 `journalctl` 里的报错，通常 `pg_ctlcluster <版本> main restart` 可恢复。
- macOS 用 Homebrew 装的 → `brew services restart postgresql@16`（不是 systemctl）。
- Windows → 用 Windows 服务管理：`Get-Service -Name postgresql*` 看状态，`Start-Service` 启动。

> 忘了 `init-db.sh` 里设的口令不用慌：重跑一次
> `PGUSER=mim PGPASSWORD='新口令' PGDATABASE=mim ./deploy/init-db.sh` 即可重置，
> 它只改角色口令，**不会删库、不会动已有数据**。

### `health` 里 `db:false`

`/api/health` 仍返回 HTTP 200，表示进程活着但连不上库。检查 `DATABASE_URL`：

- 宿主机上 PostgreSQL 与后端同一台机器，**hostname 就是 `127.0.0.1`**，端口 `5432`。
- 连接串里的账号口令要与 `init-db.sh` 创建的一致（`postgres://<账号>:<口令>@127.0.0.1:5432/<库名>`）。
- 连不上时先看 PostgreSQL 有没有在跑：`systemctl status postgresql`。
- 若报 `password authentication failed`，重跑 `init-db.sh` 重置口令（不删库）。

### 想彻底重来（清库重建）

```bash
# ⚠️ 会清空 mim 库的所有数据，仅在本机/全新环境使用
sudo -u postgres psql -c 'DROP DATABASE IF EXISTS mim;'
PGUSER=mim PGPASSWORD='换成你的密码' PGDATABASE=mim ./deploy/init-db.sh
npm run server:migrate
```

上传的文件在另一处，一起清的话删 `/opt/mim/server/data/uploads`（开发机上是 `server/data/uploads`）。

### 页面报「线上数据结构尚未就绪」/ 未知列

说明库结构比迁移旧。处理：

```bash
npm run server:migrate      # 补齐迁移
# 本机：Ctrl+C 停掉再 npm run server:dev
# 服务器：sudo systemctl restart mim-server
```

列名缓存在进程内，迁移后**必须重启后端**才会重新读取 `information_schema`。

前端 `src/data/sync.ts` 的 `writeWithFallback` 会自动剔除缺失列重试，所以迁移补齐前功能也不会崩，只是那几列不落库。

### 迁移报 `relation "xxx" does not exist`

迁移没跑全。回到第二节第 3 步重跑（幂等），然后重启后端刷新列名缓存。

### 上传报 400（超过 3MB）

`UPLOAD_MAX_BYTES` 与前端 `LIMITS.uploadMaxBytes` 都是 3MB。要放大必须**两边同时改**。

### 管理后台按钮点了没反应 / 提示未登录

`bootstrap_admin` 需要登录令牌。确认已登录（`#/login`），且库里还没有管理员。已有管理员时用后台 `#/admin/roles` 授权。

### 登出后令牌还能用？

不会。令牌带 `jti`，登出写入 `token_revocations`，每次鉴权都会查一次吊销表。

## 五、开发红线（改动前必读）

1. **金额一律「分」整数**，字段带 `Fen` 后缀；展示用 `yuanText()`。
2. **不伪造数据**：无真实来源时显示空态，禁止预置演示商品、随机点赞、假已读回执。
3. **不写死颜色**：只用 `src/ui/styles/theme.css` 的主题变量。
4. **分层单向依赖**：`pages / ui → app → domain → data → core`，反向禁止。
5. **不新增第三方依赖**（后端只允许 `pg`）。
6. 提交前 `npm run typecheck` 必须 0 错误。

完整规则见 [`README.md`](../../README.md) 第三节与 [`页面实现规范.md`](页面实现规范.md)。
