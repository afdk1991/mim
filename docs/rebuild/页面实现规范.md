# Mim 重建 · 页面实现规范（所有页面开发必须遵守）

> 本文件是并行开发期间的**契约基线**。任何页面实现前先读这里，避免风格漂移与类型不匹配。

## 一、分层与依赖方向

```
pages/  页面（薄层：组装 + 渲染）      ← 你可以改这里
  ↓
app/    状态与路由（useApp / useMall / useRouter）
  ↓
domain/ 领域模型与纯规则（无 React）
  ↓
data/   后端客户端与同步
  ↓
core/   基础设施（utils / storage / http / config）
```

**禁止**：pages 直接 `fetch`；pages 直接读写 localStorage（用 core/storage）；domain 引入 React。

## 二、路径别名

- `@/ui` → 组件库
- `@/core/xxx`、`@/domain/xxx`、`@/data/xxx`、`@/app/state/xxx`
- 页面内部相对导入用 `../../core/utils` 这类相对路径（现有代码即如此）

## 四、硬性红线

1. **金额一律「分」整数**，字段名带 `Fen` 后缀；展示用 `yuanText(fen)` 或 `<Money fen={x} />`。禁止浮点金额运算。
2. **不伪造数据**：无真实来源时显示空态 `<Empty emoji="📭" text="…"/>`。禁止预铺演示商品、随机点赞、假已读回执、假收益流水。
3. **不新增第三方依赖**（package.json 已定稿）。
4. **不改自己域之外的文件**。需要改共享层（core/domain/ui/app）时，在最终汇报里说明，由主控统一处理。
5. **不写死颜色**：只用 CSS 变量或既有类名（`.btn .btn-primary .card .tag .chip .badge .muted .page .section-title`）。
6. **组件内不直接调后端**：读取放 `useEffect`，错误/空态都要有分支。
7. 文件大小控制：单页 ≤ 400 行为宜，超出则拆子组件。

## 五、命名与风格

| 类别 | 规则 | 示例 |
|---|---|---|
| 页面文件 | PascalCase.tsx，与导出组件同名 | `FeedPage.tsx` → `export function FeedPage()` |
| 非组件模块 | kebab-case.ts | `site-config.ts` |
| 组件 | PascalCase | `PostCard` |
| hook | `use` + camelCase | `useMallGoods` |
| 常量 | UPPER_SNAKE | `PAGE_SIZE` |
| 类型 | `export interface` / `export type` | `interface FeedProps` |
| 导入类型 | 显式 `import type { X }` | 项目开了 `verbatimModuleSyntax` |

- 一律**具名导出**（`export function XxxPage()`），不允许 default export（App.tsx 除外）。
- 文件头写一段 `/* === */` 块注释，说明这个页面做什么、数据来自哪、有什么坑。
- 关键分支写中文注释解释「为什么」，不写「做了什么」。

## 六、必须有的状态分支

每个页面至少处理四种状态：
- **加载中**：`<Skeleton rows={3} />` 或骨架卡片
- **空数据**：`<Empty emoji="…" text="…" />`（文案要具体，告诉用户下一步能做什么）
- **有数据**：正常渲染
- **错误/后端未就绪**：降级为空态并给一句说明，禁止白屏

## 七、验收标准

改完后在仓库根目录执行：
```bash
npx tsc --noEmit -p tsconfig.json
```
**必须为 0 错误**（项目开了 `strict` + `noUnusedLocals` + `noUnusedParameters` + `noImplicitReturns`）。

`npm run build` 也要通过。不要提交未通过检查的代码。
