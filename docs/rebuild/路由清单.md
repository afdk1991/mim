# Mim 重建 · 路由清单

> 唯一真源：`src/app/routes.tsx` 的 `resolveRoute(path, query)`。本表与该文件逐条对应，改路由请同时更新这里。
>
> 路由形态：**hash 路由**（`src/app/router.tsx`）。`location.hash` 去掉 `#` 后为 path，`?` 之后为查询串；默认落到 `#/feed`。

## 一、守卫说明

- **全站无路由级登录守卫**：除 `#/admin/*` 外，所有页面游客可直接访问。
- 需要按身份隔离的数据，由数据层按 uid 分 key 落在 localStorage（`mim.<scope>.<uid>.<field>`），不由路由拦截。
- `#/admin/*` 由 `src/app/admin-gate.tsx` 的 `AdminGate` 校验：

  | 层级 | 校验 |
  | --- | --- |
  | 登录 | `isSignedIn()` |
  | 角色 | `hasRole('admin')` |
  | 权限 | `hasPerm(perm)`（可选参数，见下表） |

- 未命中任何分支的路径 → `Empty` 空态「页面不存在，检查一下地址吧」。

---

## 二、路由总表

**共 55 条**（本表行数 = `resolveRoute` 的全部可达路由形态）。计数口径：

- 商城 5 个频道（`youxuan` / `gexm` / `mix` / `live` / `laal`）与 4 个业务会场（`seckill` / `local` / `live` / `travel`）各自独立成行；
- `#/mall/live`（频道）与 `#/mall/biz/live`（业务会场）是两条不同路由，都保留；
- 参数路由（`:id` / `:name` / `:slug` / `:draftId`）各算一条；
- `#/feed` 覆盖空 hash、`#/`、`#/feed` 三种写法，算一条。

> `src/app/routes.tsx` 头部注释写的「45 条」是另一种口径：文件里 `case` 行共 45 行（顶层 41 行，含 fall-through 的 `case undefined`；加上 `mall` 内层业务会场 switch 的 4 行）。去重后的路径根是 40 个。三种口径不矛盾，但**请以本表为准**——它逐条对应实际返回的页面组件。

## 三、新增页面的改动清单

新增一个页面必须同时改三处，否则会拿到 `undefined` 组件：

1. 在 `src/pages/<域>/` 下新建 `XxxPage.tsx`（**具名导出**，不写 `export default`）；
2. 在 `src/pages/<域>/index.ts` 桶文件里追加导出；
3. 在 `src/app/routes.tsx` 的 `resolveRoute` 里加分支，并从桶文件 import。

若需要侧栏入口，还要改 `src/app/nav.ts` 的 `NAV`（或 `ADMIN_NAV`）。

改完后跑一遍路由遍历实测：

```bash
npm run dev            # 另开一个终端保持运行
npm run verify:routes
```
