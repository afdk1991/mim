## 三、修了什么

### 3.1 `scripts/gen-ota-manifest.mjs`（Android manifest 生成脚本）

**问题**：原输出只有嵌套结构 `{version, android:{url, sha256}}`，前端 `src/ota.ts:108` 读的是顶层 `data.url`，导致 Android 端拿到的更新链接为空。

**改动**：抽出 `apkUrl` 变量，同时写顶层 `url` 字段与 `android.url`，双写兼容。

```diff
- const manifest = {
-   version,
-   android: {
-     url: `https://github.com/${REPO}/releases/download/${tag}/app-release.apk`,
-     sha256,
-   },
- }
+ const apkUrl = `https://github.com/${REPO}/releases/download/${tag}/app-release.apk`
+
+ const manifest = {
+   version,
+   // 顶层 url 兼容 src/ota.ts 的 WebView manifest 流程（读 data.url）；
+   // 嵌套 android.url/android.sha256 供原生 MimOta 插件 downloadAndInstall 使用。
+   url: apkUrl,
+   android: {
+     url: apkUrl,
+     sha256,
+   },
+ }
```

### 3.2 `scripts/gen-tauri-updater-manifest.mjs`（新增）

**问题**：Tauri updater endpoint 配了 `latest.json`，但 tauri-action 只上传 `.sig` 签名文件，从不生成 `latest.json`。客户端请求必然 404，桌面端 OTA 完全不可用。

**改动**：新增脚本，输入 `.sig` 文件目录，自动：
1. 遍历所有 `.sig` 文件
2. 按文件名推断 Tauri 平台 key（`windows-x86_64` / `darwin-aarch64` / `darwin-x86_64` / `linux-x86_64`）
3. 同平台多产物时优先选 NSIS（Windows）或 `.app.tar.gz`（macOS）
4. 读取 `.sig` 内容作为 `signature`
5. 按 Tauri v1 规范输出 `{version, notes, pub_date, platforms}` 到 `./latest.json`

### 3.3 `.github/workflows/build-release.yml`（android job 末尾追加两步）

**位置**：`android` job 内，"上传 APK 与 manifest 至 Release" 之后，`ios` job 之前。

**改动**：追加两个 step：
1. **下载桌面端 updater 签名产物**：`gh release download --pattern '*.sig'` 到临时目录
2. **生成 Tauri updater latest.json 并上传**：
   - 若目录无 `.sig`（桌面端未配签名）→ warning 并 `exit 0`，不阻断 android job
   - 否则跑 `gen-tauri-updater-manifest.mjs` 生成 `latest.json`
   - `gh release upload latest.json --clobber` 回传 Release

```yaml
- name: 下载桌面端 updater 签名产物（.sig）
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    mkdir -p "$RUNNER_TEMP/release-sigs"
    gh release download "$GITHUB_REF_NAME" \
      --repo "$GITHUB_REPOSITORY" \
      --pattern '*.sig' \
      --dir "$RUNNER_TEMP/release-sigs" \
      --clobber || echo "::warning::Release 暂无 .sig 产物"
    ls -lh "$RUNNER_TEMP/release-sigs" || true

- name: 生成 Tauri updater latest.json 并上传
  env:
    GH_TOKEN: ${{ secrets.GITHUB_TOKEN }}
  run: |
    set -e
    SIG_DIR="$RUNNER_TEMP/release-sigs"
    if ! ls "$SIG_DIR"/*.sig >/dev/null 2>&1; then
      echo "::warning::Release 上没有 .sig 文件，跳过 latest.json 生成"
      exit 0
    fi
    SRC_VER=$(node -e "...读 APP_VERSION...")
    node scripts/gen-tauri-updater-manifest.mjs "$SRC_VER" "$GITHUB_REF_NAME" "$SIG_DIR"
    gh release upload "$GITHUB_REF_NAME" latest.json --clobber --repo "$GITHUB_REPOSITORY"
```

**为什么放在 android job 而不是单独新 job**：
- android job 已 `needs: desktop`，天然等齐三平台构建完成
- 不新增 job 数，改动最小
- android job 在 ubuntu-latest，`gh release download/upload` 跨平台通用

## 四、发版后用户在客户端点"立即更新"时发生什么

### 4.1 桌面端（Windows / macOS / Linux）

前提：`TAURI_SIGNING_PRIVATE_KEY_B64` secret 已配置（否则 tauri 不产 .sig，latest.json 不会生成）。

1. 应用启动后，Tauri updater 插件后台发 GET 请求：
   `https://github.com/afdk1991/mim/releases/latest/download/latest.json`
2. 拿到 JSON，读 `version` 字段与本地 `APP_VERSION` 做 semver 比较
3. 远端版本更高 → Tauri 弹出原生更新对话框，显示 `notes` 和"立即更新"按钮
4. 用户点"立即更新"：
   - 插件根据当前 OS 架构选 `platforms.windows-x86_64` / `darwin-aarch64` / ...
   - 下载 `platforms.<os>.url` 指向的 `.nsis.zip`（Windows）或 `.app.tar.gz`（macOS）
   - 用 `tauri.conf.json` 里的 pubkey 验证下载包对应的 `signature`
   - 验签通过 → 静默替换安装 → 提示重启
5. 验签失败 / 网络失败 → 插件降级为"打开 Release 页面"或静默失败，不崩应用

### 4.2 Android 端

前提：`VITE_OTA_MANIFEST` 构建期注入指向 `https://github.com/afdk1991/mim/releases/latest/download/manifest.json`。

1. 应用启动，React 组件挂载时 `useOta()` 触发 `checkOta()`
2. 检测 `window.Capacitor.Plugins.MimOta.check` —— **当前不存在**，跳过原生分支
3. 直接 `fetch(VITE_OTA_MANIFEST)` 拿到 `manifest.json`：
   ```json
   {
     "version": "1.0.0",
     "url": "https://github.com/.../download/V1.0.0/app-release.apk",
     "android": { "url": "...", "sha256": "..." }
   }
   ```
4. 比较 `data.version` 与本地 `APP_VERSION`，有更新则 `hasUpdate=true`
5. 顶部出现 `OtaBanner`：🚀 发现新版本 V1.0.0 + [更新] 按钮
6. 用户点"更新" → `getPlatform().ui.openExternal(info.url)` 调起系统浏览器下载 APK
7. 用户手动点击下载完成的 APK，走系统安装器覆盖安装

> **当前未做的事**：MimOtaPlugin.downloadAndInstall() 已实现"下载 + SHA256 校验 + 自动调起安装器"，但前端 `ota.ts` 没有调用它，也没有 `check()` 方法。要实现真正的 Android 端一键静默更新（不跳浏览器），需要：
> - Java 侧补 `@PluginMethod check()` 方法（读 manifest 比较版本返回 hasUpdate/url/sha256）
> - 前端 `OtaBanner` 的 `go()` 改为调 `MimOta.canInstall → requestInstallPermission → downloadAndInstall({url, sha256})`
>
> 这属于前端 UX 增强，不在本次"发版链路是否通"的修复范围内，已记录为后续待办。
