## 3. 跨站 SSO

### 端点（挂 `/api/v1`）

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/sso/ticket` | 需登录 | 登录态签发一次性 SSO 票据（5 分钟有效） |
| POST | `/auth/sso/exchange` | **公开**（票据本身承担鉴权） | 他站凭票据换取正式会话；访客账号拒绝兑换 |
| POST | `/auth/sso/logout` | 需登录 | 签发登出广播签名载荷（60 秒有效，stateless 不落库） |

### 安全约定

- 票据 / 广播载荷格式：`base64url(payload).base64url(HMAC-SHA256)`，密钥取 `MIM_SSO_SECRET`，缺省回退 JWT 密钥（仅开发态）；
- 票据落库只存 `sha256` 摘要；兑换用条件 `UPDATE ... SET consumed_at` 保证一次性消费，重放返回 `401 AUTH_SSO_TICKET_INVALID`；
- 站点必须命中 `MIM_SSO_ALLOWED_SITES` 白名单；签发与兑换各判一次（签发后收紧也拒绝）；票据站点与回传站点不一致返回 `403 AUTH_SSO_SITE_FORBIDDEN`；
- 兑换出会话必须是正式用户：`is_guest=1` 的访客账号票据直接拒绝，不与访客会话混用；
- 会话响应与普通登录同一契约（`finishLogin`：双令牌 + 用户视图）。

## 4. 实名审核（人工）

### 端点

| 方法 | 路径 | 鉴权 | 说明 |
| --- | --- | --- | --- |
| POST | `/auth/realname/submit` | 需登录 | 提交姓名 + 证件号；明文仅本次请求内存存在 |
| GET | `/auth/realname/status` | 需登录 | 查询本人脱敏视图 |
| GET | `/admin/realname/queue` | `user:read` | 待审队列（先到先审） |
| POST | `/admin/realname/:id/review` | `rbac:write` | 通过 / 驳回；驳回必须带原因 |

### 脱敏约定（合规硬约束）

- 姓名、证件号只存 **HMAC-SHA256 摘要**；姓名另存脱敏展示名（如 `张**`），证件号只存后四位；
- 表内不存在可还原的明文姓名 / 证件号列；对外视图只回显脱敏名、后四位、状态、通道、驳回原因；
- 未接第三方核验服务时 `provider='manual'`，全部进人工队列；`MIM_REALNAME_PROVIDER=third_party` 预留第三方通道。

### 状态机

`pending → approved` / `pending → rejected`；驳回后允许重新提交（同行回到 `pending`，清空旧结论）；已通过 / 待审不可重复提交（`409 REALNAME_ALREADY_SUBMITTED`）。

## 5. 邀请码注册门槛

### 开关与拦截

- `MIM_REGISTER_INVITE_REQUIRED=1` 开启门槛；**缺省 / 其他值一律关闭**，0.0.6 已上线注册行为不变；
- 拦截路径：`POST /auth/register`、验证码 `POST /auth/login` 首登建号（既有身份登录不受影响）；
- 错误码：`AUTH_INVITE_REQUIRED`（403 缺码）、`AUTH_INVITE_INVALID`（400 不存在 / 禁用 / 绑定不匹配 / 耗尽）、`AUTH_INVITE_EXPIRED`（400 已过期）。

### 管理端点（`createInviteAdminRouter`）

| 方法 | 路径 | 权限 | 说明 |
| --- | --- | --- | --- |
| POST | `/admin/invites` | `rbac:write` | 生成一枚或批量生成（上限 100），可设次数 / 有效期天数 / 绑定标识 / 备注 |
| GET | `/admin/invites` | `user:read` | 列表 + 汇总统计（总数 / 活跃 / 已核销） |
| GET | `/admin/invites/redemptions` | `user:read` | 核销记录，可按 `?code=` 过滤 |
| PATCH | `/admin/invites/:code/disable` | `rbac:write` | 禁用邀请码（幂等） |

### 并发语义

核销与建号在**同一事务**内完成；条件 `UPDATE` 守卫 `status='active' AND used_count < max_uses AND 未过期`，命中行数为 1 才写核销记录；任一失败整体回滚，并发下不超发，用尽自动置 `exhausted`。

## 7. 挂载建议（主控统一挂载，本包不动 `app.ts`）

三个工厂在 `app.ts` 装配阶段挂载到 `/api/v1`：

```ts
app.use('/api/v1', createSsoRouter(deps));
app.use('/api/v1', createRealnameRouter(deps));
app.use('/api/v1', createInviteAdminRouter(deps));
```

- **必须在全局 `requireAuth` 兜底之前挂载**：唯一公开端点是 `POST /auth/sso/exchange`（票据鉴权，不走登录态）；
- 其余端点鉴权由路由内部中间件完成：`/auth/sso/ticket`、`/auth/sso/logout`、`/auth/realname/submit`、`/auth/realname/status` 走 `requireAuth`；管理端点走 `requirePermission`；
- 权限点复用既有 `user:read`（队列 / 记录 / 统计读）与 `rbac:write`（生成 / 禁用 / 审核写），未新增 RBAC 权限点（未改 `db.ts`）。
