## 1. 配网状态机（端侧实现基准，两端必须一致）

```
待配网 ──扫描发现──▶ BLE已连接 ──MTU协商+鉴权──▶ 凭证已下发 ──设备联网──▶ 已激活
   ▲                  │失败                │失败              │失败/超时
   └──────────────可回退（任意失败可回到待配网，重试 ≤3 次，之后给人工客服入口）
```

| 状态 | 端侧行为 | 超时 |
| --- | --- | --- |
| 待配网 | 扫描广播（Service UUID 过滤），rssi > -75 才展示 | 15s 未发现提示靠近设备 |
| BLE已连接 | 协商 MTU（默认 185，失败回退 23）；读设备信息 | 8s |
| 凭证已下发 | 写入 Wi-Fi SSID/密码 + 一次性配网 Token（服务端签发，01 号文 §2.1） | 每条写 3s |
| 设备联网中 | 等设备经 notify 上报联网结果；并行轮询激活接口 | 30s |
| 已激活 | 绑定确认，进设备首页 | — |

失败分类埋点 `device_bind_fail`：`fail_reason ∈ {scan_timeout, connect_fail, mtu_fail, write_fail, wifi_fail, activate_fail}`，带 `retry_count`——配网成功率口径 `device_bind_success / device_bind_start`（03 号文 §4.3）。

## 2. GATT 协议（proto_v1，与固件解耦——04 号文 §2）

| 项 | 约定 |
| --- | --- |
| Service UUID | `0000fff0-0000-1000-8000-00805f9b34fb`（广播携带） |
| Write Char | `fff1`：配网数据，JSON 分帧（MTU-3 为帧长），帧头 `proto_v1` |
| Notify Char | `fff2`：设备状态上报（联网进度/失败原因码） |
| 配网报文 | `{"ssid":"…","pwd":"…","token":"一次性配网Token","tz":"Asia/Shanghai"}` |
| 设备回报 | `{"stage":"wifi_connecting|wifi_ok|activated|fail","reason":"…"}` |

安全：配网 Token 一次性、5 分钟有效；BLE 通道不持久化 Wi-Fi 密码；设备激活后关闭配网广播。
