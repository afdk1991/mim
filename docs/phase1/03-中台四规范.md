# 中台四份种子规范（03 号文）

> 责任岗位：CTO（兼任中台 owner，Phase 1 不设专职中台岗）
> 版本：v1.0（M0 冻结版）
> 日期：2026-10-30
> 效力：本四件套是全端（小程序 / App / Web 后台 / 后端 / 固件）唯一的接口与数据口径依据。落地方式为「文档规范 + lint/CI 检查 + 代码评审」三件套，不建独立中台服务。

---

## 0. 总则

1. **规范先行**：任何 API、错误码、权限点、埋点事件，先登记本文档再开发；未登记的代码评审不予通过。
2. **变更流程**：规范变更走 ADR（见 00 号文第 5 节流水），评审通过后更新版本号并在周会广播。
3. **兼容纪律**：所有对外契约受 04 号文发版契约约束（向下兼容 2 个版本）。

## 规范一：API 设计规范

### 1.1 基础约定

| 项 | 约定 |
| --- | --- |
| 协议 | 全链路 HTTPS；设备长连接走 MQTT、媒体流走 RTC PaaS，不在本规范范围 |
| 格式 | JSON，UTF-8 |
| 时间 | ISO 8601 带毫秒（`2026-10-30T08:00:00.000+08:00`），存储统一 UTC |
| 金额 | 单位「分」，int64，禁止浮点 |
| 命名 | 字段名 snake_case；URL 路径 kebab-case |

### 1.2 URL 与版本

- 形式：`/api/{version}/{module}/{resource}[/{id}/{action}]`
- 示例：`POST /api/v1/devices/{device_id}/ota/check`
- 版本：URL 携带主版本（v1/v2），仅破坏性变更升主版本；资源用名词复数，动作用子路径动词。

### 1.3 鉴权

| 调用方 | 方式 |
| --- | --- |
| C 端（小程序 / App） | `Authorization: Bearer {access_token}`；access_token 2h，refresh_token 30 天滚动轮换 |
| Web 后台 | Bearer + 权限点服务端校验（见规范三）；敏感操作二次确认 |
| 设备 | 一机一密 Device-Token（激活时签发），走 MQTT 通道，不适用本规范 |
| 第三方回调（支付 / 审核结果） | 平台签名验签 + 回调 IP 白名单，不走 Token |

### 1.4 分页

- 统一 **cursor 分页**：请求 `?cursor=&limit=`，limit 默认 20，上限 100。
- 响应：`{ "list": [...], "next_cursor": "...", "has_more": true }`
- `next_cursor` 为**不透明字符串**（服务端编码的复合游标）：客户端不得解析、不得自行构造；空结果原样回传入参 cursor；末页返回空串。
- 例外：Web 后台运营表格允许 `page/page_size` 风格（跳页需求），但同一模块两种风格不混用。

### 1.5 幂等

- 所有 POST 写操作支持请求头 `Idempotency-Key: {uuid}`，服务端 24h 内同键去重。
- 支付 / 订单 / 设备绑定 / OTA 触发类**强制**携带；重复请求返回首次结果并带 `X-Idempotent-Replay: true`。
- GET / PUT / DELETE 天然幂等，不加键。

### 1.6 通用请求头

| Header | 说明 |
| --- | --- |
| X-Request-ID | 客户端可传，不传则由网关生成；全链路日志串联唯一键 |
| X-Client | 端标识：`mp` / `ios` / `android` / `web-admin` |
| X-App-Version | 端版本号，兼容性判断依据（配合错误码 10010） |
| X-Device-UDID | 端设备指纹，风控与埋点关联用 |

### 1.7 限流

- 触发返回 HTTP 429 + `Retry-After: {秒}` + 错误码 10009。
- 登录、短信验证码、支付类接口单独配额，按「用户 + IP」双维度计数。

## 规范二：统一错误码

### 2.1 响应格式

成功：

```json
{ "code": 0, "data": { }, "request_id": "req_01J..." }
```

失败：

```json
{
  "code": 20102,
  "data": null,
  "request_id": "req_01J...",
  "error": {
    "detail": "token expired at 2026-10-30T08:00:00Z",
    "field_errors": [ { "field": "code", "reason": "验证码已过期" } ]
  }
}
```

### 2.2 段位分配

| 段位 | 域 | 已登记示例 |
| --- | --- | --- |
| 0 | 成功 | 0 |
| 10xxx | 客户端通用 | 10001 参数错误 / 10004 资源不存在 / 10009 触发限流 / 10010 版本过低强制升级 |
| 20xxx | 账号与权限 | 20101 未登录 / 20102 token 过期 / 20103 验证码错误 / 20201 无权限点 / 20301 账号封禁 |
| 30xxx | 设备 | 30101 设备不存在 / 30102 设备离线 / 30103 已被他人绑定 / 30201 OTA 签名校验失败 / 30202 固件版本不适用 |
| 40xxx | 音视频 | 40101 呼叫占线 / 40102 对方拒绝 / 40103 RTC Token 失效 / 40201 余额不足禁止呼叫 |
| 50xxx | 社区内容 | 50101 内容审核中 / 50102 内容违规下架 / 50201 重复举报 |
| 60xxx | 支付订单 | 60101 订单不存在 / 60102 重复入账（幂等命中）/ 60201 IAP 验票失败 / 60301 对账差异挂起 |
| 70xxx | 服务端 | 70001 内部错误 / 70002 依赖超时 / 70003 维护中 |
| 90xxx | 第三方 PaaS | 90001 RTC 平台错误 / 90002 推送失败 / 90003 短信通道错误 / 90004 内容审核服务错误 |

### 2.3 端上消费规则

1. **一律按 code 分支**，禁止解析 `detail` 原文展示给用户（detail 仅供调试与日志）。
2. 用户可见文案走端上文案表（code → 文案映射），未登记 code 兜底「系统繁忙，请稍后再试」。
3. 固定动作：`20101/20102` → 静默刷新 token 或跳登录；`10010` → 强制升级弹窗不可跳过；`20201` → 隐藏入口 + toast。
4. 新增 code 必须先登记本文档；CI 校验代码中出现的所有 code 均在登记表内。

## 规范三：账号权限模型（RBAC）

### 3.1 双体系分离

- **C 端用户**：注册即普通用户，无角色概念；会员是订阅状态（影响功能配额），不是权限角色。
- **B 端后台**：RBAC 三层模型，账号 → 角色 → 权限点。

### 3.2 模型

```
admin_user ── n:n ── role ── n:n ── permission_point
```

权限点格式：`{module}:{resource}:{action}`，示例：`content:post:audit`、`device:ota:publish`、`order:refund:approve`。

### 3.3 内置角色矩阵

| 角色 | 权限范围 | 明确禁止 |
| --- | --- | --- |
| super_admin | 全部权限点 + 角色分配 | — |
| ops（运营） | 内容 / 活动 / 推送 / 数据看板 / 设备查询 | 财务导出、退款 |
| cs（客服） | 用户查询 / 设备查询 / 工单 / 订单查询 | 资金操作、内容处置 |
| auditor（审核） | 内容审核队列与处置 | 其余全部 |
| finance（财务） | 订单 / 对账 / 退款审批 | 权限分配 |
| readonly | 全只读 | 一切写操作 |

### 3.4 硬规则

1. 权限点**服务端强制校验**；前端隐藏入口只是体验，不构成安全边界。
2. 敏感操作（退款、OTA 发布、权限变更、内容批量处置）写审计日志：操作人 / 对象 / 前后值 / IP / 时间。
3. 一人多岗边界（源文档纪律）：QA 账号不得拥有开发部署权限；任何账号不得自审自批。
4. 离职 / 转岗当日回收权限；审计日志保留 ≥ 3 年。

## 规范四：埋点数据口径

### 4.1 事件命名

- 规则：`{对象}_{动作}`，snake_case。
- 对象字典（登记制）：`auth / device / call / pay / post / ota / push`。
- 动作字典（登记制）：`expose / click / submit / success / fail / cancel`。
- 示例：`device_bind_success`、`call_invite_click`、`pay_order_submit`。

### 4.2 公共参数（全事件必带）

| 参数 | 说明 |
| --- | --- |
| event, ts | 事件名、毫秒时间戳 |
| user_id / device_udid | 登录前后两种口径，关联以登录态为准回填 |
| platform | mp / ios / android / web_admin / device |
| app_version, os_version, model | 端环境 |
| session_id | 30 分钟无事件切新会话 |
| network | wifi / 4g / 5g / none |
| request_id | 关联服务端日志 |

### 4.3 核心口径字典（全公司唯一算法）

| 指标 | 口径 |
| --- | --- |
| DAU | 当日有任一有效事件的去重 user_id 数 |
| 配网成功率 | `device_bind_success / device_bind_start`；3 次重试内成功计入分子 |
| RTC 接通率 | `call_connected / call_invite`；主叫 10 秒内取消不计入分母 |
| 通话人均时长 | 通话总时长 / 接通次数，按端拆分 |
| 付费率 | 当日支付成功去重用户 / DAU |
| 留存 | T+1 / T+7 / T+30 回访去重用户 / 当日新增 |
| OTA 成功率 | 上报成功设备数 / 触发升级设备数，按固件版本与档位拆分 |

### 4.4 硬规则

1. 新事件先登记（事件名 / 参数 / 负责人 / 口径）再开发；事件表随本文档版本管理。
2. 埋点异步上报、失败重试，不得阻塞主流程；与业务库解耦。
3. 隐私合规：不采集通讯录、精确位置、相册等非授权数据；用户撤回授权即停采并删除存量关联。
