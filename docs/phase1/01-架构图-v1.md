## 2. 关键链路

### 2.1 BLE 配网链路（移动端 × 后端 B × 设备）

```
App/小程序 ──BLE──▶ 设备（SoftAP/广播）
   │  ① 发现设备、建立 BLE 通道
   │  ② 请求配网凭证 ──HTTPS──▶ 设备服务（签发一次性配网 Token）
   │  ③ 经 BLE 下发 Wi-Fi SSID/密码 + 配网 Token
   │                设备 ──Wi-Fi──▶ MQTT Broker（携带 Token 激活）
   │  ④ 轮询/推送确认 ──◀── 设备服务（激活成功、绑定到账号）
```

状态机：`待配网 → BLE 已连接 → 凭证已下发 → 设备联网中 → 已激活 / 失败(可重试)`。
失败分支必须可回退到 `待配网`，重试上限 3 次后提示人工客服路径。

### 2.2 音视频 1v1 链路（移动端 × 后端 B × RTC PaaS）

```
主叫 App ──▶ 信令服务：发起呼叫（被叫 id/设备 id）
信令服务 ──▶ 推送/长连接：通知被叫（App 或设备）
被叫应答 ──▶ 信令服务：返回 RTC Token（频道、uid、有效期 5 分钟）
双方 ──▶ RTC PaaS：建立媒体通道（信令服务只管呼叫生命周期，不过媒体流）
通话结束 ──▶ 信令服务：计费事件入库（时长、分辨率、端类型）→ 成本面板
```

原则：**信令自研，媒体走 PaaS**。通话元数据（谁呼叫谁、时长、质量分）必须全量落库，这是成本治理与纠纷溯源的唯一依据。

### 2.3 OTA 链路（后端 B × 设备）

```
固件上传 ──▶ 对象存储 + 版本登记（版本号、适用型号、强制/非强制、灰度比例）
灰度策略 ──▶ 设备服务：按设备组 5% → 50% → 100% 逐档放开
设备拉取 ──▶ 校验签名 + 断点续传 + A/B 分区切换（防砖）
上报结果 ──▶ OTA 面板：成功率、失败原因分布、可一键暂停
```

防砖三原则：签名校验不过不刷、双分区可回滚、灰度档位之间必须有观察窗口（≥24h 或成功率 ≥99% 才进下一档）。

### 2.4 支付与对账链路（后端 A）

```
iOS：IAP 下单 ──▶ Apple 票据 ──▶ 服务端验票 ──▶ 入账（幂等键：transaction_id）
Android/小程序：自有支付 ──▶ 支付平台回调 ──▶ 幂等入账（幂等键：平台单号）
每日 T+1：拉取双方账单 ──▶ 与内部订单三方对账 ──▶ 差异单进人工队列
```

幂等是硬要求：同一笔回调重放 N 次只入账一次；对账差异必须 T+1 内出报表。

| 缓存 | Redis | ✅ 定 | 会话/限流/设备影子 |
| 对象存储 | 国内云 OSS/COS | ✅ 定 | 固件与媒体分桶 |
| CI/CD | GitHub Actions 为主 | ✅ 定 | 四管道见 04 号文发版契约 |
| 推送 | 厂商通道聚合（华为/小米/OPPO/vivo/苹果 APNs） | ✅ 定 | iOS 必走 APNs |
