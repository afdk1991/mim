# 发版契约 v1（04 号文）

> 责任岗位：CTO 签发，全员签署
> 版本：v1.0（M0 签署版）
> 日期：2026-10-30
> 效力：本契约覆盖全部发布行为（服务端 / Web 后台 / 小程序 / iOS / Android / 固件 OTA）。违反契约的发布一律视为事故，按 07 号文风险登记册定级并复盘追责。契约变更走 ADR（00 号文第 5 节流水）。

---

## 1. 四套发布管道与时效表

| 管道 | 发布窗口 | 审核时效 | 灰度能力 | 回滚能力 |
| --- | --- | --- | --- | --- |
| 服务端 | 工作日 10:00–20:00 | 无（自主） | 金丝雀 5% → 观察 → 全量 | **5 分钟内**回滚上一镜像版本 |
| Web 后台 | 工作日 10:00–17:00，随时 | 无（自主） | 按用户白名单灰度（可选） | **秒级**回切（静态资源版本化 + CDN） |
| 小程序 | 审核 **1–3 天**，提前提审 | 微信平台审核 | 发布后按比例分阶段放量 | 版本回退需重新提审（约 1 天），故主要靠服务端开关兜底 |
| iOS | 审核 **1–3 天** | App Store 审核 | 分阶段发布 1% → 100% | 无真正回滚，走三级预案（§4.3） |
| Android | 审核 0.5–3 天（渠道差异） | 各渠道审核 | 渠道内灰度 + 分包发布 | 同上，只能发新版 |
| 固件 OTA | 服务端控制，随时 | 无（自主） | **5% → 观察 24h → 50% → 100%**（02 号文 S6 固定节奏，不可乱） | A/B 分区自动回滚 + 面板一键暂停 |

**发布顺序（02 号文固定，不可乱）**：服务端先行 → Web 后台 → 小程序提审 → App 提审 → 固件 OTA 灰度。任何端不得先于其依赖的服务端版本发布。

## 2. 版本号规则

| 对象 | 规则 | 示例 |
| --- | --- | --- |
| 端（小程序 / App / Web） | 语义化 `x.y.z`：x 破坏性变更、y 功能、z 修复 | 1.2.3 |
| API | URL 携带主版本 `/api/v{n}/`，仅破坏性变更升主版本（03 号文规范一 §1.2） | `/api/v1/devices` |
| 固件 | `x.y.z+build`，build 单调递增；设备拒绝 build 低于当前值的包（防降级攻击） | 1.0.0+1024 |
| 固件协议 / BLE 协议 | 独立协议版本号 `proto_v{n}`，与固件版本号解耦 | proto_v1 |

## 3. 向下兼容 2 版本硬约束（N-2 原则）

1. 线上当前版本 N 必须兼容 N-1、N-2 两个历史客户端/固件版本。
2. 客户端版本低于 N-2 → 服务端返回错误码 **10010**（03 号文已登记），端上弹强制升级窗，**不可跳过**。
3. 破坏性变更一律「**先加后删**」三步走：
   - **v(N)**：新增字段/接口，旧字段保留并继续写入；
   - **v(N+1)**：双写/双读，灰度验证新路径正确性；
   - **v(N+2)**：确认旧路径流量归零后下线旧字段/接口。
4. 数据库变更：只允许增量迁移（加列/加表/加索引）；禁止直接改列类型、删列；删列同样走「先加后删」。
5. 固件 / BLE 协议：新协议字段对旧固件必须可忽略；旧固件遇到未知字段不得崩溃、不得进入异常状态机。
6. CI 卡控：API diff 检测（OpenAPI 对比）发现破坏性变更且未升主版本号 → 流水线红灯。

## 4. 灰度与回滚预案

### 4.1 服务端
- 金丝雀 5% → 观察 10 分钟核心指标（5xx 错误率、P95 延迟、业务错误码分布）→ 无异常全量。
- 回滚：5 分钟内切回上一镜像；**回滚不回库**（数据库迁移必须向后兼容，见 §3.4）。

### 4.2 Web 后台
- 静态资源按内容哈希版本化，CDN 秒级回切上一版本。

### 4.3 App 三级预案（应用商店无真正回滚）
- **一级（分钟级）**：服务端功能开关/远程配置关闭问题功能，热修文案与跳转。
- **二级（天级）**：紧急修复版走 App Store 加急审核通道；Android 多渠道并行重提。
- **三级（重大事故）**：公告降级说明 + 配合 10010 强制升级引导用户到修复版。

### 4.4 固件 OTA
- A/B 双分区：新固件首次启动自检失败 → 自动回滚旧分区并上报。
- 灰度档位之间观察窗 **≥24h**；任一档成功率 <99% 立即暂停，不得人工跳档。
- OTA 面板提供**一键暂停**（01 号文 §2.3），按下后 5 分钟内全量停止下发。
- 防砖三原则（01 号文重申）：签名校验不过不刷、双分区可回滚、档间必须有观察窗。

## 5. 审核窗口预案

1. **素材随迭代更新**：商店截图、描述、隐私政策链接、审核账号每个 S 迭代刷新一次；W11 冻结终稿，W12 只提审不改稿。
2. **被拒响应 SLA**：2 小时内定位拒因并分派责任人，24 小时内修复重提；涉及资质/合规（音视频、支付类目）立即升级 CTO+PM 双签决策。
3. **节假日冻结**：春节/国庆前 3 天冻结一切发布，仅允许 P0 hotfix（CTO 单签）。
4. **Android 渠道表**：各渠道（华为/小米/OPPO/vivo/应用宝）素材要求与审核节奏登记入渠道表，比 iOS 提前 1 天提审。

## 6. 发布检查单（逐项签字，缺一项不发布）

- [ ] **N-2 兼容回归通过**：N-1、N-2 老版本端对新服务端全主路径回归
- [ ] **P0/P1 缺陷清零**（依据 07 号文风险分级测试矩阵）
- [ ] **回滚演练实测**：服务端回滚脚本、Web 回切、OTA 一键暂停在预发环境真实执行过
- [ ] **监控告警就位**：错误率、RTC 接通率、配网成功率、OTA 成功率、对账差异面板有数且有告警阈值
- [ ] **数据库迁移脚本**可重复执行、向后兼容、有回退说明
- [ ] **值班表确认**：发布日值班人签字——CTO、QA、后端 A/B、移动端各一

> 签字人：发布负责人 + CTO。检查单存档于 docs/phase1/releases/ 目录，按版本号命名。

---

## 7. 违规与事故定级

违反本契约导致的线上事故，按 07 号文风险矩阵定级（P0/P1/P2），复盘会必须回答三个问题：哪条契约被违反、为什么没被检查单拦住、流程上补哪一道。同一契约条款一年内被违反两次，该条款升级为 CI 强制卡控。
