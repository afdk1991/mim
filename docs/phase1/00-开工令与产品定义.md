## 1. 项目前提（不可变更的边界条件）

| # | 前提 | 含义与约束 |
| --- | --- | --- |
| P1 | **不出海** | 只做中国大陆市场。合规口径按国内（ICP、个保法、算法备案、音视频内容审核）；无多语言、无跨境数据、无海外支付 |
| P2 | **硬件 + 音视频 + 重度交互全要** | 三条主线同等优先级，任何一条掉链子 Phase 1 即失败。排期必须给三线各自的联调与认证窗口 |
| P3 | **后端自研** | 业务后端不采购 SaaS 套件；仅音视频 RTC、推送、短信等基础能力允许使用 PaaS |
| P4 | **上中台，但 Phase 1 只出规范不建团队** | Phase 1 交付中台四份种子规范（API 规范 / 统一错误码 / 账号权限模型 / 埋点数据口径），由 CTO 兼任中台 owner，不设专职中台岗 |

## 2. 产品定义（假设驱动，逐条待确认）

> 原文档未写明产品具体形态。以下为基于文档技术线索（BLE 配网、固件 OTA、RTC、10 万长连接、小程序+App+管理后台、支付对账）的**工作假设**。标注 ⚠️ 的条目请决策者在 W1 内确认或纠正；未纠正即按假设执行。
>
> ✅ **2026-10-30 决策者确认**：A1（硬件形态）、A2（小程序为第一入口）锁定，按假设执行；A3–A7 未收到纠正，按「未纠正即按假设执行」规则生效。ADR-001 关闭。

### 2.1 一句话产品定义（假设 A1 ✅ 已确认）

**一款面向国内家庭/个人用户的智能音视频互动硬件，配套小程序与独立 App 完成配网、控制与社区互动，Web 管理后台支撑运营与客服，硬件与音视频之外的增值服务（会员/内容/时长包）构成商业闭环。**

### 2.2 假设清单（W1 必须全部确认）

| # | 假设 | 依据线索 | 风险 |
| --- | --- | --- | --- |
| A1 ✅ | 硬件形态为带摄像头/屏幕/麦克风的联网设备（互动屏/陪伴机器人/摄像头三选一或兼容） | BLE 配网、OTA、Metal 渲染、RTC | 形态不同直接影响结构设计、认证类目（3C/SRRC 型号）、音视频采集链路 |
| A2 ✅ | C 端第一入口是**微信小程序**，独立 App 承载重度交互 | 小程序 1–3 天提审管道、App Store 管道并存 | 决定双端功能切分与差异化矩阵 |
| A3 | 音视频场景以 **1v1 实时互动** 为主，Phase 2 才考虑多人 | 顾问岗按"单用户单分钟成本"建模、RTC 选型 | 多人场景成本模型与架构差异巨大 |
| A4 | 商业模式含**应用内付费**（会员/增值），iOS 走 IAP、Android/小程序走自有支付 | 后端 7A 交付物含"支付幂等对账" | IAP 与自有支付双轨对账是后端复杂度大户 |
| A5 | Phase 1 设备在线规模目标 **10 万长连接** | 后端 7B 交付物 | 决定 MQTT Broker 选型（自研 EMQX 集群 vs 托管） |
| A6 | 硬件由外部 ODM/方案商供板，团队只做固件上层 + 配网协议 + OTA 机制 | 岗位表无硬件结构/电子工程师 | 若实际要自研硬件本体，9 人配置不成立，需立即升级 |
| A7 | 内容形态含 UGC 社区（动态/图片/视频） | 文档多处"社区/内容"表述 | 涉 UGC 则内容审核（先审后发/先发后审）是必须项 |

### 2.3 Phase 1 范围内 / 范围外

**范围内（0–6 个月必须交付）：**

1. 硬件：BLE 配网全流程、固件 OTA（灰度+防砖）、设备激活/绑定/解绑
2. 音视频：1v1 RTC 通话（App↔设备、App↔App 至少一路）、质量指标面板、单分钟成本核算
3. 软件：小程序（配网+控制+社区浏览）、iOS/Android App（全功能）、Web 管理后台（账号/RBAC/设备/内容审核/订单）
4. 后端：账号中心 v1、RBAC、设备接入层、OTA 服务、音视频信令服务、社区服务、支付与对账、管理后台 API
5. 中台：四份种子规范（只出规范 + 在业务代码里落地，不建独立中台服务）
6. 基建：CI/CD 四管道、监控告警、成本面板

**范围外（Phase 2 及以后）：**

- 多人音视频/连麦、直播
- 出海、多语言
- 独立中台团队与中台服务化拆分
- 商城/电商闭环
- 硬件本体自研（结构/电子/射频）
