## 第二部分：风险分级测试矩阵

> 三级定义：**P0 阻断**——挂了产品就不能用或造成资金/安全事故，发版前必须 100% 通过，自动化优先；**P1 主路径**——核心体验受损但有兜底，发版前 100% 通过（允许手工）；**P2 边缘**——体验降级，发版前抽样，缺陷可带限放行（PM 签字）。

### P0 阻断级（不过 = 不发布，对应 04 号文检查单「P0/P1 清零」）

| 域 | 用例 | 覆盖要点 | 自动化 |
| --- | --- | --- | --- |
| 账号 | 验证码登录 / 微信登录 / token 过期续期（20102 静默刷新）/ 强制升级拦截（10010） | 三端 | ✅ E2E |

## 第三部分：执行机制

1. **P0 自动化进 CI**：配网/支付幂等/账号核心用例挂主仓库流水线，红灯即阻塞合并（W6 前接入，W9 E2E 主路径全量自动化——02 号文 S5）。
2. **测试环境**：SIT（随 CI）→ 预发（类生产，W11 RC 回归在此）两级；固件测试通道与正式通道物理隔离。
3. **众测**（W10，02 号文）：≥50 台设备、≥100 用户，众测报告是 M3 验收件；众测缺陷按本矩阵定级，P0/P1 必须清零才能进 W11。
4. **缺陷流转**：发现 → 定级（QA 单签，争议升级 CTO）→ P0 当日响应 / P1 当迭代关闭 / P2 登记放行。
5. **发版裁决**：QA 依据本矩阵出「可发布/不可发布」结论，与 04 号文检查单互为前置；QA 有一票否决权。
