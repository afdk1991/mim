# 06 · 治理规约

> 本仓库的治理体系由 [AGENTS.md](file:///f:/合并项目/Mim/AGENTS.md) 定义，对所有 AI 协作者（本机会话、CI、自动化）具有强制约束力。本页为结构化解读，原文以 AGENTS.md 为准。

## 1. 十一条铁律总览

| # | 铁律 | 一句话 | 优先级 |
|---|---|---|---|
| 一 | AI 负责执行 | 不把任务丢回用户，全权接管浏览器等一切可自动化环境 | **最高** |
| 二 | 可逆直接做，不可逆先授权 | 不可逆/结构性操作须先出计划 + 影响清单 | 高 |
| 三 | 基于证据 | 「已完成/已修复/不可达」须有命令输出或文件改动佐证 | 高 |
| 四 | 版本号规约 | 首版 V0.0.0 起递增；预览走 RELEASE_CHANNEL；内部 tag 用 draft-*/pre-* | 中 |
| 五 | 必须引入第三方依赖 | 通用能力用成熟库，禁 vendor，登记名称/版本/用途 | 中 |
| 六 | 全角色全流程自动化 | AI 承担所有人员职责，每轮交付前必须 BUG/代码检查 | 高 |
| 七 | 功能模块增删全量同步 | 增/改/删模块须同步全部受影响工件，交付报告附同步清单 | 高 |
| 八 | 任务完成后必须生产上线 | 前后端 + 数据库全自动部署到远程生产环境；**禁止以本地预览替代上线**；无线上取证不得宣称已上线 | **最高**（与铁律一同为硬门禁） |
| 九 | 多平台免费部署矩阵 | 9 个免费平台固定矩阵，禁引入付费方案；每轮部署逐平台刷新 HTTP / 耗时 / 连接取证；本机不可达须附网络侧证据 + 替代取证 | 高 |
| 十 | 免费平台额度矩阵与选型路由 | 远程仓库 4 + 纯静态 5 + 后端动态 2 平台免费额度为准入依据；Render 修正为免费候选；新平台过四要件 + 季度复核 | 中 |
| 十一 | 全仓库逐行注释与解释 | 业务代码 / 脚本 / CSS / HTML 每行中文解释；`comment-check.mjs` 校验；`--strict` 为 CI 门禁；未达标禁止虚报完成 | 高 |

## 2. 铁律一详解（执行优先）

- 用户提出目标（部署/上线/修复）时，AI 必须穷尽当前环境下可执行的真实动作
- 障碍处理顺序：① 穷尽真实动作（诊断、替代方案、可逆操作）→ ② 如实报告客观前提缺失 → ③ 报告必须区分「我没有做」与「环境确实不可达」
- 「不可达」必须有取证证据（命令、输出、时间戳）
- **唯一例外**（可请求用户提供凭证，且须附已尝试证据）：
  - 外部服务需用户私有 OAuth 令牌/密钥
  - 外部主机需用户私有 SSH 私钥且沙箱不可生成

## 3. 铁律二操作分级

| 类型 | 示例 | 动作 |
|---|---|---|
| 可逆 | 本地分支改名、重命名 tag、重部署、改文件 | 直接执行，不追问 |
| 不可逆/结构性 | 远端删 tag、强推、跨目录移动、删数据 | 先输出完整计划 + 影响清单，获明确授权（常以「执行」单字批准）后执行 |

## 4. 铁律四版本号规约（与 README 同步）

```
正式通道：  V0.0.0 → V0.0.1 → V0.0.2 …（发布前不得占用）
预览通道：  RELEASE_CHANNEL=preview → 展示 V0.0.0-preview（semver 数字不变）
内部 tag：  draft-* / pre-*（禁止 V<semver> 形态）
强制校验：  scripts/version-check.mjs（通道感知：预览通道存在正式 tag 即 ❌）
密钥校验：  scripts/env-check.mjs（09 清单 §0：.env.example ↔ 09 清单 ↔ .gitignore 一致性）
注释校验：  scripts/comment-check.mjs（铁律十一：逐文件注释覆盖率，--strict 为 CI 门禁）
```

校验器的具体实现与判定表见 [03-code-reference.md](./03-code-reference.md)。

## 5. 铁律五依赖治理

- 必须显式声明依赖清单 + 锁文件
- 交付报告登记依赖名称、版本号、用途
- 自研例外须说明理由并经用户确认
- **冲突裁决**：与铁律一冲突时（沙箱无网络、包管理器不可达等）执行优先，可本地实现/精简功能，但报告中必须显式标注「已偏离铁律五」及理由

当前仓库依赖实况（零第三方依赖）见 [04-dependencies.md](./04-dependencies.md)。

## 6. 铁律六详解（全角色全流程自动化）

AI 以项目全部角色（产品、架构、前端、后端、测试、运维、QA 等）身份全自动推进开发闭环，不以「分工」为借口将任何环节丢回用户。

- **覆盖全程开发**：新写代码、补充补全（占位/半成品/TODO 实现必须补完）、修复、梳理整理、BUG 排查、代码检查（自查 + 审查）等全部环节
- **每轮交付前必须做 BUG/代码检查**：静态检查 + 自测（可运行命令时以命令取证），结果写入交付报告；「没检查」不得作为交付结论
- **自动化优先**：能写脚本/命令自动完成的验证不手工描述；可固化的检查项沉淀为脚本或文档规则
- **接管浏览器**等一切可自动化环境（与铁律一「全权接管所有包括浏览器等等」一致）

## 7. 铁律七详解（功能模块增删全量同步）

每次**添加、修改或删除**任何功能模块（含规则、文档、依赖、配置），必须同步更新项目内所有受影响工件，不允许「只改代码不改文档」。

- **同步范围**（按实际涉及项）：源代码与补全、依赖清单 + 锁文件（铁律五）、版本号与 RELEASE_CHANNEL（铁律四）、PRD（Mim-PRD.html）、Wiki（docs/wiki/*）、README
- **交付报告必须附同步清单**：列出本次更新的工件与明确「不涉及」的工件；漏更新视为交付未完成
- **删除模块同样适用**：同步清理文档、依赖、索引与版本记录，不得留下悬空引用

## 7.1 铁律八详解（任务完成后必须生产上线）

**本地运行 / 本地预览不是交付终点，只是过程验证手段。** 记录日期：2026-11-04。

- **交付终点 = 生产可访问**：每轮任务（新增功能、修复、改造、文档/静态站点变更）完成后，必须把**前端 + 后端 + 数据库**全自动部署到远程生产环境并上线；不得以「本地跑通了」「本地预览正常」「你自己部署一下」作为结论。
- **链路全自动、可重放**：CI（`.github/workflows/deploy.yml`）在 `main` 上触发 → 安装依赖 → 类型检查 → 测试 → 构建 → 远程发布（`deploy/deploy.sh`）→ 重启服务 → 线上健康检查。服务器侧以幂等脚本实现，禁止依赖手工敲命令。
- **禁止只交付静态站点预览**：`apps/web` 构建产物必须与 `services/mim-api`、SQLite 数据库一起上线到生产域名；部署配置（`deploy/`、`.github/workflows/`）必须入库。
- **必须有线上取证**：`curl https://mim.mixm.top/health` 返回 200、已下线接口（`/api/v1/plans`、`/api/v1/audit/logs`）返回 404、以及一次真实端到端操作（登录 / 设置页 / 漫剧项目列表）验证结果。**无线上取证不得宣称「已上线」。**（原「建项目 / 建任务 / 仪表盘」示例随 FR-03 于 2026-11-04 移除；套餐/订阅/审计模块于 2026-11-05 下线）
- **数据库必须持久化**：生产库落磁盘（非内存/临时目录），备份脚本 `deploy/backup-db.sh` 随工件入库。
- **客观不可达时**：按铁律一处置——先穷尽可执行动作并附取证，再明确报告缺口，不得以「本地预览」替代上线。

## 8. 产品侧治理约束（PRD §6 共享规则）

| 规则 | 定义 | 影响模块 |
|---|---|---|
| Region 隔离 | 国内(cn)/海外(global) 数据物理隔离，账号 / 模块权益 / 漫剧数据按 region 分区存储 | FR-01/03 |
| 幂等性 | 写操作接口（建工程、建任务、发成片版本等）以 `Idempotency-Key` 幂等，同键同体重放首次结果、同键异体 409 | FR-03 |
| 操作留痕 | 登录、注销等关键操作由运维变更记录留痕 180 天（应用内审计模块已于 2026-11-05 随产品范围下线） | FR-01/06 |
| 通知规则 | 异常登录站内 + 邮件/短信通知；原支付成功 / 到期提醒 / 续费失败通知已随订阅模块于 2026-11-05 下线 | FR-01 |

合规底线：国内数据境内存储不出境；账号注销 7 天冷静期；海外删除请求按 GDPR/CCPA 30 天内处理。（原「支付清算必须由持牌机构完成」已随支付模块下线于 2026-11-05 移除）
