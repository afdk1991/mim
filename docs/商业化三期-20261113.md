# 商业化三期落地说明（2026-11-13）

> 范围：后端包「商业化与分类级权限」。仅含三项能力——**批量改价**、**积分抵扣消费**、**分类级权限**。

## 1. 数据模型

增量 SQL：`services/mim-api/src/schema.d/10-commerce3.sql`（幂等；`CREATE TABLE IF NOT EXISTS`；已有表补列走 `ALTER_ADD:`；无 DROP / DELETE 业务语句）。

| 表 / 补列 | 用途 | 关键约束 |
|---|---|---|
| `price_batches` | 批量改价批次头：模式、方向、参数、筛选快照、命中 / 改动 / 跳过计数、回滚时间 | `(actor_id, idempotency_key)` 唯一；`target_type` / `mode` / `direction` CHECK |
| `price_batch_items` | 逐条改前 / 改后快照明细，供回滚与审计；`skipped=1` 记跳过原因 | 外键 `batch_id`；`price_row_id` 定位模块生效价格行 |
| `category_access_rules` | 分类级权限规则：角色 / 用户 → 一级 / 二级分类 allow / deny | `(subject_type, subject_id, category_slug)` 唯一；`subject_type` / `effect` CHECK |
| `module_orders.points_spent` | 本单消耗积分（补列，默认 0） | `ALTER_ADD` |
| `module_orders.points_deduct_cents` | 积分折抵金额（分，补列，默认 0）；原始成交价 `amount_minor` 不改写，抵扣额单列留痕便于对账 / 退款回滚 | `ALTER_ADD` |

## 2. 批量改价

### 2.1 能力口径

- 目标两类：`module`（模块当前生效价格行）、`shop_product`（独立商城商品 `shop_products.price_cents`）。
- 三种模式：
  - `fixed` 固定价：`direction=set`，`value` 为新价（分）；
  - `percent` 百分比增减：`value` 为百分点（1–100），按原价四舍五入到分；
  - `amount` 固定金额增减：`value` 为分，原价加减，结果不为负。
- 筛选条件（全部可选，取交集）：`region`、`category_slug`（二级精确 / 一级前缀）、`codes` 编码清单、`include_inactive`（缺省只改在售 `active`）。
- 安全规则：当前价格 `<= 0` 的免费 / 0 价商品一律跳过（记 `skipped`，reason=`free_zero_price`），不会被误改成付费；计算结果与原价一致的记 `unchanged`，不产生无意义写入。
- 事务化：整批快照、改价、留痕在同一 `db.transaction` 内，任一失败整体回滚。
- 幂等：`(actor_id, idempotency_key)` 唯一；同键重复提交回放既有批次，不二次改价。
- 快照回滚：逐条 before/after 落明细；`POST rollback` 按快照把实际改动项恢复到改前价格，同事务；已回滚批次重复回滚返回 409。
- 审计留痕：批次头 + 明细全量留存操作人、模式、参数、筛选条件、改前 / 改后价与跳过原因。

### 2.2 管理端端点（权限：`commerce:write`，复用既有权限点，未新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/api/v1/admin/commerce/price-batches` | 提交一批调价；Body：`target_type` / `mode` / `direction` / `value` / `filter` / `idempotency_key`；201 返回批次视图（含明细快照） |
| GET | `/api/v1/admin/commerce/price-batches` | 最近 50 批（倒序） |
| GET | `/api/v1/admin/commerce/price-batches/:id` | 批次详情（改前 / 改后快照） |
| POST | `/api/v1/admin/commerce/price-batches/:id/rollback` | 按快照回滚该批；重复回滚 409 |

服务层：`src/commerce/price-batch.ts`（`runPriceBatch` / `rollbackBatch` / `listBatches` / `getBatch`）。

## 3. 积分抵扣消费

### 3.1 组合顺序

```
商品原价 → 优惠码折扣（商城既有逻辑，community 域）→ 积分抵扣 → 余额 / 渠道支付
```

本包只实现「优惠码之后」的积分段；优惠码、余额、渠道支付既有链路不变。

### 3.2 计算口径（纯函数 `computeDeduction`，可单测穷举）

- 兑换比例：`MIM_POINTS_PER_YUAN` 积分 = 1 元（1 元 = 100 分）；
- 单笔上限：抵扣额不超过应付金额的 `MIM_POINTS_MAX_RATIO_PERCENT`%；
- 余额约束：抵扣额不超过当前积分余额可折金额；
- 三重约束取最小（上限 / 余额 / 应付额）；积分向上取整，避免少扣导致平台贴钱。
- 入参 `points_to_use`（可选）：指定消耗积分；校验余额与单笔上限，不足抛 `INSUFFICIENT_POINTS`，超限抛 `POINTS_CAP_EXCEEDED`；未指定则按预算最大化抵扣。

### 3.3 边界处理

| 场景 | 行为 |
|---|---|
| 总开关关闭 / 0 元订单 / 免费商品 / 无积分余额 | 不抵扣、不消耗积分，订单抵扣字段归零 |
| 未指定积分 | 受上限与余额截断，`capped_by` 记录约束来源（`ratio` / `balance` / `none`） |
| 指定积分超余额 | 400 `VALIDATION_FAILED`，`details.reason=INSUFFICIENT_POINTS`；不生成订单、不扣积分 |
| 指定积分超单笔上限 | 400 `VALIDATION_FAILED`，`details.reason=POINTS_CAP_EXCEEDED`；不生成订单、不扣积分 |
| 抵扣后应付为 0（全额抵扣） | 订单置 `paid`，同事务内即时发放权益并留状态事件，不再生成待付单 |

### 3.4 事务与留痕

- 订单写入、积分扣减、权益发放包在同一个 `db.transaction`；扣减带 `points >= ?` 守卫，并发超扣时影响 0 行直接抛错回滚整笔。
- 积分流水：`wallet_transactions.kind='points'`，`points` 记负向积分、`amount_cents` 记折抵金额，`ref_type='module_order'` 关联订单。
- 订单留痕：`points_spent`（消耗积分）、`points_deduct_cents`（折抵金额分）；原始成交价 `amount_minor` 不改写。

### 3.5 结算接入点（模块订单，购物车）

`POST /api/v1/cart/checkout` 新增可选入参：`use_points: boolean`、`points_to_use: number`（指定积分量，视为开启抵扣）。响应每条结果回带 `points_spent` / `points_deduct_cents` / `payable_cents`。

服务层：`src/commerce/points.ts`（`getPointsBalance` / `computeDeduction` / `deductPoints`）、`src/commerce/config.ts`（配置读取与归一化）。

### 3.6 未接入点（需后续 / 并行包）

- **独立商城商品（shop product）结算**：在 `community.ts`（禁止修改）。接入点：商城下单余额扣款之前，先调 `computeDeduction` 计算抵扣，再在同一事务内 `deductPoints`，抵扣额从应付中扣减并留痕。
- **待结算订单后续结算路径**：模块订单抵扣后仍有应付余额时，后续人工 / 渠道结算（`catalog.ts` settle / payment-notify）需按 `points_deduct_cents` 从应付中扣减；本包仅在订单两列留痕，结算金额对账口径待结算链路补齐。

## 4. 分类级权限

### 4.1 口径（在既有 RBAC 之上叠加分类维度）

- 主体：`role`（按角色码，经 `user_roles` 实时并集）、`user`（按用户 ID）。
- 规则：`allow` / `deny`；**deny 优先**——同一分类只要存在一条 deny 规则即拦截。
- 命中：规则 slug 为二级标识时精确命中；为一级标识时前缀覆盖其全部二级条目（`${slug}-`），并按分类树父级兜底匹配。
- **未配置 / 无规则命中 → 放行**，与 0.0.6 现网公开行为一致；模块无分类标识（老数据）规则无从命中，保持公开。
- 匿名主体：无规则可命中。公开路由未挂 `requireAuth`，服务层支持可选解析 Bearer 令牌（校验失败回落匿名，不抛 401、不阻断公开浏览）。

### 4.2 生效点

**商城列表（两处过滤，被 deny 的模块整列剔除）：**
1. `GET /api/v1/modules` 模块列表；
2. `GET /api/v1/modules/hot` 热门列表。

**购买（两处门禁，被 deny 抛 403 `FEATURE_NOT_AVAILABLE`）：**
1. `POST /api/v1/cart/items` 加购时拦截；
2. `POST /api/v1/cart/checkout` 结算时逐条拦截（整笔结算不落到被 deny 条目）。

**其余访问门禁：**
- `GET /api/v1/modules/:code` 详情 403；
- `POST /api/v1/entitlements/:code` 解锁 403；
- `POST /api/v1/orders` 下单 403。

> 说明：列表过滤与详情 / 下单门禁使用同一规则集；403 不泄漏「存在但被禁」与「不存在」的差异。

### 4.3 管理端端点（权限：`rbac:write`，复用既有权限点，未新增）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/v1/admin/category-access` | 全部分类规则 |
| PUT | `/api/v1/admin/category-access` | 整组替换某主体规则；Body：`subject_type` / `subject_id` / `rules[{category_slug, effect}]`；同 slug 去重、deny 胜出；空清单即清空 |
| DELETE | `/api/v1/admin/category-access/:id` | 删除单条规则；不存在 404 |

服务层：`src/commerce/category-access.ts`（`subjectFromUser` / `subjectFromRequest` / `isCategoryBlocked` / `assertCategoryAllowed` / `blockedModuleIds` / `listAllRules` / `replaceSubjectRules` / `deleteRule`）。

## 5. 环境变量（MIM_ 前缀，未写入 `.env.example`）

| 变量 | 默认 | 说明 |
|---|---|---|
| `MIM_POINTS_DEDUCTION_ENABLED` | `1`（开启） | 积分抵扣总开关；显式 `0` 关闭，其余取值视为开启 |
| `MIM_POINTS_PER_YUAN` | `100` | 多少积分折抵 1 元（1 元 = 100 分）；正整数，非法回落默认 |
| `MIM_POINTS_MAX_RATIO_PERCENT` | `30` | 单笔抵扣上限占应付金额百分比（0–100）；0 表示不可用积分 |

批量改价、分类级权限无需新增环境变量。
