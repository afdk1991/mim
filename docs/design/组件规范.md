## 1. 现状总览

- 组件目录：`src/ui/`，共 4 个 tsx + 1 个出口 `index.ts` + 4 个样式文件。
- 统一出口：`src/ui/index.ts`，页面只从 `@/ui` 导入（`src/ui/index.ts:1` 的约定）。
- **组件分为两类**：
  1. **React 组件**（18 个导出，含 1 个 hook、1 个模块级函数）；
  2. **纯 CSS 类组件**（按钮、输入、chip、tabs 等，页面直接写 `className`）。
- `src/ui/basic.tsx:3-4` 明确了既有写法：**按钮直接写 `className="btn btn-primary"`，不额外包一层 Button 组件**。补齐计划必须尊重这一约定，否则会与全站既有写法冲突。

## 4. 三端一致落地建议

### 4.1 组件层禁止触碰宿主 API（当前存在违规）

平台层约定（`src/platform/types.ts:8-10`）：**全工程不允许再直接写 `localStorage / window / document / navigator / wx`**。

已确认的违规点（**仅登记，未修改代码**）：

| 文件:行号 | 违规内容 | 影响端 | 建议 |
| --- | --- | --- | --- |
| `src/ui/basic.tsx:74` | `window.addEventListener('keydown', onKey)` | 小程序（无 window）运行时会抛错；Capacitor/Tauri 可用 | Modal 的键盘监听应做宿主存在性判断，或下沉为「可选增强」 |
| `src/ui/basic.tsx:75` | `window.removeEventListener` | 同上 | 同上 |

其余组件（`toast.tsx`、`post-card.tsx`、`rich-text.tsx`）未发现裸宿主 API。

### 4.2 统一出口与导入约束

- 页面只写 `import { PostCard, Modal } from '@/ui'`（`src/ui/index.ts`）。
- 新增组件必须同时在 `src/ui/index.ts` 导出，否则会绕过统一出口。
- 组件内**不得** import `src/data`、`src/domain` 的业务态；交互一律通过回调外抛（`src/ui/post-card.tsx:4-5` 的既有约定）。

### 4.3 样式与 Token

- 组件样式一律用 CSS 变量，禁止硬编码颜色（`src/ui/styles/theme.css:1-6` 铁律）。
- 组件内禁止写死字号/间距，优先等 `DesignToken.md` 第 2/3 节变量落地后再批量改造（当前为硬编码）。
- 深色模式：每个新组件必须同时核对 `html[data-theme='dark']` 下的取值。

### 4.4 尺寸与触控

| 项 | 现状 | 建议 |
| --- | --- | --- |
| 图标按钮 | 32×32（`base.css:158-159`） | 移动端触控目标建议提升到更大尺寸，或新增移动变体 |
| 主断点 | 860px（`layout.css:165`） | 新增组件一律以该断点为唯一响应式分界，不各自定义 |
| 内容最大宽度 | `--max-w: 1180px`（`theme.css:35`） | 全宽组件沿用该变量 |
| 图片 | 动态图硬截 9 张（`post-card.tsx:57`） | 网格规则见 `.post-images.n*`（`components.css`） |

### 4.5 文案与提示

- 轻提示统一走 `emitToast` / `useToast`，组件内不自己实现提示（`src/ui/toast.tsx:1-6`）。
- 分享/复制/打开外链等能力结果一律为 boolean，降级文案由调用方给出（平台层语义，见 `docs/product/多端差异矩阵.md`）。
