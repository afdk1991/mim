# Mim 功能全景与落地路线图（2026-11-12）

> 依据：用户 2026-11-12 给出的「阅读主题 → 知识付费 → VIP 会员 → 余额/积分/分成 → 社区论坛 → 模块化布局 → 独立商城 → 国际化 → 安全加固」功能清单。
> 对照基准：`packages/core-domain/src/siteModules.json` 的 44 个统一入口、`services/mim-api/src/schema.sql`、`apps/web/src` 现有视图。
> 说明：本文只描述事实与落点，不把「计划」写成「已完成」；并行会话正在落地的部分单独标注。

## 0. 一句话结论

Mim 已经不是单一 IM，而是「IM + AI 漫剧 + 模块商城 + 统一入口 + 导航站」的多业务平台；本轮并行补齐**社区论坛、知识付费帖、VIP、钱包/积分、卡密、优惠码、独立商城、推广返佣**的后端底座，本会话补齐它们都缺的**统一搜索**。清单里的付费图库/视频资产、支付渠道适配、物流、提现与分成结算、可视化页面搭建、机器翻译、验证码与内容审核、Meilisearch 索引同步仍按 P1–P5 推进。

## 3. 分批落地计划

### P0（本轮，已交付）
- 统一搜索：五来源聚合、来源过滤、片段高亮、Meilisearch 可选、失败自动降级。
- 并行底座：社区、付费帖、VIP、钱包/积分、卡密、优惠码、商城、推广（由并行会话落地，本会话只做冲突隔离与必要修复）。

### P0+（商业化二期，V0.0.5 已交付）
- 付费资产四类（阅读 / 下载 / 图库 / 视频）与购买解锁、作者 70% 分成。
- 支付意图与四渠道适配：支付宝当面付、微信 Native、人工转账、沙箱 HMAC。
- 发货物流轨迹、售后申请与审核退款、订单评价与商品评分聚合。
- 提现冻结 / 驳回退回 / 打款、创作者收益结算、平台资金汇总。
- 外观设置与页面区块 CRUD / 排序、成长等级与徽章、按 Mim ID 私信、IP 哈希归属地。
- 百度翻译适配、翻译缓存、前后台语言分离。
- 前端 `/commerce` 商业化中台五页签；`commerce.test.ts` 8 例契约测试。

### P1（内容付费四件套）
- 表：`library_contents`、`library_assets`、`library_purchases`。
- 接口：列表/详情/购买/资产下载/我的已购；付费内容对未授权用户只回摘要，不回正文与资产地址。
- 视图：`/library` 阅读主题首页 + 详情页；四类内容共用一套卡片与付费墙。
- 验收：免费内容匿名可读；VIP 内容按等级解锁；付费内容余额不足 402；购买幂等；下载必须校验权益。

### P2（交易闭环）
- 支付适配器：微信企业支付、支付宝当面付/企业支付、虎皮椒/讯虎、PayPal、Stripe；统一 `payments` 状态机与回调验签。
- 订单：待支付/已支付/发货中/已完成/退款中/已退款；超时关单；库存与卡密原子扣减。
- 物流：运单号、快递查询适配、收货确认；售后：退款/退货/评价。
- 营销：优惠码与订单联动、批量改价、满减；免登录购买 + 支付前绑定手机。
- 验收：回调重放不重复入账；退款回冲余额与佣金；卡密发货不超卖。

### P3（用户成长与运营）
- 等级成长值、徽章规则、实名认证、邀请码注册、私信、IP 归属地。
- 推广返佣结算、创作分成月结、提现申请与人工审核、对账报表。
- 验收：分成可追溯到订单；退款自动回冲；提现冻结/解冻有流水。

### P4（布局与国际化）
- 可视化页面搭建：页面 → 区块 → 组件三层，论坛可设为首页；导航/背景/配色/列表样式可配置。
- 多语言：机器翻译任务、术语表、前后台语言分离、SEO hreflang；分享卡片、代码高亮、幻灯片组件。
- 验收：同一页面中英切换不丢配置；区块拖拽排序可持久化；翻译失败可回退原文。

### P5（安全与运维）
- 验证码：图片/滑动、腾讯、极验 4.0；内容审核：百度审核 + 举报频控；防 SSRF 白名单。
- 运维：Redis 会话/频控、CDN、懒加载、慢查询与索引巡检、备份恢复演练、换域名清单。
- 验收：攻击面清单逐项有测试；密钥不入库；审核失败有降级策略。

### P6（自研工具发布）
- Quick Build WP、数据库批量替换/换域名、流盾 WAF 作为独立产品，在社区「工具发布」板块提供介绍、下载、版本记录与讨论。

## 4. 关键数据模型与接口落点（P1 建议）

```sql
-- 内容库主表：四类内容共用，access 决定付费墙
library_contents(id, slug, kind, title, summary, body, cover_url, category, tags,
                 access, vip_level, price_cents, status, author_id, views, downloads,
                 published_at, created_at, updated_at)
-- 资产表：下载文件 / 图集图片 / 视频地址
library_assets(id, content_id, kind, name, url, size_bytes, sort_order)
-- 购买表：一人一内容一条，幂等回放
library_purchases(id, user_id, content_id, amount_cents, source, created_at, UNIQUE(user_id, content_id))
```

接口：
- `GET /library/contents?kind=&access=&q=&page=`
- `GET /library/contents/:id`（未授权只回 `locked:true` + 摘要）
- `POST /library/contents/:id/purchase`（登录 + 幂等；余额支付写 `wallet_transactions`）
- `GET /library/contents/:id/assets`（校验 VIP/购买后返回资产地址）
- `GET /me/library`（我的已购）

## 5. 风险与合规（必须前置）

1. **支付资质**：虎皮椒/讯虎等「免营业执照通道」存在合规与跑路风险，生产环境优先持牌通道；PayPal/Stripe 涉及跨境结算与税务。
2. **资金安全**：余额、提现、分成属于资金业务，必须实名、风控、对账与人工审核；不得把「余额」做成可自由转账的通用支付账户。
3. **内容合规**：付费图库/视频/下载需版权授权；百度内容审核只做兜底，不能替代人工巡查；未成年人付费需限制。
4. **代理登录**：一套账号多站共用会放大单点失陷影响，必须站点白名单、短票据、退出广播与异常登录告警。
5. **机器翻译**：机器翻译不得覆盖用户原创正文；只翻译界面与可翻译字段，保留原文与回退。
6. **运维栈差异**：宝塔/伪静态是 PHP 生态方案，Mim 应使用 Nginx/EdgeOne 规则、环境变量换域名、CDN 与短信供应商配置。
