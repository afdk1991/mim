## 2. 风险分级定义

| 级别 | 定义 | 判定示例 | 处置 |
| --- | --- | --- | --- |
| 阻断（Blocker） | 核心链路不可用、数据写错、越权、白屏，或发布后必然回滚 | 登录失败；`verify:routes` 出现白屏或 JS 异常；钱包扣款重复扣；非管理员可进 `#/admin/*`；秒杀超卖 | 不允许发布；需当日修复并复测 |
| 严重（Major） | 主要功能受影响但有替代路径，或跨端一致性破坏 | 某端 `copyText` 恒 false；深色模式文本不可读；缺列降级未生效导致写入全失败；移动端 860px 断点布局错乱 | 本迭代内修复；可带已知问题发布并记录 |
| 一般（Minor） | 体验/文案/样式细节，不影响主流程 | Toast 文案不一致；空态 emoji 不统一；骨架屏行数不符 | 排期修复，不阻塞发布 |

### 2.1 分级补充规则

1. **资金与库存类一律不低于「严重」，涉及金额错误或多扣即「阻断」**（`wallet_debit`、`seckill_grab`、`travel_book`、`verify_voucher`）。
2. **越权类一律「阻断」**（`AdminGate`，`src/app/admin-gate.tsx:14`）。
3. **平台契约任一条红 = 阻断**（契约是本地优先逻辑跨端成立的前提，`contract-check.ts:6-9`）。
4. 同一问题在**多个端**复现，级别上调一级。

## 7. 测试矩阵

### 7.1 平台 × 浏览器 × 屏幕

| 平台 | 载体 | 可自动化 | 现状说明 |
| --- | --- | --- | --- |
| Web(H5) | Chromium（Playwright `playwright-core`，`resolveBrowser()`） | **是（唯一）** | 已实现：L3/L7/L8 均基于此；浏览器由 `scripts/lib/browser.mjs` 解析 |
| Web(H5) | Firefox / Safari / Edge(非 Chromium) | 否 | 未安装对应驱动，未建立用例 |
| Android(Capacitor) | 真机 / 模拟器 | 否 | 无 Appium/Detox 依赖；仅能人工 |
| iOS(Capacitor) | 真机 / 模拟器 | 否 | 同上 |
| 桌面(Tauri) | 本地窗口 | 否 | 无 Tauri 端到端框架，且无 npm script |
| 鸿蒙 | 真机 / 模拟器 | 否 | 壳工程存在，无设备与脚本 |
| 小程序 | 微信开发者工具 | 否 | **无小程序工程目录** |

**诚实结论：当前可自动化覆盖的只有 Web(H5) + Chromium 一条组合。** 其余平台的「一致性」依赖平台契约测试（L2）在 Node 环境模拟四种适配器来保证，这是**能力语义层面**的覆盖，**不能替代真机渲染与手势验证**。

## 9. 执行流程

```text
开发自测：npm run typecheck && npm run test
        → 提 PR
CI（当前）：typecheck + build（见 Q-02）
QA 本地  ：npm run server:health
          npm run verify:routes          # 59 路由 0 白屏 0 异常
          npm run verify:backend         # 8 条断言（未启动则记录「未验证」）
          npm run verify:mobile 390 844  # 移动端视口
          npm run verify:desktop-regress # 桌面回归
          node scripts/verify-r6-r10.mjs # 需 DATABASE_URL
          node scripts/loadtest-v1-v8.mjs# 需 DATABASE_URL + 测试库
准出评审：对照第 5 节 X-01 ~ X-10 逐条打勾
```

### 9.1 缺陷管理约定

- 每条缺陷必须标注：级别（第 2 节）、端（web/android/ios/tauri/harmony/小程序）、复现路由或 RPC 名。
- 阻断级缺陷修复后，必须回归**同域全部用例** + 重跑 `verify:routes`。
- 平台层改动必须重跑契约测试，四端全绿方可合并。
