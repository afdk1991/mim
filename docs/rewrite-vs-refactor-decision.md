## 1. 判断依据与适用边界

### 1.1 通用决策框架（可套用到任意指定模块）

以「重写」为**例外**、「梳理」为**默认**。逐维观测，任一🔴硬门槛命中才翻转为重写。

| # | 维度 | 观测项（取证方式） | 倾向「重新开发」 | 倾向「保留结构梳理」 |
|---|---|---|---|---|
| D1 | 功能目标 | PRD / Wiki 目标 vs 用户本轮目标 | 目标被重新定义、原实现覆盖不到新目标 | 目标不变，只是实现不清晰 / 有坏味 |
| D2 | 输入输出契约 | 请求/响应字段、状态码、错误信封、URL、localStorage 键 | 契约需不兼容变更（字段语义/协议/端点全换） | 契约可逐字保持（本方案的硬约束） |
| D3 | 交互契约 | 导航、刷新/深链接、登录解锁、失效回落、跨标签页 | 交互模型整体更换（如 SPA→SSR / 多端统一路由） | 交互模型保持，仅内部实现整理 |
| D4 | 回归保护 | 契约测试、静态断言、E2E、类型检查、注释门禁 | 无任何可运行回归网，且缺陷遍布全域 | 存在可重放门禁，可作为「行为不变」的证明 |
| D5 | 缺陷性质 | 缺陷清单 / 复现步骤 | 根因在架构（数据模型、状态机、分层错误） | 根因在局部（重复逻辑、悬空引用、文档漂移、命名） |
| D6 | 耦合与沉没成本 | 依赖方数量、平台适配点、线上取证 | 依赖方少、无线上用户、无历史包袱 | 多平台 / 多端依赖，重写会牵动回退链路与部署矩阵 |

🔴 **硬门槛（命中任一即改判重写）**：
1. D1 功能目标被重新定义，且现有分层无法承载；
2. D2/D3 要求不兼容变更，且用户明确接受输入输出与交互改变；
3. D5 根因在数据模型或状态机，且 D4 无回归网（此时梳理 = 在错误结构上打补丁）；
4. 技术栈/运行时被替换（如零依赖 history 路由 → 引入路由库；SQLite → 分布式库）。

🟢 **默认结论**：其余一律「保留结构梳理」——**先冻结行为基线，再只动内部实现与口径**。

### 1.3 为什么选模块 A 作示范

1. 它是全站交互入口，「功能目标 / 输入输出 / 交互一致」三类约束最集中，最能检验框架；
2. 同一模块内同时存在「代码完整可运行」「文档口径漂移」「部分工件已缺失」三种状态，是典型分叉场景；
3. 有 35 静态断言 + 17 live 场景 + 174 契约测试，梳理过程可被证明为行为等价。
4. 若用户实际指定的是其它模块，§1.1 的框架与 §3/§5 的模板可直接复用，只需替换 §1.2 的取证数据。

### 1.4 适用边界（何时必须改判「重新开发」）

| 场景 | 触发条件 | 建议 |
|---|---|---|
| 多端统一路由 | 小程序 / App 复用同一路由模型，零依赖 history 路由无法承载 | 重新开发路由层，但**保留** URL 与 old-hash 兼容契约 |
| 引入 SSR / 服务端鉴权 | 首屏需服务端渲染与 Cookie 会话 | 重新开发；`localStorage` + Bearer 契约将不兼容，需用户签字 |
| 持久化层替换 | SQLite → 分布式库，状态机与事务语义变化 | 重新开发数据层，前端门禁层仍走梳理 |
| 缺陷在状态机 | 成片 / 生成任务状态迁移错误且无测试网 | 先补测试网再重写，不得直接裸改 |
| 用户明确接受交互变更 | 要求改导航结构、登录形态、错误文案 | 重写，并重新签输入输出基线 |
| **本轮场景** | 目标 / 契约 / 交互均不变，仅整理实现与口径 | ✅ **梳理** |

### 2.3 阶段 1 — 三处代码级梳理（完整实现，可直接执行）

#### A. 🔴 `scripts/verify-auth-gate.mjs:99-105` — 消除「文件缺失被误判为无门禁」的假阳性

**现状取证**：`site/` 已被删除（工作树 staged `D site/index.html`、`D site/prd.html`），而 `read()` 在缺文件时返回空串（`:38`），`!''.includes(...)` 恒为真 ⇒ 两条断言仍打印 `[PASS] 静态页 site/*.html 已移除门禁`（本轮实测 35/35 中的 2 条）。**校验覆盖被静默削弱**，属梳理范畴，不是功能故障。

**替换实现**（保持 35 项断言、`[PASS]` 格式、汇总行与退出码逐字不变，只把判定语义显式化）：

```js
// 静态 HTML 入口：仍存在的静态页须无门禁；缺失页面按「不存在即无门禁」显式处理，避免缺失被读成「已校验」
const gatedFiles = ['site/index.html', 'site/prd.html', 'Mim-PRD.html']; // 三份静态文档（保留清单以兼容历史 checkout）
for (const rel of gatedFiles) { // 逐个检查
  const abs = join(ROOT, rel); // 绝对路径，用于显式判定文件是否仍在仓库
  const present = existsSync(abs); // true 表示文件存在，需要真实读取内容
  const html = present ? readFileSync(abs, 'utf8') : ''; // 缺失时不读取，杜绝空串伪装成「已检查」
  const clean = !html.includes('data-auth-gate') && !html.includes('全站会话门禁'); // 门禁标记检查
  check(`静态页 ${rel} 已移除门禁`, clean, present ? '静态页门禁脚本残留' : `${rel} 不存在，按无门禁处理`); // 失败明细区分「残留」与「缺失」
} // 静态入口遍历结束
```

> 可选 B 方案：把缺失项改为显式 `SKIP` 输出 —— **会改变输出契约**（35 项 → 33 PASS + 2 SKIP），按本轮「输入输出一致」约束不采用；若用户同意输出变更再启用。
