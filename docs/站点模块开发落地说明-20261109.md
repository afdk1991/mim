# 站点模块开发落地说明（2026-11-09）

## 0. 结论与依据边界

- **本轮任务性质**：用户给出 45 类「主机记录 + 备注」，要求「整个项目……开发对应的模块和功能等等」。与上一轮（[站点入口契约落地说明](./站点入口契约落地说明-20261109.md)）不同：**上一轮只登记契约并标记 43 类未决；本轮按用户新指令真正开发模块与功能**，因此「不引入额外功能 / 不大范围重构」的旧护栏由本轮指令取代。
- **唯一备注依据**：用户 2026-11-09 消息正文（45 类备注，每条重复两次）+ 同消息所附 DNSPod「备注」列截图。经逐字比对，与项目内 `dnspod_records_2026-11-05_21-42-26.xls` 的 **`mixm.top` 工作表第 4–93 行**（每类两行：短主机记录 + 全限定域名）完全一致，45/45 零漂移。
- **主机记录依据**：消息开头两行 `@` 对应 `mixm.top` 第 2–3 行（备注为空）；45 类的短/全主机记录取自同一工作表（该列未被清空）。
- **关键事实（决定实现形态）**：45 类备注全部是「入口描述｜系统名」两段式标签，**没有功能规格、输入输出、交互流程或行为约束**；`记录类型 / 记录值 / MX优先级 / 权重 / 状态 / 最后操作时间` 6 列仍为空。因此本轮的功能点（capabilities）与业务条目模型是**按系统名语义派生的最小可运行实现**，属实现推导，不是备注原文；所有演示数据均明确标注为非真实业务数据。
- **未做 DNS 层**：未改 nginx / DNS / 域名解析、未新建 46 个子站实例。备注只描述「入口｜系统」，清空的记录值列无法提供解析目标；本轮把 45 个系统落成**项目内可运行的模块**（共享注册表 + 后端 API + 数据库 + 前端视图），而非 45 个独立站点。
- **未引入新第三方依赖**：全部复用现有 React 18 / Vite 6 / Express 5 / zod / better-sqlite3 / vitest / supertest。铁律五不适用（无新通用能力需求）；依赖清单与 `pnpm-lock.yaml` 未改动。
