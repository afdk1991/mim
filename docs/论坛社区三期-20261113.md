## 三、能力与端点

### 1. 关注后可见（followers 板块）
- 既有 `community_board_follows` 关注关系表与 `POST /community/boards/:slug/follow`（关注 / 取关开关）保留；`hasBoardAccess` 统一校验付费门槛与 followers 关注关系。
- 列表：未关注用户只返回摘要（`summary`），不返回正文；详情未解锁时 `body=''`、`locked=true`、媒体与回复隐藏。
- 付费板块（`price_cents > 0`）准入：已加入 / VIP 有效；付费帖允许单独购买解锁，不强制先加入板块，免费内容仍受板块会员门槛约束。

### 2. 发帖频率 / 数量限制
- 三层配额，按 用户 + 板块：
  1. 滑动窗口：最近 N 分钟内最多 M 帖；
  2. 每日配额：UTC 自然日上限；
  3. 累计配额：历史总量上限。
- 超限返回 `429 RATE_LIMITED`，响应头 `Retry-After` 为建议退避秒数，`details.reason` 为 `WINDOW | DAILY | TOTAL`，`details.retry_after` 同值。
- 板块列配置优先；为 `0` 时回落环境变量全局默认，再回落内置默认（10 分钟 / 5 帖 / 每日 20 / 累计 200）。
- 版主可调：`PUT /community/boards/:slug/config`（`rate_window_minutes / rate_window_max / daily_max / total_max / post_min_level`）。

### 3. 创建板块限制与审核队列
- 门槛：VIP 或等级 ≥ 阈值（默认 Lv.5）；每人可建数量上限（默认 3）。
- 校验：`slug` 唯一；名称大小写 / 去重后唯一；本地受限词命中拒绝；`visibility` 支持 `public | followers | paid`，`paid` 落库为 `public + price_cents > 0`，未定价拒绝。
- 审核开关开启时新板块进入 `pending`，不出现在公开列表（创建者本人可见自己的待审核板块）；运营队列与处置：
  - `GET /community/boards/pending`（运营）
  - `POST /community/boards/:slug/approve`（上架）
  - `POST /community/boards/:slug/reject`（驳回，可带 `note`）
  - `GET|PUT /community/review-setting`（审核开关读写）

### 4. 论坛设为首页
- `GET /community/home-setting`（公开）：返回 `{ home: 'community' | 'portal' }`。
- `PUT /community/home-setting`（运营）：写入首页指向；落库沿用既有 `site_settings.home.view`（`community | store`，`portal` 即既有商城门户），与 `/site/config` 公开配置保持一致。
- 本包只提供权威配置；前台实际渲染由前端包消费。

### 5. Tab 栏目模块化组合
- 缺省清单：`latest 最新 / hot 热门 / recommend 推荐 / rating 评分 / favorites 收藏`，各自带排序口径与顺序。
- `GET /community/boards/:slug/tabs`（公开）：缺省清单 + 板块持久化覆盖合并后返回。
- `PUT /community/boards/:slug/tabs`（版主 / 创建者）：全量保存栏目顺序、显隐与排序口径；未知栏目 / 未知排序口径拒绝。

### 6. 推荐指数与排序
- `recommend_score = (浏览×w_views + 回复×w_replies + 收藏×w_favorites + 评分项×w_rating) × 半衰期衰减`；评分项为 `max(0, 平均分-1) × 评分人数`。
- 权重来源优先级：环境变量 JSON 覆盖 > `site_settings` 持久化 > 内置默认（views 1 / replies 3 / favorites 5 / rating 4 / 半衰期 7 天）。
- 发帖 / 回复 / 点赞 / 收藏 / 评分 / 浏览后回写分数；列表 `sort=recommend` 按 `recommend_score` 倒序。
- `GET /community/recommend-weights`（公开）读取生效权重与默认值；`PUT /community/recommend-weights`（运营）持久化调整。
- `sort=rating`（评分）、`sort=favorites`（收藏）排序口径在本包回归覆盖。

## 八、商城积分抵扣

### 结算顺序
`商品原价 amount = price × quantity` → 优惠码抵扣 `couponDiscount` → 积分抵扣 `computeDeduction` → 余额扣款 / 线下转账。积分段入参为优惠码之后的金额 `afterCoupon`；未开启抵扣时走零抵扣兜底，应付等于 `afterCoupon`。

### 入参与响应字段
- 请求新增（既有字段不变）：
  - `use_points: boolean`：是否使用积分抵扣；
  - `points_to_use: number`：指定消耗积分（正整数）；缺省按可抵扣上限最大化。
- 下单响应在既有 `order_id / payable_cents / discount_cents / delivery_kind` 之后**追加**：
  - `points_spent: number`：实际消耗积分；
  - `points_deduct_cents: number`：折抵金额（分）。
- `GET /shop/orders` 列表 SELECT 同步回显 `points_spent / points_deduct_cents`。

### 事务与留痕
- 积分扣减（`deductPoints`，流水 `refType='shop_order'`）、订单落库、余额扣款（`payable > 0` 才 `debit`）在同一事务内，任一失败整体回滚；`points_spent = 0` 时不写积分流水。
- `shop_orders` 留痕列（`ALTER_ADD:`，列已存在自动跳过）：
  - `points_spent INTEGER NOT NULL DEFAULT 0`
  - `points_deduct_cents INTEGER NOT NULL DEFAULT 0`
- 推广分成佣金基于抵扣后 `payable` 计算。

### 全额抵扣即时完成
- 抵扣后 `payable = 0` 时不调余额扣款；`virtual_auto` 商品仍即时分配卡密、状态 `delivered`、`paid_at` 落库，不生成待支付死单。

### 四类边界断言
1. **单笔上限百分比截断**：积分充足时抵扣额受 `maxRatioPercent` 上限截断，超出部分仍走余额；
2. **积分余额截断**：余额不足时按余额可折金额截断，不报错；
3. **指定积分不足**：400 `INSUFFICIENT_POINTS`，不生成订单、不扣积分（details 带 `balance / requested`）；
4. **指定积分超单笔上限**：400 `POINTS_CAP_EXCEEDED`，不生成订单（details 带 `max_deduct_cents / requested_cents`）；
5. **开关关闭**：`MIM_POINTS_DEDUCTION_ENABLED=0` 整段跳过，积分不动、应付不变。

## 九、发帖审核与验证码

- 发帖、回复、板块名 / 简介均经 `auditText` 本地审核（provider=none 默认放行）；回复路径既有审核覆盖保持不变。
- 发帖端点挂 `verifyCaptcha(db, env, 'post', rawBody)`：`MIM_CAPTCHA_MODE=off` 或场景未强制时为空操作直接放行；image 模式读取原始请求体的 `captcha_id` / `captcha_code`（或 `id` / `answer`），一次性消费校验。验证码字段在 zod 解析后会被剥离，故校验读取原始 `req.body`，解析后的 `body` 继续供业务使用。
