## 3. 异常项与处置建议

### 3.1 `data.mixm.top`（EdgeOne Pages）——DNS 目标域失效，入口整体不可用

- `Resolve-DnsName data.mixm.top -Type CNAME` **能查到** CNAME → `data.mixm.top.pages.dnsoe5.com`（TTL 10）；
- 但该 CNAME **目标** 在默认 DNS 与 `8.8.8.8`（`dns.google`）下均为 `Non-existent domain`，因此 `data.mixm.top` 无 A 记录、全链路 NXDOMAIN；
- 本机 000 与 CI 000 一致，确认不是本地网络问题。
- **判断**：EdgeOne 侧为该自定义域分配的 CNAME 目标已被回收 / 变更（与 2026-11-11 项目名迁移到 `mim` 的时间点吻合），而 DNSPod 记录仍指向旧目标。
- **处置**：EdgeOne Makers 控制台 → 项目 `mim` → 域名管理，复制当前分配的 CNAME 目标；在 DNSPod 更新 `data` 主机记录；随后复测。本轮为只验证不擅改线上 DNS，未执行。

### 3.2 `mim-i3ywsdfn.cloud.sealos.io/health`（Sealos）——双出口 000

- DNS 正常：`34.87.102.86` / `34.126.135.140` 等 GCP 新加坡段可解析；
- 本机 curl：TCP 建连后 TLS 握手被 `Connection was reset`（exit 35）；CI 为 000 / 0.46s；
- **判断**：不是域名解析问题，属服务 / Ingress / 实例侧不可用（免费实例停摆或被回收的可能性最高）；
- **叠加事实**：仓库 secrets 无 `SEALOS_KUBECONFIG/SEALOS_DOMAIN/SEALOS_NAMESPACE/MIM_JWT_SECRET`，CI Sealos 步骤长期 `SKIP`，线上为历史旧版本。**处置**：需 Sealos 控制台核查实例与 Ingress；补齐 secrets 后由 CI 重新发布。

### 3.3 IGA Pages——登记入口 `preview.iga-pages.com` 本身不存在

- `preview.iga-pages.com`、`iga-pages.com` apex 均无 A 记录（本机与 CI 双 000）；
- 实测真实预览域为 **`mim.preview.iga-pages.com`**（与 `fr95fuwu57.preview.iga-pages.com` 同解析到 `115.231.191.209`），返回 **401 / 2413B**（IGA 预览访问保护要求口令 / `iga_token`）；
- 即：站点在线，但登记在注册表里的 `entry_url` 写错了。已在 `deploymentRegistry.json` 修正 `entry_url` 并记录 401 结果。**遗留**：`~/.iga/auth.json` 刷新令牌失效，需重新 `iga login` 才能取项目详情。

### 3.4 `mim-store.15726833367.workers.dev`（独立 Worker）——根路径 404

- CI 出口可达：`404 / 17B / 0.09s / 172.67.150.222`（Cloudflare 边缘）；
- 本机因 `*.workers.dev` DNS 污染（解析到 `31.13.88.26`）无法取证；
- **判断**：Worker 本身在跑，但没有为根路径注册路由 / 未返回内容。**处置**：确认该 Worker 预期入口路径（若只服务 `/store` 等子路径，应在注册表登记真实路径而非根域）。

### 3.5 Vercel 产物滞后

- CI 实测 200 但 **5182B**，其他静态站为 **5305B**（同一轮构建），说明 Vercel 上仍是较早产物；
- 根因即 CI 步骤 `SKIP: 缺少 VERCEL_TOKEN`（从未由 CI 真发）。**处置**：补 `VERCEL_TOKEN / VERCEL_ORG_ID / VERCEL_PROJECT_ID` 后重跑，或控制台手动重部署。
