# 入口目录业务条目批量建库：44 模块 × 3 能力 = 132 条（2026-11-12）

## 1. 指令与口径

> 按模块批量建：44 个模块 × 3 个能力（清单 / 管理 / 记录）各 1 条 → 132 条真实条目，逐模块读回核对。

- 页面：`https://mim.mixm.top/entry-catalog`（`Sites.tsx`，数据源 `packages/core-domain/src/siteModules.json`）
- 写入端点：`POST /api/v1/sites/:host/items`（`host` 取模块的 `entryKey`，如 `PORTAL_ROOT`），中间件 `requireAuth + idempotency`
- 会话：访客会话 `MIM-10000033`（匿名可免登录领号，写操作凭 Bearer 令牌；每条写请求独立 `Idempotency-Key`）
- 幂等与去重：脚本按「同模块同标题已存在则跳过」，可重复执行不产生重复行

## 2. 条目口径

每个模块按自身 3 个功能点顺序映射到 3 个能力：

| 能力编码 | 能力名 | 条目标题 | 初始状态 | 可流转 |
|---|---|---|---|---|
| `catalog` | 清单 | `<系统名>｜<功能点 1>` | `active` | `active → archived` |
| `manage` | 管理 | `<系统名>｜<功能点 2>` | `pending` | `pending → active → archived` |
| `record` | 记录 | `<系统名>｜<功能点 3>` | `pending` | `pending → done → archived` |

条目说明统一为：`模块：<业务域> / <系统名>（入口 <entry>，DNSPod 行 <rows>）。能力：<能力名>（code）。负责：<inScope>。边界：<outOfScope>。`

示例（MALL_B2C）：

- `[catalog] active` · `B2C 官方商城系统｜B2C 商品目录、详情与搜索`
- `[manage] pending` · `B2C 官方商城系统｜购物车、下单与订单状态`
- `[record] pending` · `B2C 官方商城系统｜自营库存与价格管理`

## 4. 影响面

- **仅数据写入**，未改动任何代码：`siteModules.json` 未动（44 模块 / 132 功能点口径不变），接口契约与前端视图未变。
- 页面表现：每个模块由「3 个功能点 · 2 条记录」变为「3 个功能点 · 5 条记录」（`PORTAL_ROOT` 为 6 条），展开即可看到 3 条真实条目并可逐条推进状态。
- 数据落在生产库（`https://mim.mixm.top`，SQLite WAL），随部署持久化；无新增依赖、无版本号变更（非功能模块增删）。

## 5. 复现方式

一次性脚本 `node .tmp-seed-catalog.mjs`（执行后已删除，不入库）：领访客会话 → 遍历 44 模块 → 按模块能力建 3 条（同标题跳过）→ 逐模块 `GET /sites/:host/items` 回读统计 `total / real / perCap` → 汇总 `CREATED / MODULES_WITH_3_REAL`。运行日志留档 `%TEMP%\seed-catalog-backup.log`。
