| 竞态处理（第二轮补丁） | run `43068721652` 实测到一次真实竞态：CI 检出 `f786d2a` 期间，另一并发进程把 Gitee 推到 `24b9485`（已包含 `f786d2a` 及后续提交），`git push` 被按「非快进 / 远端含你没有的提交」拒绝 → 该步骤报红。补丁逻辑：push 失败后 `git fetch` 远端分支，若 `git merge-base --is-ancestor HEAD FETCH_HEAD` 成立（远端已包含本次提交）→ 判为已同步并 `exit 0`；仅当真分叉（远端不含本提交）才 `::error::` + `exit 1`，**绝不强推**破坏远端历史 |
| YAML 校验 | `python -c "import yaml; ..."` → `jobs: ['verify','deploy','pages','packages','platforms']`、`platforms` 末步 = `Gitee 镜像同步` |
| 提交 | `cf13458`（`ci: 托管平台同步作业内新增 Gitee 镜像自动推送`) |
