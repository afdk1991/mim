## 1. 判定口径（先看这里，否则会误读表格）

1. **平台适配层只承认 4 种 kind**：`web | mock | capacitor | miniprogram`（`src/platform/types.ts:14`）。
   因此 **桌面（Tauri）与鸿蒙目前没有独立适配器**，运行时被 `detectPlatformKind()` 判为 `web`（`src/platform/index.ts:29-34`），复用 `webStorage / webEnv / webHttp`（`src/platform/web.ts`）。
   表中这两列标注的「同 Web」是**代码事实**，不是能力承诺；一旦原生能力接入，必须新增 kind 并补契约测试。
2. **Capacitor 的 Android 与 iOS 共用一个适配器**（`src/platform/capacitor.ts:48`），二者在当前代码里**没有任何分支差异**，差异只来自宿主系统本身（如 iOS 不能用 APK 安装）。
3. **小程序只有适配层，没有工程目录**：仓库根目录不存在 `miniprogram/`、`mini-program/` 等真实小程序工程（已 `ls` 核实），仅有 `src/platform/miniprogram.ts` 与 `tests/platform-contract.test.ts` 里的假 `wx` 注入。因此小程序列的「预期」为设计目标，「当前状态」一律为**未落地**。
4. 三态能力判定统一为「返回 boolean」：本层不做 toast、不抛异常，由调用方决定降级文案（`src/platform/types.ts:45-51`）。

## 3. 关键降级细节

### 3.1 令牌落地位置（跨端一致，但非安全存储）

```ts
// src/data/session.ts:58 —— 令牌由会话层注入，最终由 core/http.ts 加进 Authorization
setTokenProvider(() => (current.token ? current.token : null))

// src/core/http.ts:57-61
if (opts.auth !== false) {
  const token = tokenProvider()
  if (token) headers.Authorization = `Bearer ${token}`
}
```

- 会话持久化键为 `mim.session`（`src/data/session.ts:16`），经 `readJson/writeJson` → `getPlatform().storage`，即 **localStorage / `wx.setStorageSync`**。
- 因此：**换端不换行为**，但也意味着**所有端都没有使用系统安全存储**，令牌可被同机其他脚本或越狱环境读到。列为合规与安全的待办项，不在本文件承诺修复。

### 3.2 物理返回键缺口

- `package.json:36` 已声明 `@capacitor/app@^8.1.2`，但 `src/` 下检索 `capacitor/app`、`App.addListener`、`backButton` **零命中**。
- 现状推断（未真机实测，标记**待核实**）：Android 物理返回键按 WebView 默认行为处理，多级页面可能直接退出应用而非回退一级。

### 3.3 小程序网络通道约束

```ts
// src/platform/miniprogram.ts:142-165
request(method, url, opts) {
  if (!wx?.request) return Promise.resolve({ ok: false, status: 0, text: '' })
  return new Promise((resolve) => {
    wx.request!({ url, method, header: opts.headers, data: opts.body, timeout: opts.timeoutMs, ... })
  })
}
```

- 小程序要求 **request 合法域名白名单 + HTTPS**，自托管后端域名必须提前在小程序后台登记，否则真机请求直接失败（返回体与 `offline` 无法区分，前端会显示「后端未配置或网络不可达」）。
- 适配层把 `opts.body`（已是 JSON 字符串）直接赋给 `wx.request.data`，小程序会按字符串透传；若后端 `Content-Type: application/json` 解析异常，需在此处改为 `JSON.parse(opts.body)`。此项**待真机核实**。

### 3.4 通知能力现状

- 前端仅有站内通知（REST 表 `notifications`，`server/src/rest.js:41`）。
- `android/app/src/main/AndroidManifest.xml` 声明的权限仅 `INTERNET` 与 `REQUEST_INSTALL_PACKAGES`，**无 POST_NOTIFICATIONS**；iOS `Info.plist` **无** `NSUserNotificationsUsageDescription`；鸿蒙 `module.json5:15-18` 仅 `ohos.permission.INTERNET`。
- 结论：全端**当前不具备系统通知能力**，也不需要在隐私政策中声明通知权限（若后续接入需同步更新合规清单）。
