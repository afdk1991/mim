# 自研算法模块：搜索排序与社区热榜（2026-11-19）

> 版本：`0.0.13`（展示 `V0.0.13-preview`）｜通道：`preview`
> 代码位置：`services/mim-api/src/algorithms/`（6 个纯函数文件）+ `services/mim-api/src/routes/community.ts`（接入层）

## 1. 为什么自研，而不是换第三方库

铁律五要求「优先引入成熟第三方依赖」，本轮是**明确的例外**，理由如下：

| 候选方案 | 不采用的原因 |
|---|---|
| Meilisearch / Elasticsearch | 需要独立实例与索引同步（项目已有可选 Meilisearch 接入但要求外部服务），社区站内小规模检索用它等于为 17 条帖子维护一套集群；且线上未配置实例时仍要降级到 SQLite |
| `nodejieba` / `segmentit` 等中文分词库 | 依赖词典文件与原生编译（Windows 本机与 CI 多平台都要重新编译），分词结果随词典版本漂移，线上与本地难以逐位对账 |
| `natural` / `flexsearch` 等 JS 库 | 体积与 API 面相对于本项目所需的三件事（中文二元切分、BM25、MMR）过重，且无法按项目字段权重（标题 3 / 摘要 2 / 正文 1）与中文停用字自定义 |

本轮要解决的是**确定性、可单测、零外部服务**的站内排序，因此自研纯函数族更合适：每个函数输入输出完全确定，测试可直接断言数值，不引入任何运行时依赖。

## 2. 算法清单与公式

### 2.1 文本归一化与分词（`text.ts`）

- `normalizeText`：全角转半角（`0xFF01–0xFF5E` 平移、`0x3000` → 空格）、统一小写、空白压缩。
- `tokenize`：
  - CJK（主区 `4E00–9FFF`、扩展 A `3400–4DBF`、兼容区 `F900–FAFF`）按连续串取**相邻二元词**，孤立单字保留（非停用字）；
  - 拉丁/数字按连续串成词，去所有格 `'s`、`ies→y`、`es`、`s` 轻量归一；
  - 中文停用字 25 个、英文停用词 27 个直接丢弃。
- `termFrequency` / `jaccard` / `tokenSet`：词频、集合交并比、词项集合。

示例：`tokenize('漫剧工作台')` → `['漫剧','剧工','工作','作台']`。

### 2.2 BM25 相关性（`bm25.ts`）

```
idf(t) = ln(1 + (N − df(t) + 0.5) / (df(t) + 0.5))
score(D,Q) = Σ_{t∈Q} idf(t) · [ tf(t,D)·(k1+1) / ( tf(t,D) + k1·(1 − b + b·|D|/avgdl) ) ]
```

- 默认 `k1 = 1.2`、`b = 0.75`；
- 字段加权：标题 3、摘要 2、正文 1（权重直接放大词频与文档长度，保证长正文不会靠字数压过标题）；
- 查询词去重，不重复累加；分数四舍五入 4 位；同分按 `id` 升序，保证排序稳定；
- 空查询/空文档集：全 0 分并保持输入顺序，调用方可安全降级。

### 2.3 时间衰减热度（`heat.ts`）

```
engagement = 3·likes + 5·replies + 6·favorites + 0.3·views
heat = engagement / (ageHours + 2)^1.5
```

- 回复与收藏创作成本最高 → 权重最大；浏览最廉价 → 权重最小；
- 常数 `+2` 防止刚发布内容除零爆炸；
- 重力指数 1.5，年龄翻倍时热度衰减约 2.83 倍。

### 2.4 MMR 多样性重排（`mmr.ts`）

```
next = argmax_{i∈R} [ λ·rel(i) − (1−λ)·max_{j∈S} sim(i,j) ]
```

- 默认 `λ = 0.7`；`λ=1` 退化为纯相关性排序；
- 相似度夹到 `[0,1]`，同分按输入顺序，**不修改入参**；
- 复杂度 `O(n²)`，只用于单次请求的候选窗口（≤200），不做全库排序。

### 2.5 综合排序分（`rank.ts`）

```
decay(ageDays) = 0.5^(ageDays / halfLifeDays)        // 默认半衰期 7 天
blend = relevance·decay + 0.02·ln(1 + 2·likes + 3·replies)
```

相关性决定相关性、半衰期让老帖自然退场、对数互动项做小幅微调（不会让大数霸榜）。

## 3. 接口变化

### 3.1 `GET /api/v1/community/search`（行为升级，字段兼容）

| 参数 | 默认 | 说明 |
|---|---|---|
| `q` | 必填 | 关键词，≤ 由原有校验约束 |
| `board` | 空 | 板块 slug 过滤 |
| `limit` / `offset` | 20 / 0 | 上限 50 |
| `sort` | `relevance` | `relevance` 走自研排序；`latest` 回到「按最后活跃时间」旧口径 |
| `diversify` | `0` | `1` 时追加 MMR 多样性重排（同板块相似度 0.9，否则标题词项 Jaccard） |

响应新增：`items[].relevance`（相关性分，`latest` 分支为 0）、`sort`、`diversify`、`candidate_limit`。
`total` 仍是**全量 LIKE 命中数**；相关性排序在候选窗口（200 条，按最后活跃时间取）内进行，超出窗口的深翻页只有 `sort=latest` 能覆盖到——这一点在响应里以 `candidate_limit` 显式暴露，不隐藏。

### 3.2 `GET /api/v1/community/trending`（新增，匿名可读）

- 参数：`limit`（默认 10，夹到 1–50）、`board`（可选板块 slug）；
- 候选窗口 200 条（`status='published'`，按最后活跃时间取）；
- 返回：`items[]`（帖子摘要字段 + `heat` 热度分）、`limit`、`algorithm: 'heat-v1'`、`window: 200`；
- 已加入社区路由的匿名读白名单（`^/api/v1/community/trending$`），与搜索一致：只读、无个人数据。

## 7. 仍存的边界

- 相关性排序是「候选窗口内全量打分」而非倒排索引：窗口上限 20000 条以内可任意深翻页，超过窗口的超大表需分片或落倒排索引表（当前社区数据量远低于该量级）。
- `latest` 分支的 `relevance` 恒为 0，前端已按 `sort` 字段决定是否展示相关度。
- 分词为确定性二元切分，不做同义词扩展与纠错；错别字查询命中率与 `LIKE` 等价，不会更高。
