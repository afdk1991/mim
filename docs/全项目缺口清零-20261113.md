## 二、本轮真正补上的缺口（9 项）

1. **独立商城 shop 结算积分抵扣**：`POST /shop/orders` 接入 `computeDeduction` + 同事务 `deductPoints`，顺序「原价 → 优惠码 → 积分抵扣 → 余额」，全额抵扣即时完成；6 例边界测试。
2. **独立「圈子」模型**：4 张表 + 12 个端点 + 前端视图；与板块彻底分离（圈子是成员制社群，板块是内容分区），18 例测试。
3. **三款自研工具可执行实现**：25 例测试 + 真实运行证据（安装脚本 `bash -n`、换域名 diff、WAF 拦截日志）。
4. **CDN 回源缓存契约 + 主动刷新适配 + 线上探测脚本**：实测生产未接 CDN，如实输出 `not-detected`。
5. **验证码强制开启回归**：image/slider/off 三模式 7 例，含「一次性码二次使用拒绝」。
6. **内容运营独立权限点 `content:write`**：`db.ts` 种子 + 域 SQL，双权限兼容期不断管理入口。
7. **SSRF 全链路**：AI 厂商 baseUrl 配置来源校验 + 上游返回图片/视频 URL 受控拉取，19 例。
8. **访客频控迁出进程内 Map**：`guest:${ip}` + 3600s TTL，配 Redis 多副本一致。
9. **首屏体积**：入口 194 kB → **48.94 kB**；echarts/g6 拆为独立懒加载包。

## 七、P0 事故与修复：存量库升级导致生产 API 502（2026-11-13 19:47–20:05 CST）

**现象**：`c1a44de` 推送后 Deploy 作业「远程发布」步骤失败（服务器侧 `deploy.sh` exit 1），`https://mim.mixm.top/api/v1/*` 与 `/health` 全量 502，nginx 上游 `127.0.0.1:8787` 无监听。CI 其余四个作业（质量门禁 / ghcr / Pages / 托管同步）全绿，故障与测试无关，属**仅在生产真实数据上才出现**的升级缺陷。

**根因（已复现，非推测）**：`07-content.sql` 给公告表加了 `published_at`，但只写在 `CREATE TABLE IF NOT EXISTS announcements` 的列定义里；生产库是老库，该语句是空操作，列不会被补出来。随后同一脚本的种子 `INSERT ... (published_at, starts_at, ...)` 显式引用该列 → 启动初始化抛 `SQLITE_ERROR: table announcements has no column named published_at` → `mim-api` 进程退出 → nginx 502。原有 667 例测试全部建**全新库**，升级已有库这条路径从未被测到。

**复现方式（本地可重跑）**：用上一版本（`0d45090`）的 `schema.sql` + `schema.d/*.sql` 造出「存量库」，再用当前 `createDatabase()` 打开它；修复前稳定得到同一句报错，修复后输出 `[db] domain schema applied: announcements.published_at, shop_orders.points_spent, shop_orders.points_deduct_cents` 并成功返回。

**修复内容**：
1. `schema.d/07-content.sql` 顶部补 `ALTER_ADD: announcements.published_at TEXT`——老库补列，新库由 `CREATE TABLE` 自带该列。
2. `src/db.ts` 的 `applyDomainSchema` 增加两条健壮性：
   - 指令行指向「本脚本自己新建的表」且表尚不存在时跳过（新库先遇指令、后建表的时序问题），指向其它表名仍直接报错，不放过真写错；
   - `body.split(/\r?\n/)` 与 `ALTER_ADD_RE` 末尾 `\s*$`，修掉 CRLF 检出时指令行漏匹配、进而 `exec` 报 `near "ALTER_ADD": syntax error` 的环境差异。
3. 新增 `test/upgrade-path.test.ts`（2 例）：把新库退化成老库形状（删 `published_at` / `shop_orders` 两列 / 删 `circles*`、`cdn_purge_audit`、`promotion_conversions` 表）后重开，断言列与表被补齐、公告种子 ≥3 条、`content:write` 已授超管，并验证二次重开幂等不重复补列。**这条用例是本轮唯一能拦住本次事故的测试类型。**

**门禁复跑**：`pnpm -r typecheck` exit 0；`@mim/api test` **56 文件全过**；`comment-check --strict` PASS；`gap-scan` exit 0。

**教训（写入流程约束）**：任何「给既有表加列 + 同脚本种子引用该列」的改动，必须在同一脚本写 `ALTER_ADD`，且必须补一条老库升级复现用例；只跑全新库测试会把这类缺陷 100% 漏到生产。
