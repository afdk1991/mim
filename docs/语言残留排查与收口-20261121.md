# 全站非中文文案排查与收口（2026-11-21）

> 背景：用户反馈「整个项目存在语言不是中文」。本轮对前台 `apps/web`、后台 `apps/admin`、后端 `services/mim-api`
> 做双向取证（线上生产 + 源码静态扫描），区分三类英文出处，避免误删项目设计内的中英双语能力。
> 生产入口：Mim 前端 `https://zy.laal.top/`、后台 `https://zy.laal.top/admin/`、API `https://api.laal.top/api/v1`；
> 裸域 `https://laal.top` 是同机另一套 WordPress（zibll）站点，**不属于 Mim，本轮未触碰**。

## 1. 语言架构与判定口径

项目自带 `@mim/i18n` 双字典（`zh-CN` / `en-US`），语言优先级：已登录账号 `user.locale` > 后台站点选项
`default_locale` > 默认中文（`DEFAULT_LOCALE='zh-CN'`）。绝大多数视图用 `tr(locale, zh, en)` 本地助手、
`isZh/isEn/zh ?` 三元或 `{zh, en}` 字典表分流，**英文仅在 en-US 渲染，属合法设计内分支**，本轮不改动。

排查把英文出处分为三类：

1. **设计内英文分支**：`en-US` 才显示的字典英文条目、英文 ternary 分支 —— 保留。
2. **中文界面下写死英文的残留**：不随语言切换、直接进界面或错误面板的英文字面量 —— 本轮收口。
3. **服务端下发的英文错误提示**：后端 `AppError` / Zod refine / 信封 `message` 英文原文，经前端错误展示回显 —— 见 §4 遗留工作包。

## 2. 本轮已收口的前端残留（5 个源文件）

| 文件 | 位置 | 改动 |
|---|---|---|
| `apps/web/src/views/Community.tsx` | 社区眉题 | `MIM COMMUNITY` 写死 → `{locale === 'en-US' ? 'MIM COMMUNITY' : '社区互动广场'}`，英文界面保留装饰小标 |
| `apps/web/src/views/CommunityAssets.tsx` | 资产页眉题 | `MIM ASSETS` 写死 → `{isZh ? '付费资产专区' : 'MIM ASSETS'}`；同步更新上方注释 |
| `apps/web/src/views/PaymentReturn.tsx` | 回跳缺意图错误 | `setError('missing intent')` 写死英文 → `locale === 'en-US' ? 'Missing payment intent' : '缺少支付意图编号'` |
| `apps/admin/src/views/CommunityAdmin.tsx` | 标签页配置文本框 | 标签 `Tab JSON` → `标签页配置（JSON）` |
| `apps/web/src/api/request.ts` | `errorText()` 错误文案兜底 | 中文界面只回显**已是中文（含 CJK）**的服务端原文；历史遗留英文 `message` 不再透出，回落错误码对应的中文翻译。英文界面行为不变 |

`errorText()` 兜底规则说明：原有逻辑在中文界面优先回显服务端原文，以保留「余额不足」「不能转给自己」
「卡密已被使用」等具体原因；本轮增加 CJK 判定，**已是中文的服务端具体原因照常回显**，仅把非中文的 legacy
英文提示替换为错误码中文文案。前端无任何按 `.message` 文本做 `===` / `includes` / `startsWith` 分支判断的逻辑，
文案调整不会影响流程分支。

## 3. 取证后判定「保留英文」的范围（非残留）

- **设计内 en-US 分支**：`lib/messages.ts`、`lib/release-notes.ts` 的 `changesEn`、`Login.tsx` 的 OAuth 错误
  `[中文, 英文]` 表与各 `isZh ? … : …` 三元、`MyAssets/CommunityAssets` 的 `KIND_LABEL` 字典等，英文仅在英文界面渲染。
- **品牌与专有名词**：`Mim`、`VIP`、`QR`、`GitHub`、`Alipay`、`WeChat Pay`、`Manual transfer` 渠道英文名、
  第三方平台名等，按品牌保留。
- **枚举 / 键名 / 技术标识**：CSS 类名、路由段、MIME、URL、SVG 路径、`info/warning/success/danger` 严重度键、
  `cn/global/pending` 等枚举值、TypeScript 类型注解（`Promise` / `Record` / `void` / `Set` 等）。
- **种子 / 演示内容**：`MIM-DEMO-100` 等演示编号、种子内容标题中的英文，属数据而非界面文案。
- **后端内部诊断 `throw new Error(...)`**：不回传客户端，保留英文（如 `cache.ts` redis 已关闭、`auth.ts` JWT
  payload 缺字段、`notify.ts` 短信上游发送失败）。

## 4. 后端英文错误提示批量中文化（路线 A，已完成）

### 4.1 处置范围

回传客户端的英文 `message`（`new AppError('CODE', 'English msg')`、Zod `.refine({message})`、
信封 `message:` 字段、404/非法 JSON/500 兜底信封）已全部译为中文，覆盖 `services/mim-api/src/` 下 31 个源文件：

`auth.ts`、`commerce/points.ts`、`commerce/price-batch.ts`、`commerce/vip-pricing-admin.ts`、
`federation.ts`、`growth/service.ts`、`identity.ts`、`invitations.ts`、`middleware.ts`、
`oauth/accounts.ts`、`oauth/client.ts`、`realname.ts`、`routes/admin.ts`、`routes/auth.ts`、
`routes/community.ts`、`routes/content-ops.ts`、`routes/deployments.ts`、`routes/federation.ts`、
`routes/invites.ts`、`routes/me.ts`、`routes/media.ts`、`routes/oauth.ts`、`routes/orders.ts`、
`routes/shop-admin.ts`、`routes/sso.ts`、`routes/vip-pricing.ts`、`security.ts`、`sso.ts`、
`storage.ts`、`utils.ts`。

### 4.2 同步的测试断言

- `test/rbac.test.ts`：11 处断言英文 `body.message` 的用例同步改为中文文案。
- `test/commerce-points.test.ts`：2 处 `toThrowError(/英文/)` 正则断言同步改为中文片段。
- 其余后端测试只断言 `.status` / `.body.code` / 枚举键 / 内容字段，不断言错误 message 文本，无需改动。

### 4.3 保留未译的范围

- **内部诊断型 `throw new Error(...)`**：不回传客户端，保留英文（`cache.ts` redis 已关闭 / URL 非法、
  `auth.ts` JWT payload 缺字段、`db.ts` 迁移标识符、`notify.ts` 短信上游发送失败等）；未知异常由
  错误处理层归一为通用中文信封，不泄漏内部堆栈或英文诊断。
- **英文界面（en-US）**：错误码翻译表 `@mim/i18n` 仍提供英文文案；后端 message 现为中文，英文界面
  以前端错误码翻译为准，服务端中文原文不强制透出。
- **后台 `describeError()`**：仍按 `${code}: ${message}` 原样透出；后端 message 已中文化，中文控制台不再
  出现 legacy 英文提示。非 JSON 的 5xx 兜底串 `request failed with status …` 属极少数网络异常边缘路径，保留。
