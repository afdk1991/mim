# 免登录体验：全站「此功能需登录后使用」门禁解除（2026-11-12）

## 1. 需求与结论

用户要求：解除 `F:\合并项目\Mim` 项目中所有「此功能需登录后使用」的限制。

**落地结论**：全站改为**免登录体验（guest session）**模型——不是删掉鉴权，而是让每个匿名访客在进入站点时**自动获得一个真实可用的访客会话**。
因此商城下单、购物车结算、个人中心、聊天收发、漫剧创作工作台、站点模块写操作全部按「已登录」路径工作，界面上不再出现任何登录门禁；`/signin` 只承担「把访客升级为正式账号」的职责。

选择该方案而不是「删掉鉴权」的理由：

- 订单、权益、创作数据需要归属主体，彻底匿名会丢失归属与审计能力；
- 访客会话与正式账号共用同一套令牌与中间件，安全水位不下滑；
- 可逆：访客账号带 `users.is_guest = 1` 标记，可按此列批量清理；正式登录会替换为真实账号。

### 4.1 本轮踩到的一个真实坑（已修）

首次 `--live` 有 5 项失败（侧栏无访客身份、退出后未重建访客、失效提示缺失等）。排查发现**不是逻辑问题**：本地 `apps/web/dist` 里被烤进了 `VITE_API_ORIGIN=https://mim.mixm.top`，浏览器实际在向生产域名发 `POST /auth/guest`（CORS 预检 204 后失败），本地 API 一次都没被调用。用 `VITE_API_ORIGIN='' pnpm --filter @mim/web build` 重新做同源构建后，`--live` 立刻 56/56。结论：**托管平台构建（需绝对 API 源）与自建同源构建（需空源）是两种产物，本地真渲染验证必须用同源构建，否则会把环境问题误判成功能缺陷。**

## 6. 复现方式

```powershell
# 1) 起本地 API（同进程内 SQLite）
$env:MIM_AI_WORKER='0'; $env:MIM_JOBS='0'; pnpm --filter @mim/api dev
# 2) 以「同源」方式构建前端（VITE_API_ORIGIN 必须为空）
$env:VITE_API_ORIGIN=''; pnpm --filter @mim/web build
# 3) 静态服务 + /api 反代到 8787
node scripts/serve-local.mjs
# 4) 无头 Edge 开 CDP 后跑真实渲染验证
node scripts/verify-auth-gate.mjs --live
```

## 7. 已知边界

- 访客账号会随匿名访问增长，`users.is_guest = 1` 可用于定期清理；当前未实现自动清理任务。
- 访客升级为正式账号后，访客期间产生的订单 / 创作数据仍归属原访客账号，未做数据迁移（如需「登录后带走访客数据」需另做绑定迁移）。
- 管理后台 `/admin/` 的门禁不属于「此功能需登录后使用」范畴（属管理面凭证门禁），本轮保持不变。
