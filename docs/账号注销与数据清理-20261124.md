# 账号自助注销与到期数据清理（2026-11-24，V0.0.17-preview）

> 本轮把「用户无法自助注销、服务端长期留存个人数据」收口为 **自助申请 → 冷静期 → 到期物理删除 → 数据包导出** 的闭环。代码主体位于 `services/mim-api/src/privacy.ts`，配套用户侧接口、管理端接口、前端个人中心与后台「账号注销」视图。
>
> 生产入口：前端 `https://zy.laal.top`、API `https://api.laal.top/api/v1`、后台 `https://zy.laal.top/admin/`。裸域 `https://laal.top` 是同机独立 WordPress 站点，与 Mim 无关，不在本轮改动范围。

## 1. 背景与目标

- **自助注销端到端可用**：登录用户自己在前端发起注销、看到冷静期截止时间、随时撤销；到期后账号由服务端自动真正删除，不依赖管理员手工操作。
- **到期物理删除彻底且幂等**：删除后该用户的 PII 与业务行在库里查不到；重复执行不报错、不误删他人数据。
- **定期清理自动化**：随进程启动自然生效，受 `MIM_JOBS` 总开关与三个可配置参数控制，执行有审计记录。
- **数据尽量只落在用户设备**：服务端保留面收敛到「跑不动的最小集」；用户可先导出自己的数据包再注销。
- **管理端可见可干预**：待删除队列、剩余时间、执行结果可见；具备手动触发清理入口，受 RBAC 约束。

## 2. 接口清单

### 2.1 用户侧（`/api/v1/me`，均需登录）

| 方法 | 路径 | 行为 |
|---|---|---|
| `POST` | `/me/deletion` | 账号置 `pending_deletion` 并写入 `deletion_scheduled_at`（当前时间 + 冷静期）；重复申请幂等，回显既有预约时刻、**不重置冷静期** |
| `POST` | `/me/cancel-deletion` | 撤销注销，恢复 `active`，清空预约时刻；未处于待删状态回 409 `ACCOUNT_NOT_PENDING_DELETION` |
| `GET` | `/me` | 回传 `deletion_scheduled_at` 与 `deletion_grace_days` |
| `GET` | `/me/export` | 导出本人全量数据包 JSON，附件名 `mim-data-<MimID>-<YYYYMMDD>.json`；口令哈希 / 刷新令牌哈希 / 提现账户名与账号 / 实名姓名与证件哈希**不进包**，手机邮箱首尾脱敏 |

### 2.2 管理端

| 方法 | 路径 | 权限点 | 行为 |
|---|---|---|---|
| `GET` | `/admin/deletions` | `user:read` | 返回 `total` / `items`（Mim ID、昵称、区域、状态、预约时刻、剩余秒数、逾期标记）/ `policy`（冷静期天数、扫描间隔、批大小、自动清理开关）/ `last_run` |
| `POST` | `/admin/deletions/run` | `privacy:write`（本轮新增权限点） | 立即触发一轮到期清理，回传 `scanned` / `purged` / `at` / `audit_id`；写 `privacy.account_purge` 审计 |

匿名访问上述两类端点均 401；权限不足 403。

## 3. 环境变量（已登记 `.env.example` 与 `docs/wiki/09-third-party-sdk-inventory.md`）

| 变量 | 默认 | 取值区间 | 说明 |
|---|---|---|---|
| `MIM_DELETION_GRACE_DAYS` | `7` | 1–365 | 注销冷静期天数；越界 / 非法值回落默认 |
| `MIM_DELETION_SWEEP_MINUTES` | `60` | 5–1440 | 到期账号扫描间隔（分钟） |
| `MIM_DELETION_BATCH` | `50` | 1–500 | 单轮批量清理上限 |

总开关：`MIM_JOBS`。关闭时调度器既不跑首轮也不注册定时器；管理端手动触发不受周期调度开关限制。

## 4. 调度行为

- `startPrivacyScheduler` 在 `MIM_JOBS` 为真时注册：**进程启动先跑一轮**（避免长驻进程首个轮询前积压到期账号），之后按 `MIM_DELETION_SWEEP_MINUTES` 周期 `setInterval`，定时器句柄 `unref`（不阻止进程退出），返回 stop 句柄供优雅停机清理。
- 候选选择：`status='pending_deletion'` 且 `deletion_scheduled_at <= now`，按预约时间升序取 `MIM_DELETION_BATCH` 条。
- 逐账号独立事务：单账号失败整体回滚、记错误日志，**不阻断同批其余账号**；重复执行幂等——无候选即 `purged=0`，不报错。
- 审计：每轮写 `privacy.account_purge`，`detail.source` 区分 `startup` / `interval` / `manual`；`payload` 只含计数、逐表行数与已删 id 的 sha256 前 8 位摘要，不含用户原值。日志前缀 `[privacy]`。

### 5.3 审计日志脱敏（不物理删）

`audit_logs` 不做物理删除：`user_id` 改写为 `deleted-<sha256(原id) 前 12 位>`，`payload` 置 `{"redacted":"账号已注销"}`。审计链可追溯批次规模，但不可反推本人原值。

### 5.4 对象存储

删行前先收集本人主题帖媒体 / 封面 / 附件、消息附件、数字资产文件与封面（`media_json` 内联媒体一并解析）；事务提交后按 key 尽力删除对象存储。删除失败只记错误日志（只打键前缀），**不回滚已提交的数据库事务**；外链对象不入本仓存储、跳过。

### 5.5 保留的字典 / 运营表（无个人数据）

权限与角色、VIP 套餐、商品券模板、成长等级与徽章、站点配置、迁移台账、发号器元数据等字典 / 运营表不随个人账号删除。

## 6. 服务端最小保留面与保留时长

| 保留项 | 为什么必须留 | 保留时长 |
|---|---|---|
| 字典 / 运营 / 配置表 | 全站运行依赖，不含个人行 | 长期（站点生命周期） |
| 脱敏后的 `audit_logs` | 审计合规与故障追溯；已剥离 PII 与原始 payload | 按既有审计策略保留 |
| `privacy.account_purge` 批次审计 | 证明清理已执行、可对账；只含计数与 id 摘要 | 同上 |
| 冷静期内的账号与关联行 | 撤销需要回滚到完整状态 | 冷静期 `MIM_DELETION_GRACE_DAYS`（默认 7 天），到期后一个扫描周期内物理删除 |

**项目铁律：不创建任何数据库备份**——迁移 / 清理脚本不调用 `db.backup()`，仓库无备份脚本 / systemd timer，不生成 `.bak`；数据删除后不可恢复。

## 7. 用户数据包导出说明

`GET /me/export` 按身份 / 资金 / 内容 / 社交 / 交易五域组织 JSON：

- **包含**：本人账号标识（Mim ID、区域、展示昵称、状态）、身份与绑定的脱敏标识、本人帖子 / 回复 / 资产 / 收藏 / 购买 / 消息 / 钱包流水等业务行。
- **不包含**：口令 `secret_hash`、刷新令牌哈希、提现账户名与账号、实名姓名与证件哈希；手机 / 邮箱首尾脱敏。
- 导出是注销的前置能力：建议用户先下载数据包留存，再申请注销。数据包落在用户自己的设备上，由用户自行处理。

## 8. 管理端使用说明

- 后台「账号注销」视图：展示待删除队列、Mim ID、昵称、剩余倒计时、是否逾期、策略参数与最近一次清理结果；无 `privacy:write` 权限时「立即执行清理」按钮灰显。
- 手动触发：`POST /admin/deletions/run`（或视图按钮）只清到期账号，未到期账号不受影响；响应回传扫描数 / 回收数 / 时间 / 审计 id。
- 核对留痕：库内 `audit_logs WHERE action='privacy.account_purge'`；`payload` 只含计数、逐表行数与 id 摘要。
