# Mim 管理后台全量快照（2026-11-22）

## 取证方式

- 通道：`X-Admin-Token`（`MIM_ADMIN_TOKEN`，64 位，位于服务器 `/opt/mim/mim-api.env`）
- 身份：`bootstrap=true` / `roles=["superadmin"]` / 8 项权限（`user:read`、`rbac:read`、`rbac:write`、`commerce:write`、`appearance:write`、`content:write`、`messaging:write`、`deployments:read`）
- 基址：`https://api.laal.top/api/v1`，全部为只读 GET，未产生任何写操作。
- 令牌值未写入本文档；仅落于本机 `%USERPROFILE%\.mim-admin-token`（64 字节，ACL 仅当前用户）。

## 二、关键实体现状

**用户**：仅 1 个 `Administrator`（`status=active`，`region=global`，角色 `superadmin`，建于 2026-11-16）。与「全部平台只保留一个管理员」的既有口径一致。

**角色**：`operator`（运营管理员，10 项权限）、`superadmin`（13 项权限），两者 `builtin=true`。

**商城商品（3 个，均 active）**

**交易**：订单 0、售后 0、优惠券 0。

## 三、值得注意的三点

1. `pixi-pack` 可用库存只剩 3（总 20），是唯一「卖得动」的自动发货商品；再卖 3 单就会缺卡密。
2. 4 张 1 分钱作废卡密是测试遗留，建议清出列表以免运营误读库存口径。
3. `/admin/audit-logs` 返回 0 条——需确认是「令牌通道不记审计」还是「RBAC 写操作尚未发生」，这条直接影响后面做批量写操作时的可追溯性。

## 四、与 laal.top（WordPress）的区别

容易混的一点：**Mim 商城有 3 个商品**，而 `laal.top` 的 WP 站 `shop_product` 仍是 **0 个**（编辑器已修好，缺商品资料）。两边是独立站点、独立商品体系，Mim 的这 3 个不会出现在 `laal.top/shop/`。
