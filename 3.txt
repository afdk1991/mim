已完成思考，参考了12篇资料
先说实话：真正“完全免费 + 完全无限制”的托管不存在，任何免费层都有配额或休眠机制。但有两套组合能逼近你要的效果——Cloudflare 边缘全家桶（流量不计费、几乎用不完）和 Oracle Cloud Always Free 真服务器（自己掌控，配额内长期免费）。下面按“最接近无限制”排序给你选型。
方案 A：Cloudflare 全家桶（最接近“不限流量”）
适合：前端 + 轻量后端（Node/TS、Python 转 Worker 较麻烦）、需要全球 CDN、不想运维。
组件	免费额度	关键限制
组件	免费额度	关键限制
Pages（静态/SSG）	静态访问不限次数、不限带宽，每月 500 次构建	单站 2 万文件、单文件 25 MiB、构建 20 分钟超时 36
Workers（后端逻辑）	每天 10 万次请求，无冷启动	每请求 10ms CPU、最多 100 个脚本、UTC 零点清零 34
D1（SQL 数据库）	每天读 500 万行 / 写 10 万行，共 5 GB	单库 500 MB，超额当天拒绝查询（不扣费） 3
KV（键值）	每天 10 万读	写/删/列仅 1000 次/天，1 GB 34
R2（对象存储）	10 GB 存储 + 出站流量免费	唯一超量会真扣钱的一项，需先订阅（0 元起） 3
要点：官方现在建议新项目直接用 Workers（Pages 逐步被整合），Pages 的 Functions 与 Workers 共用额度 3。这套的“无限”体现在静态资源出口流量不计费，个人/中小站点基本跑不爆。
方案 B：Oracle Cloud Always Free（最接近“无限制的真服务器”）
适合：Docker Compose 全栈（Nginx + Node/Go/Python + PostgreSQL/MySQL + Redis）、需要长驻进程、定时任务、自定义环境。
配额：ARM（Ampere A1）2 OCPU + 12 GB 内存、2 台 AMD 微型实例、200 GB 块存储、每月 10 TB 出站流量 。
注意：2026 年 8 月 18 日起 ARM 配额从 4核24G 砍半，超额实例会被自动终止；建议原位降配（Edit → 改 OCPU/内存）而非删除重建，避免热门区域抢不到资源 。
闲置回收：连续 7 天 CPU/网络/内存利用率低于 20% 会被停止，升级 PAYG 账户可避免回收（额度内仍不收费） 。
注册门槛：风控较严，需真实外币信用卡、干净设备与 IP，Home Region 选定后不可改 。
这是唯一能跑“任意栈、任意端口、任意进程”的免费方案，代价是自己运维（安全更新、备份、监控）。
方案 C：国内可访问性优先
腾讯云 CloudBase：免费体验版每月 3000 资源点，含云函数、云数据库、静态托管；小程序发布后环境到期时间会缩短，长期使用需转付费 10。
阿里云函数计算 FC：按量付费模式下每月前 100 万次请求、前 40 万 GB·秒、前 1 GB 公网出流量免费 。
国内服务器 + 自定义域名需完成 ICP 备案 11；海外平台无需备案，但国内直连延迟和稳定性不可控 。
不推荐当主力的
Render（闲置 15 分钟休眠、冷启动 10–30 秒、免费 PG 仅 90 天）、Railway（每月 $5 额度，用完即停）、Fly.io（额度小、信用卡验证门槛）——适合 Demo 与 MVP，不适合“长期无限制” 。
我建议的落地组合
主推：Cloudflare Pages（前端）+ Workers（API）+ D1（数据）+ R2（文件），全 0 元、免运维、HTTPS 自动签发；域名用 *.pages.dev 免费，绑自定义域名需另买域名（域名本身不免费）。
需要重后端/长驻进程时：OCI 2核12G + Docker Compose + Cloudflare Tunnel（免开公网端口、免备案即可先用 IP/免费域名访问），再把静态资源丢 Cloudflare CDN。
避坑三条：R2 与 OCI 超额是唯一会真产生账单的点，务必设用量告警；D1/KV 超额是“停服”不是扣费，但要写降级逻辑；SQLite 在只读文件系统的平台（Workers/Serverless）不能直接落盘，改用 D1 或挂载存储。

2.3 后端入口（Hono，轻量、类型友好）

编辑



import { Hono } from 'hono'
const app = new Hono()

app.get('/api/health', c => c.json({ ok: true, ts: Date.now() }))

app.get('/api/users', async c => {
  const { results } = await c.env.DB
    .prepare('SELECT id, name, created_at FROM users ORDER BY id DESC LIMIT 20')
    .all()
  return c.json(results)
})

// 文件上传到 R2
app.post('/api/upload', async c => {
  const form = await c.req.formData()
  const file = form.get('file') as File
  const key = `uploads/${Date.now()}-${file.name}`
  await c.env.BUCKET.put(key, file.stream(), {
    httpMetadata: { contentType: file.type },
  })
  return c.json({ key })
})

// Cron 触发
app.scheduled(async (event, env) => {
  await env.DB.prepare('DELETE FROM sessions WHERE expires_at < ?')
    .bind(Date.now()).run()
})

export default app

2.5 前端调用后端
生产环境给 Workers 绑一个自定义域名（如 api.example.com），前端直接 fetch('https://api.example.com/api/users')；开发期用 wrangler dev + 前端代理。若前后端同域，可在 Pages 里配 _routes.json 把 /api/* 转给 Workers 函数，省掉 CORS。
2.6 免费额度与超额行为（关键差异）
Pages 静态访问：不限次数、不限带宽；限制在每月构建次数、单站文件数、单文件大小、构建超时。
Workers 请求数：按天计，UTC 零点重置；CPU 有单请求时间上限，重计算任务要拆分或改走 OCI。
D1 / KV：超额表现为当天拒绝写入或查询，不会扣费；D1 单库有容量上限，接近上限要归档历史数据。
R2：存储与出站有免费额度，超出会真扣钱，且需先订阅（可 0 元）——这是整套里唯一会爆账单的组件，务必设用量告警。
2.7 适合与不适合
适合：营销站、博客、管理后台、SaaS 轻量版、Webhook 网关、定时抓取。
不适合：长连接 WebSocket 密集场景、CPU 密集计算、需要固定出口 IP、需要跑 PostgreSQL 原生特性（D1 是 SQLite 方言）。
三、方案 B：Oracle Cloud Always Free（真服务器 + Docker Compose）
3.1 注册与配额要点（最容易踩坑的部分）
Home Region 一旦选定不可更改，就近选可用区域；部分区域 ARM 资源紧张，抢不到就换区域。
ARM（Ampere A1）免费额度曾被下调（2026 年 8 月起从 4 OCPU/24GB 降至 2 OCPU/12GB 量级），超额实例会被自动终止。若已开高配，在原实例上降配（Edit → 改 OCPU/内存）比删除重建更安全，避免停机后抢不到资源。
闲置回收：长期低利用率（CPU/网络/内存均很低）的实例会被停止；转为 PAYG（按需付费）账户后额度内仍不收费，但可避免回收。
风控：需要真实可用的外币信用卡、干净的浏览器与 IP，避免用代理/虚拟机注册。

3.5 备份与恢复（免费方案里最容易被忽略的一环）
bash

编辑



#!/bin/bash
# /usr/local/bin/backup.sh —— 每天 02:00 由 cron 调用
set -euo pipefail
TS=$(date +%F-%H%M)
docker compose exec -T db pg_dump -U app -d app | gzip > /backup/app-$TS.sql.gz
# 同步到 Cloudflare R2（S3 兼容）用 rclone / restic
rclone copy /backup remote:r2-backup --max-age 30d
find /backup -mtime +14 -delete
恢复演练：新建临时库 → gunzip -c app-xxx.sql.gz | psql -U app -d restore_test → 抽查关键表行数。没演练过的备份等于没有备份。
3.6 防闲置与保活
低强度 cron（如每分钟一次本地健康检查、每天一次备份）能显著降低被判闲置的概率；但不要把“保活”做成持续高负载，既违背免费层初衷也可能触发风控。最稳妥的做法仍是转 PAYG 账户，额度内不收费。
3.7 这套的边界
优点：任意技术栈、任意端口、长驻进程、系统级定时任务、可装监控 Agent。
代价：自己负责安全更新、故障恢复、数据备份；实例被终止时需要有重建脚本（把上面所有步骤写成 bootstrap.sh + Git 仓库，做到 10 分钟重建）。

八、必须说清的三条“无限制”真相
没有任何平台同时做到“零成本 + 无配额 + 无休眠 + 无运维”。能逼近的只有：Cloudflare（流量维度几乎不限）与 OCI（能力维度几乎不限）。
超额行为分两类：停服型（D1/KV/多数免费层，不扣钱但拒绝请求）与计费型（R2、OCI 超出免费额度、国内按量服务）。上线前必须确认你用的每一项属于哪一类。
“免费”不等于“可长期依赖”。生产业务请把免费层当作开发与中小流量阶段的基础，同时准备好：付费开关、迁移脚本、数据导出通道。业务量起来后，最先成为瓶颈的通常是数据库写入额度与 CPU 时间上限。

三套全用
已完成思考
三套全用是可行的，但必须明确分工、单向数据流、可独立降级，否则会变成三套系统互相依赖、一起挂。下面给你一套能真正落地的“三层多云”架构：Cloudflare 做边缘与静态、Oracle Cloud 做主力计算与主数据库、国内平台做境内接入与合规，外加统一的调度、同步、部署和降级方案。
一、职责划分（谁负责什么，谁不碰什么）
层	平台	承担职责	明确不做
层	平台	承担职责	明确不做
边缘层	Cloudflare（DNS + CDN + Workers + Pages + D1/KV/R2）	域名解析、HTTPS、静态前端、WAF/限流、边缘路由与鉴权、上传文件存储、只读缓存副本	不做重计算、不做主库写入
主力层	Oracle Cloud Always Free（2核12G ARM + Docker Compose）	长驻 API、WebSocket、定时任务、PostgreSQL 主库、Redis、后台 Worker、报表/导出	不直接暴露公网端口（走 Tunnel）
境内层	腾讯云 CloudBase 或阿里云 FC	国内用户就近接入、备案域名站点、国内短信/支付回调、国内静态镜像、灾备热备	不做主库（只读或独立业务库）
核心原则：写入只有一个入口（OCI 主库），其余全是只读副本或缓存。 三套之间不做双写，避免一致性地狱。

要点：
DNS 只做一层调度，业务路由判断放在 Workers，方便秒级切换（改 Worker 变量即可，不用等 DNS TTL）。
国内入口默认只读：读 D1 副本或缓存；需要写操作时，引导到境外主站或走异步任务队列（写请求投递到 OCI 的队列接口，返回任务 ID）。
中国大陆访问 Cloudflare 免费套餐没有境内节点，延迟与稳定性不可控，这正是必须引入国内层的根本原因。

// worker/src/index.ts —— 统一入口，负责调度与降级
type Env = {
  OCI_TUNNEL: string      // https://app.example-tunnel.com
  CN_ORIGIN: string       // https://cn.example.com（CloudBase/FC）
  CACHE: KVNamespace
  DB: D1Database
}

const HEALTH_KEY = 'upstream:healthy'

async function probe(url: string): Promise<boolean> {
  try {
    const r = await fetch(url + '/api/health', {
      method: 'GET',
      signal: AbortSignal.timeout(3000),
      headers: { 'User-Agent': 'edge-probe' },
    })
    return r.ok
  } catch { return false }
}

export default {
  async fetch(request: Request, env: Env): Promise<Response> {
    const url = new URL(request.url)

    // 1) 静态与 API 分流：非 /api 前缀交给 Pages（此处仅示意）
    if (!url.pathname.startsWith('/api/')) {
      return env.CACHE.get('placeholder') ? new Response('static') : fetch(request)
    }

    // 2) 地理判断（cf 对象在 Cloudflare 边缘可用）
    const country = request.cf?.country ?? 'XX'
    const isCN = country === 'CN' || country === 'HK' || country === 'MO' || country === 'TW'

    // 3) 主备选择：健康缓存 60s，避免每次请求都探测
    const cached = await env.CACHE.get(HEALTH_KEY, 'json') as { oci: boolean; ts: number } | null
    let ociHealthy = cached?.oci ?? true
    if (!cached || Date.now() - cached.ts > 60_000) {
      ociHealthy = await probe(env.OCI_TUNNEL)
      await env.CACHE.put(HEALTH_KEY, JSON.stringify({ oci: ociHealthy, ts: Date.now() }), { ttl: 120 })
    }

    // 4) 路由决策
    let target: string
    if (isCN && !ociHealthy) target = env.CN_ORIGIN          // 国内 + 主站挂 → 国内只读
    else if (isCN) target = env.CN_ORIGIN                     // 国内默认走境内
    else if (ociHealthy) target = env.OCI_TUNNEL              // 境外正常
    else target = env.CN_ORIGIN                               // 兜底

    // 5) 写操作在国内入口直接拒绝（只读策略）
    if (target === env.CN_ORIGIN && !['GET', 'HEAD', 'OPTIONS'].includes(request.method)) {
      return Response.json({ error: 'read_only_region', hint: '请切换主站域名提交' }, { status: 503 })
    }

    const upstream = await fetch(target + url.pathname + url.search, {
      method: request.method,
      headers: request.headers,
      body: ['GET', 'HEAD'].includes(request.method) ? undefined : request.body,
      signal: AbortSignal.timeout(15_000),
    })
    return new Response(upstream.body, { status: upstream.status, headers: upstream.headers })
  },
}

async function syncPosts(env: Env) {
  const cursor = (await env.CACHE.get('sync:posts:cursor')) ?? '0'
  const r = await fetch(`${env.OCI_TUNNEL}/api/sync/posts?since=${cursor}`, {
    headers: { 'x-sync-token': env.SYNC_TOKEN },
  })
  const { rows, next } = await r.json()
  for (const row of rows) {
    await env.DB.prepare(
      'INSERT INTO posts (id, title, body, updated_at) VALUES (?1, ?2, ?3, ?4) ON CONFLICT(id) DO UPDATE SET title=?2, body=?3, updated_at=?4'
    ).bind(row.id, row.title, row.body, row.updated_at).run()
  }
  await env.CACHE.put('sync:posts:cursor', String(next))
}

八、密钥与安全边界
三套平台密钥各自独立，绝不跨平台共用；边缘用 wrangler secret put，OCI 用 .env（权限 600，不入仓），国内平台用平台密钥管理。
内部接口（同步、队列）加 HMAC 签名 + 时间戳 + nonce，防重放；只允许 Cloudflare 出口 IP 段访问 Tunnel 域名（Tunnel 本身已隐藏源站，再加一层更稳）。
主库账号最小权限；备份桶独立密钥，仅备份机可写。
所有对外响应加基础安全头（CSP、X-Content-Type-Options、Referrer-Policy），WAF 规则在 Cloudflare 侧统一维护。

十一、必须提醒的三个代价
复杂度是主要成本：三套平台意味着三套日志、三套密钥、三套额度、三套故障模式。团队只有一两个人时，建议先做“Cloudflare + OCI”双套，国内层等到确实有境内用户量再上。
数据一致性只能做到最终一致：D1 副本天然滞后（分钟级）。凡涉及“写入后立刻读”的功能，必须走主站，不能依赖副本，否则会出现用户看不到自己刚提交内容的 bug。
免费层的可持续性风险：OCI 闲置回收与配额调整、国内平台环境有效期、R2 计费超额，都是会在未来某个时间点打断服务的变量。生产业务请始终保留导出脚本 + 迁移到付费方案的开关，把免费层当成阶段性基础设施而非永久承诺。

十一、必须直说的四个风险
平台数量 ≠ 可用性。多镜像、多制品库、多 CI 会显著增加“配置漂移”和密钥泄露面。建议：镜像仓最多 3 个（GitHub + Gitee + 极狐/自建），制品库最多 2 套（GHCR + 一个国内副本），其余等真有需求再加。
“限时免费”是有期限的。EdgeOne Makers 明确处于限时免费阶段，商业化版本按构建次数、函数调用、内存时长、Agent 请求、存储、Token 等维度计费26。把它当加速与亚太入口，别把主数据与唯一部署流程锁死在上面。
免费制品与镜像库不能当生产唯一依赖。ACR 个人版官方明确无 SLA、不建议生产使用39；GitHub Packages 超额会真扣费且与 Actions 工件共享配额78。生产镜像应保证“GHCR 与至少一个国内副本同时可用，且 tag 可复现”。
多 CI 结果可能不一致。国内 CI 与 GitHub Actions 的镜像、缓存、依赖源不同，容易出现“这边过那边挂”。约束办法：所有 CI 共用同一份 Dockerfile 与 lockfile，国内 CI 只做构建与部署、不重复判定质量门禁。
