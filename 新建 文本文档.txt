# 一、CTO / 技术负责人（1 人）

**定位**：技术侧最终决策者与项目技术风险的第一责任人，负责"定边界、定规范、定节奏、定质量底线"。

### 1. 架构与选型
1. 定义系统分层与边界：终端层、接入层（网关）、业务服务层、设备接入层、音视频链路、数据层、基础设施层，明确每层职责与故障域。
2. 主导技术选型并出具决策记录（ADR）：跨端策略（原生为主、哪些页面走 H5/跨端）、后端语言与框架、数据库与缓存、消息队列、时序数据存储、部署形态、音视频 PaaS 与自建的取舍。
3. 定义各端与后端的通信契约：协议风格、版本策略、能力协商机制、向下兼容规则（至少兼容 2 个历史版本）。
4. 主持不可逆变更的技术评审：数据模型变更、协议变更、中台接口变更、OTA 方案、存储与成本结构变更。

### 2. 规范与标准（Phase 1 的核心产出）
5. 主导并冻结四份基础规范：**API 规范**（RESTful 约定、版本、分页/排序/过滤、幂等、统一响应结构）、**统一错误码规范**（全端共用一张表）、**账号与权限模型**、**埋点与数据口径规范**。
6. 制定代码与工程标准：分支策略、提交规范、代码评审规则、CI 门禁（lint + 单测 + 构建 + 冒烟）、文档要求。
7. 制定日志、监控、告警与链路追踪标准，保证线上问题可定位、可复盘。

### 3. 中台推进
8. 定义中台边界与 Phase 1 范围：只做账号中心、网关、多端组件库三件套，其余需求统一收口并延后。
9. 判定"何时从规范转为团队"：出现 ≥2 个真实复用场景后才抽人成立平台组，并决定抽谁、抽几人。
10. 仲裁中台与业务线的冲突：接入成本、需求优先级、是否允许业务线自建，避免影子系统。
11. 为中台设定考核口径：以"为业务方节省的人日"和"业务方是否愿意主动接入"为准，而非接入数量。

### 4. 发版与稳定性
12. 制定发版契约：Web、小程序、App、固件四套管道的发布顺序、窗口、依赖关系与回滚预案。
13. 定义发布质量门禁与放行授权：崩溃率、核心链路用例通过、性能基线不劣化、合规项通过；明确谁有权发固件。
14. 主导重大故障与线上事故的指挥、复盘与改进项跟踪。
15. 主导 OTA 升级策略评审：分批灰度、电量/网络前置校验、失败率熔断、回滚与防变砖方案。

### 5. 成本与容量
16. 对云成本、音视频带宽与录制转码成本负责，设定单用户单分钟成本上限并要求做成可观测面板。
17. 主导容量评估与压测要求：设备长连接承载、音视频并发、数据库与缓存容量水位。

### 6. 团队与协作
18. 负责技术岗面试终面与技术梯队建设，识别"能独立交付"与"只会执行"。
19. 指定并考核跨领域兼任责任人（如硬件联调负责人、发版负责人、合规对接人），消除责任真空。
20. 向业务/管理层做技术风险与排期的对外解释，承担砍需求的技术论证。

### 7. 风险前置
21. 维护技术风险登记册，为每条风险设定触发信号与预案：认证周期、协议兼容、成本失控、中台被绕开、关键人单点。
22. 与 PM 共同把硬件认证、备案、合规节点倒排进技术排期。

# 二、产品负责人 / PM（1 人）

**定位**：需求收敛者、跨端一致性 owner、合规与发版窗口的实际推动者。

### 1. 需求管理与范围控制
1. 建立需求池与优先级机制，明确 Phase 1 的"做/不做清单"，非核心需求进 Backlog 并对外解释。
2. 编写需求文档：用户场景、业务流程、状态流转、异常与空态、验收标准、涉及端清单。
3. 做需求可行性与成本评估，与 CTO 共同裁决"做不了/延后做/降级做"。
4. 管理需求变更：变更走评审，评估对协议、固件、多端与发版窗口的影响。

### 2. 硬件与软件的联合产品定义
5. 定义设备生命周期体验：开箱、配网、绑定、使用、升级、解绑、丢失与重置。
6. 定义设备状态与异常体验：连接中/失败/断连重连、低电量、固件升级中/失败、离线、权限缺失。
7. 与硬件方案商/工厂对接产品侧需求：按键与指示逻辑、提示音与灯效、功耗预期、包装与说明书中的软件配合项。
8. 把硬件打样、认证送检、量产节点倒排进产品排期，标识关键路径与缓冲。

### 3. 多端一致性
9. 维护"多端差异矩阵"：同一功能在 iOS/Android/小程序/H5/管理后台的差异、文案、错误提示、权限申请话术。
10. 统一文案与术语表（设备名、状态名、错误提示、按钮动词），避免各端各自表述。
11. 统一权限与隐私话术：相机、麦克风、蓝牙、定位、通知、相册的用途说明与出现时机。

### 4. 合规与外部事务
12. 建立并维护合规清单，逐项指定责任人与完成状态：ICP 备案、App 备案、隐私政策与用户协议、权限说明、SDK 清单披露。
13. 音视频/UGC 场景的内容安全方案：审核方式（自建/第三方）、举报与处置流程、录制文件的留存与删除策略。
14. 若涉及直播类业务，评估资质路径与替代方案，并向管理层提示风险。
15. 对接法务、应用商店与小程序审核，准备审核被拒的整改预案与话术。

### 5. 发版与上线
16. 制定发版日历：四套管道的发布时间、审核缓冲、灰度比例与观察期。
17. 定义灰度与回滚触发条件：观察哪些指标、超阈值如何处理、由谁决策回滚。
18. 组织版本验收与上线后冒烟，收集首批用户反馈并分级（阻断/严重/一般）。

### 6. 数据与迭代
19. 定义北极星指标与核心漏斗，输出埋点需求表并与埋点规范对齐。
20. 上线即收数：验收埋点准确性，避免上线后补埋点造成数据断档。
21. 基于数据做下一版迭代决策，输出复盘结论（哪些假设成立/不成立）。

### 7. 用户与运营接口
22. 早期用户访谈与内测群运营，沉淀问题库与 FAQ。
23. 与客服/运营对接问题分级与响应机制，推动高频问题进产品迭代。

# 三、UI/UX 设计师（1 人）

**定位**：重度交互项目的规范生产者，交付"可被工程消费的资产"而非静态图。

### 1. 交互设计与原型
1. 输出核心流程的交互稿与可点击原型：配网与绑定、设备控制、音视频通话/观看、账号与订单、消息与通知。
2. 定义完整状态机：加载、空态、失败、重试、权限缺失、离线、降级，每态给出视觉与文案。
3. 定义手势与导航：返回逻辑、侧滑、长按、拖拽、下拉刷新与冲突处理。
4. 与 PM 对齐异常与边界场景，不接受"只画正常流"。

### 2. 设计系统与 Design Token
5. 建立 Token 体系：颜色、字号与行高、间距、圆角、阴影、层级、动效时长与缓动曲线，输出语义化分层与三端可用的变量文件。
6. 建立组件规范与变体：按钮、输入、选择、弹窗、Toast、列表项、卡片、标签、状态页、媒体播放控件。
7. 建立 Token 变更与版本发布机制：变更通知、兼容策略、废弃标记，配合前端组件库落地。
8. 与前端/移动端共同评审组件抽象是否合理，避免"设计一套、三端各写一套"。

### 3. 动效与标注
9. 输出动效规格：触发条件、时长、缓动、帧率要求、可降级方案（低端机/省电模式）。
10. 提供完整标注与切图：尺寸、间距、资源倍图、字体子集、暗色模式取值。
11. 对复杂渲染（视频层、地图层、Canvas/Metal 层）给出层级与性能约束建议。

### 4. 多端与硬件场景适配
12. 平台差异适配：iOS/Android 导航栏、返回手势、分享、权限弹窗、键盘行为。
13. 小屏/大屏与横竖屏、折叠屏与平板的布局策略；小程序与 H5 的差异适配。
14. 暗色模式、字体缩放、无障碍（对比度、点击区域、读屏标签、字幕与音量提示）。
15. 硬件联动视觉：配网进度、信号与电量、升级进度与失败、固件版本展示。

### 5. 走查与验收
16. 每个版本发布前做 UI/交互走查，输出走查表并跟踪修复闭环。
17. 参与可用性验证（内测用户操作观察），输出改进项。
18. 维护设计资产库与规范文档，保证新人可自助查阅。

# 四、前端工程师（2 人）

> 两人分工明确：**A 偏管理后台 + H5**，**B 偏小程序 + 组件库/前端基建**。共同承担前端质量、埋点与联调。

## 4A 前端工程师 A（管理后台 + H5）

### 1. 管理后台
1. 搭建并迭代管理后台：基于中后台模板实现布局、路由、菜单、面包屑、全局状态与主题。
2. 业务模块：用户与账号管理、设备管理与远程指令、订单与支付查询、内容与审核工作台、数据看板、系统配置、操作审计日志。
3. 通用能力封装：CRUD 模板、复杂表单校验、批量操作、导入导出、筛选与保存视图、大数据量表格（虚拟滚动、分片渲染）。
4. 权限控制：路由级 + 按钮级 + 数据级，严格消费账号中心的权限模型，禁止前端自造权限逻辑。

### 2. H5 与跨端容器
5. H5 页面：活动页、帮助与协议、分享落地页、支付与回调页。
6. 与 App 的 JSBridge 通信：能力检测、降级策略、安全校验、版本兼容。
7. 移动端 H5 适配：安全区、键盘、滚动穿透、图片与首屏性能、缓存策略。

### 3. 联调与工程
8. 与后端对齐 API 与错误码，实现统一请求层：拦截器、Token 刷新与并发单飞、超时重试与幂等、统一错误提示。
9. 前端埋点接入与自检，配合 PM 的埋点需求表与埋点规范。
10. 前端错误与性能监控接入，异常上报可定位到版本与用户路径。
11. 参与 API 文档评审，发现契约不一致及时提出并推动修正。
12. 编写模块文档与关键实现说明，保证可交接。

## 4B 前端工程师 B（小程序 + 组件库 / 前端基建）

### 1. 小程序与轻端
1. 小程序（或 H5 轻端）页面开发：登录与绑定、设备列表与控制、消息与通知、分享与邀请链路。
2. 小程序专项优化：分包与预加载、首屏渲染、 setData 性能、包体积、订阅消息与权限。
3. 与 App 的功能一致性对齐，参与多端差异矩阵评审并落地差异实现。

### 2. 多端组件库与设计系统落地
4. 消费设计 Token，实现 Web/小程序可用的基础组件与业务组件（设备状态卡片、媒体播放控件、状态页等）。
5. 建立组件文档与示例站，制定版本发布与变更日志、breaking change 沟通机制。
6. 抽象跨端适配层：同一组件在不同端的差异实现收敛到一处。
7. 建立视觉回归或快照测试，防止 Token 变更引发大面积走样。

### 3. 前端基建
8. 统一工程规范：TypeScript 约定、ESLint/Prettier、Git 提交与分支规范、Code Review 配合。
9. 构建与发布：多环境配置、CI 构建与产物优化、CDN 与缓存策略、Source Map 与错误定位。
10. 通用 SDK 封装：请求层、埋点、监控、日志、工具库，供其他前端与 H5 复用。
11. 自动化基础：单元测试与 E2E 冒烟用例（后台关键流程），接入 CI。

# 五、iOS 工程师（1 人）

**定位**：iOS 原生唯一主力，负责重度交互、音视频渲染与硬件通信在 iOS 上的正确落地。

### 1. App 主体功能
1. 实现账号体系：登录注册、Token 与刷新、多端登录策略、登出与踢出、账号与设备绑定。
2. 实现设备功能：配网、绑定、控制、状态同步、消息与推送、订单与支付、设置与隐私。
3. 实现业务页面与路由、缓存与离线策略、下拉刷新与状态一致性。

### 2. 重度交互与渲染
4. 实现复杂手势、转场与自定义动画，保证目标帧率与可中断性。
5. 列表与滚动性能治理：Cell 复用、离屏渲染、透明度与圆角、图片解码与缓存。
6. 视频与图形渲染层实现与优化（视频显示层、图层合成、必要时 Metal/OpenGL 参与）。
7. 启动与内存治理：启动阶段拆分、首屏渲染、内存峰值与泄漏、包体积控制。

### 3. 音视频
8. 集成 RTC/播放器 SDK 或自研模块：频道与会话管理、Token 鉴权、推拉流参数、订阅与角色切换。
9. 音频链路：音频路由（听筒/扬声器/蓝牙/耳机）、音频会话与打断、来电与闹钟打断恢复、后台音频、AEC/音量控制。
10. 质量与体验：首帧时间、卡顿与重连、弱网降级、分辨率与码率自适应、多端互拨表现一致。
11. 生命周期与权限：相机/麦克风权限流程、前后台切换、息屏与后台保活策略、省电与发热控制。

### 4. 硬件通信
12. 实现 BLE 配网与通信（扫描、连接、GATT 读写、MTU、写无响应等），以及局域网通信与设备发现。
13. 实现连接状态机：连接、超时、重试、退避、断连恢复、并发操作互斥，并保证与 Android 语义一致。
14. 与固件协议对齐：解析与封装、版本与能力协商、错误码映射到统一错误码表。
15. 参与 OTA 客户端侧实现：版本检测、下载校验、升级提示、进度与失败处理、防误升级。

### 5. 稳定性、合规与发布
16. 崩溃与卡顿监控接入与治理，ANR/卡死与内存问题定位。
17. 埋点与日志按规范接入，关键链路打点（配网成功率、连接成功率、接通率、首帧时间）。
18. 上架合规：隐私清单与权限描述、数据收集披露、审核问题整改、TestFlight 灰度与回滚。
19. 编写模块设计与协议对接文档，参与代码评审与知识共享。

# 六、Android 工程师（1 人，兼硬件联调负责人）

**定位**：Android 原生唯一主力，额外承担机型碎片化治理与硬件（固件）联调的长期对接。

### 1. App 主体功能
1. 实现与 iOS 语义一致的功能：账号、设备配网与绑定、控制、消息与推送、订单与支付、设置与隐私。
2. 架构与分层：模块化、依赖注入、协程与 Flow 的数据流、状态管理与生命周期安全。
3. 本地存储与缓存、离线策略、数据迁移与升级兼容。

### 2. 重度交互与性能
4. 实现复杂交互与动画（Compose/View 体系），处理手势冲突与嵌套滚动。
5. 低端机与碎片化性能治理：渲染管线、过度绘制、大图与列表优化、启动与内存、包体积与多渠道。
6. 系统版本行为适配：通知权限、精确闹钟、后台定位、后台限制、前台服务类型、targetSdk 升级。
7. 厂商 ROM 差异处理：推送通道、后台保活、自启动与权限弹窗引导。

### 3. 音视频
8. 集成 RTC/播放器：会话管理、Token 鉴权、推拉流与订阅、录制与回放。
9. 采集与处理：CameraX/Camera2 预览与拍照、硬编解码、音频焦点与路由、3A 效果配合。
10. 后台与功耗：前台服务与通知、WakeLock 管理、息屏与后台策略、发热与耗电治理。
11. 质量指标实现与上报：首帧、卡顿、丢包、延迟、音画同步，与 iOS 口径一致。

### 4. 硬件通信与联调（兼任职责）
12. 实现 BLE（GATT、MTU、连接参数、扫描与功耗）、Wi-Fi 配网、局域网通信与设备发现。
13. 实现与 iOS 语义一致的连接状态机、重试与退避、并发互斥与超时策略。
14. 作为硬件联调唯一 owner：与固件同事对接协议、组织联调、抓包分析（btsnoop/Wireshark）、问题复现与归因。
15. 维护协议对接文档与变更记录，任何协议变更走评审并评估旧版本兼容性。
16. 参与 OTA 客户端与联调：升级流程、中断与恢复、防变砖的客户端保护。

### 5. 稳定性、合规与发布

# 十、跨角色共同职责（所有人适用）

1. **契约优先**：任何跨端/跨系统交互必须先定契约（API、协议、错误码、事件），再并行开发；契约变更走评审。
2. **可观测优先**：自己负责的模块必须自带日志、指标与告警，不依赖"出问题再看"。
3. **文档沉淀**：模块设计、协议对接、部署与运维、已知问题与 workaround 必须有文档，保证可交接。
4. **兼容意识**：客户端与固件存在长尾旧版本，任何变更默认要求向后兼容，不兼容必须显式声明并给出方案。
5. **成本意识**：涉及存储、带宽、转码、短信、第三方调用的改动，需评估成本影响并告知负责人。
6. **合规意识**：涉及个人信息、权限、内容、录制的改动，需同步 PM 与合规清单。
7. **发布纪律**：遵守发版窗口与门禁，具备回滚方案，不做"只进不退"的变更。

下面是两份配套文件：**第一份 RACI 责任矩阵**（把职责落到"谁执行、谁拍板、谁被咨询、谁被知会"），**第二份 Phase 1 交付物与验收标准清单**（可勾选，直接用于试用期目标与版本验收）。

约定：
- **R** = Responsible，执行主责（干活的人，可多人）
- **A** = Accountable，最终负责/拍板（**每行只有一个 A**，出问题找他）
- **C** = Consulted，被咨询（事前必须征求其意见）
- **I** = Informed，被告知（事后同步即可）
- 角色缩写：CTO｜PM｜UX（设计）｜FA（前端A·后台/H5）｜FB（前端B·小程序/组件库）｜iOS｜AND（Android）｜BA（后端A·业务）｜BB（后端B·设备/实时）｜QA｜AV（音视频顾问）

**RACI 使用规则（很重要，否则矩阵会失效）**
1. 每行**有且只有一个 A**；出现两个 A 说明责任没分清，出现零个 A 说明这是"责任真空"（硬件联调、OTA、合规、发版最容易真空）。
2. A 可以不做（不写 R），但必须签字；R 可以多人，但要指定"主 R"。
3. 标 C 的角色**必须在事前被征求意见**，事后补通知不算；标 I 的只需事后同步。
4. 矩阵每季度或每个大版本复审一次，人员变动时同步更新，否则很快变成废纸。
